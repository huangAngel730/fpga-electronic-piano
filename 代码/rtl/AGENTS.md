# FPGA 技术与集成岗位规则

负责人：M2 FPGA 技术与系统集成负责人，兼任技术与集成负责人。岗位定义见 `代码/docs/角色分工.md`。

## 优先级

本文件适用于 `代码/rtl/` 下全部内容。`代码/rtl/audio/AGENTS.md`（M1）和 `代码/rtl/input/AGENTS.md`（M3）是更深的规则，在各自目录内优先于本文件；本文件对未被它们覆盖的部分生效，包括 `代码/rtl/board/`、`代码/rtl/common/`、`代码/rtl/audio_out/` 和顶层模块。

## 主责范围

- 时钟、PLL、复位与 `sample_tick` 的产生和分发。
- 跨时钟域处理、同步器、握手和异步 FIFO。
- I2S 发送器与音频输出链路的时序。
- UART 状态通道的协议与顶层实现。
- 顶层模块、端口定义与模块例化。
- Gowin 工程、CST 引脚约束与 SDC 时序约束。
- 资源规划、综合、布局布线、时序收敛与稳定码流。

## 写入范围

以上目录尚未创建时按需创建，不要为了占位批量建空目录。

## 与 M1 的边界

- PCM 数据格式、位宽、舍入和饱和策略由 M1 定义，本岗位按约定实现，不自行改动。
- 数字效果器的跨采样率切换和跨时钟域部分由本岗位参与实现，算法本身归 M1。
- 本岗位复核 M1 的流水线实现和资源占用是否符合时序与器件能力。
- M1 的算法 RTL 需要加流水线、改资源结构或接 FIFO 时由本岗位实施，算法数学定义和最终验收仍归 M1。

## 与 M3 的边界

- 引脚、电平、供电和实物接线依据由 M3 提供；CST 约束由本岗位落地，两者必须一致。
- 改动接线后由 M3 通知本岗位修改 CST 并更新引脚文档，约束、接线表和引脚文档三者同步变更。
- UART 状态通道的协议和顶层实现归本岗位；上位机解析和采集脚本归 M3。

## 约束

- 新增时钟必须写入 SDC 约束。不使用逻辑门控时钟，改用时钟使能或器件专用时钟资源。
- 禁止直接跨时钟域使用多位总线。单比特控制信号用双触发器同步，脉冲用握手，多位数据用 Gray 码或异步 FIFO。
- 修改时钟、复位、CDC、FIFO、乘法器或接口时序后，必须重新运行相关仿真和时序检查，不能只跑综合。
- 资源占用和时序结果必须引用工具的实际报告，不得估算或沿用旧数据。
- 时序未收敛的工程不得标记为稳定版，不得用于上板音质评价。
- 修改公共接口、时钟、复位、位宽、采样率或顶层端口前先停止并提交影响分析。
- 构建产物和厂商自动生成目录不提交，规则见根目录 `.gitignore` 和根目录 `AGENTS.md`。
- 软件任务积压时按 D010 分担算法 RTL 的流水线、资源优化和构建工作，算法数学定义与最终验收仍由 M1 负责。
