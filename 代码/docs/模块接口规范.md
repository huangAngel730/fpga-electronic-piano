# 模块接口规范

版本：草案 v0.1。冻结前允许讨论，冻结后按变更流程修改。

## 时钟与复位约定

- 顶层系统时钟名称暂定 `sys_clk`，实际频率待板级工程确认。
- 复位名称暂定 `rst_n`，低有效；模块内部优先同步释放。
- 音频算法使用 `sample_tick` 作为时钟使能，不使用普通逻辑生成门控时钟。
- 跨时钟域信号必须通过同步器、握手或异步 FIFO。

## 统一演奏事件

建议公共类型：

```systemverilog
typedef struct packed {
    logic [2:0]  event_type;
    logic [6:0]  note_number;
    logic [9:0]  velocity;
    logic [9:0]  expression;
    logic [7:0]  control_id;
    logic [11:0] control_value;
} performance_event_t;
```

建议传输接口：

```systemverilog
input  logic               event_valid;
output logic               event_ready;
input  performance_event_t event_data;
```

事件类型初稿：

| 编码 | 事件 |
|---:|---|
| 0 | Note On |
| 1 | Note Off |
| 2 | Aftertouch |
| 3 | Pitch Bend |
| 4 | Control Change |
| 5至7 | 保留 |

约定：Note事件走FIFO；高频连续控制参数可采用降采样事件或独立影子寄存器，禁止无控制地占满事件FIFO。

## 音频样本接口

第一版建议：

```systemverilog
output logic signed [23:0] pcm_left;
output logic signed [23:0] pcm_right;
output logic               pcm_valid;
input  logic               pcm_ready;
```

- 内部PCM暂定有符号24位。
- 混音累加暂定有符号32位或更宽。
- 波表样本暂定有符号16位。
- 最终位宽只能在Python参考模型和综合报告支持下调整。

## 状态与错误接口

各子系统至少提供：

- `active_voice_count`
- `clip_count`
- `event_fifo_overflow`
- `audio_underrun`
- `max_processing_cycles`

UART文本字段名称保持稳定，便于软件自动解析。

## 公共接口修改规则

修改字段、位宽、极性或握手时序前，必须：

1. 在技术决策记录新增提案。
2. 列出影响模块、Testbench和脚本。
3. 三名负责人确认。
4. 先修改接口文档和公共测试桩。
5. 各模块在同一个集成窗口完成适配。
6. 全回归通过后合并。
