## 二 时钟与复位约定（已定）

- 顶层系统时钟名称 `sys_clk`，实际频率在 W2 由 M2 结合 PLL 方案确认。
- 复位名称 `rst_n`，低有效；模块内部优先同步释放。
- 音频算法使用 `sample_tick` 作为时钟使能，不使用普通逻辑生成门控时钟。
- 跨时钟域信号必须通过同步器、握手或异步 FIFO，禁止直接使用多位总线。

### 时钟域划分

| 域 | 时钟来源 | 主要内容 | 归属 | 跨越方式 |
|---|---|---|---|---|
| 输入域 | `sys_clk` | 按键去抖、传感器采样、事件打包 | M3 | 异步 FIFO 或握手进入音频域 |
| 音频域 | `sys_clk` 加 `sample_tick` 使能 | 相位累加、波表、ADSR、混音、效果器 | M1 | 本域内部，不跨时钟 |
| 输出域 | I2S 位时钟 | 串行移位与声道输出 | M2 | 音频域按 `sample_tick` 交付样本 |

若 W2 确认全系统只使用单一 `sys_clk`，则音频通路内部不跨时钟域，只有外部输入需要同步处理。这一结论必须在 W2 结束前书面确认。

## 三 统一演奏事件

### 事件结构（待第七节确认位宽）

```systemverilog
typedef struct packed {
    logic [2:0]  event_type;
    logic [6:0]  note_number;
    logic [9:0]  velocity;
    logic [9:0]  expression;
    logic [7:0]  control_id;
    logic [11:0] control_value;
} performance_event_t;
```

当前字段合计 50 位，不是 BRAM 或 FIFO 的自然位宽，见第七节 Q1。

### 字段语义

| 字段 | 含义 | 取值约定 |
|---|---|---|
| `event_type` | 事件种类 | 见下表 |
| `note_number` | 音高编号 | 建议沿用 MIDI 语义，0 至 127，60 为中央 C |
| `velocity` | 触发强度 | 范围与映射方式待定，见 Q2 |
| `expression` | 连续表情量 | 压力或弯音合并或独立，见 Q3 |
| `control_id` | 控制编号 | 用于音色切换与参数调节 |
| `control_value` | 控制值 | 与 `control_id` 配对 |

### 事件类型

| 编码 | 事件 | 是否走 FIFO |
|---:|---|---|
| 0 | Note On | 是 |
| 1 | Note Off | 是 |
| 2 | Aftertouch | 是 |
| 3 | Pitch Bend | 是 |
| 4 | Control Change | 是 |
| 5 至 7 | 保留 | 是 |

约定：Note 事件必须走 FIFO 保证顺序；高频连续控制参数可采用降采样事件或独立影子寄存器，禁止无控制地占满事件 FIFO。

### 传输接口与时序语义

```systemverilog
input  logic               event_valid;
output logic               event_ready;
input  performance_event_t event_data;
```

- 当 `event_valid` 与 `event_ready` 在同一 `sys_clk` 上升沿同时为高时，事件被接收。
- 事件只在 `sample_tick` 边界被音频核心取用，同一 `sample_tick` 内到达的多个事件应全部在本拍处理或全部进入下拍，不得部分处理。
- 背压策略见 Q5。
- 复位期间 `event_ready` 的行为必须在模块接口注释中写明。

### 事件 FIFO 约定

- 深度见 Q4。
- 溢出时必须置位 `event_fifo_overflow` 计数，不得静默丢弃。
- Note On 与对应的 Note Off 不得因溢出而错配，必要时按最老事件丢弃并在状态寄存器中记录。

## 四 音频样本接口

```systemverilog
output logic signed [23:0] pcm_left;
output logic signed [23:0] pcm_right;
output logic               pcm_valid;
input  logic               pcm_ready;
```

- 内部 PCM 暂定有符号 24 位，混音累加暂定有符号 32 位或更宽。
- 波表样本暂定有符号 16 位。
- 每个 `sample_tick` 产生一组左右样本，交接在 `sample_tick` 边界完成。
- 音频核心与 I2S 数字发送的边界即本接口：`pcm_*` 由 M1 侧产生，I2S 移位与串行时序由 M2 负责。
- 位序、声道顺序与 I2S 相位对齐方式见 Q7。
- 最终位宽只能在 Python 参考模型和综合报告支持下调整，禁止仅凭听感确定。

## 五 状态与错误接口

各子系统至少提供：

- `active_voice_count`
- `clip_count`
- `event_fifo_overflow`
- `audio_underrun`
- `max_processing_cycles`

UART 文本字段名称保持稳定，便于上位机自动解析。字段命名一经冻结由 M2 维护。

## 六 公共接口修改规则

修改字段、位宽、极性或握手时序前，必须：

1. 在技术决策记录新增提案。
2. 列出影响模块、Testbench 和脚本。
3. 三名负责人确认。
4. 先修改接口文档和公共测试桩。
5. 各模块在同一个集成窗口完成适配。
6. 全回归通过后合并。

## 七 待决项（T001 评审范围）

评审时逐项给出结论，未达成一致的项按倾向值执行并在决策记录中标注为暂定。

| 编号 | 待决项 | 候选 | 倾向 | 影响 |
|---|---|---|---|---|
| Q1 | 事件结构总位宽 | 保持 50 位；补齐到 54 位；补齐到 64 位 | 补齐到 64 位，便于 FIFO 与 BRAM 位宽对齐 | 事件 FIFO 实现与资源占用 |
| Q2 | `velocity` 语义与范围 | 7 位 MIDI 直映射；10 位线性；10 位对数 | 10 位线性，保留高分辨率 | ADSR 幅度映射与输入模块 |
| Q3 | `expression` 语义 | 压力与弯音合并；拆成两个字段 | 合并为上包络量，弯音走 Pitch Bend 事件 | 事件宽度与输入模块 |
| Q4 | 事件 FIFO 深度 | 16；32；64 | 32，兼顾突发和弦与资源 | 突发事件丢失概率 |

| Q6 | `sample_tick` 生成归属 | 音频域产生；顶层产生后分发 | 顶层产生后分发，避免门控时钟 | M1 与 M2 的边界 |
| Q7 | I2S 位序与声道对齐 | M1 侧保证；M2 侧保证 | M2 侧保证，M1 只交付左先右后的并行样本 | 调试归属与联调工作量 |
| Q8 | 是否单时钟方案 | 单 `sys_clk` 加使能；音频独立时钟 | 单 `sys_clk` 加使能 | 是否需要在音频通路内做 CDC |
