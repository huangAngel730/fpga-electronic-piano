更新时间：2026-09-11。岗位定义见 `角色分工.md`，验证等级见 `测试验收标准.md`，同步点定义见 `抉择与并行开发顺序.md`。

## 一 硬约束

- 作品提交截止：2026-11-03，周二。
- **完赛度红线：2026-10-18（W6 结束）**。这是保底档必须整体可演示的**最后时刻**，不是计划完成日。红线后不再讨论任何未完成的加分项。见 D019。
- 起点 2026-09-11，合计 53 天，约 7.5 周。
- 国庆期间实验室可用，W5 计为完整工作周，不设假期损耗。
- 冻结日 2026-10-27。冻结后只允许包装、上传和回退，不得再改动码流或核心 RTL。
- W8 为预留缓冲周，用于打包、上传演练与故障回退，不作为开发周。
- 核心开发窗口为 W2 至 W6，共 5 个工作周。所有开发承诺必须落在该窗口内。

预留时间的口径：本排期把 W8 整周作为缓冲，并额外在 W7 留出报告定稿与视频成片的时间。任何需要挤占 W8 的开发任务都视为已经超期。

**红线两侧的分工**：10-18 之前是"把作品做成立"，10-18 至 11-03 的 16 天是"把作品交出去"（报告定稿、视频成片、上传演练、故障回退）。**不得把前者的欠账挪到后者**，因为后者没有余量容纳开发工作。

### 降级顺序与止损（D019）

若进度落后，按以下**固定顺序**降级，砍到某一项时其后的项一并砍掉，不得跳砍：

1. PCB 与机械结构
2. 可视化方案
3. 滑音与颤音
4. 每键独立压力检测
5. 合唱效果
6. 声部规模扩展（8 声部及以上）

两个止损触发点：

- **W5 结束（2026-10-11）**：若"最小可演示闭环"未通（板卡通电 → 固定音从 PT8211 出声 → 输入事件可改变音高 → 至少 2 复音），**立即砍掉全部加分项**。
- **W6 结束（2026-10-18）**：保底档未整体可演示时，继续砍保底档内部非核心项，顺序为**延迟效果 → 第二种音色 → UART 状态输出**。

**四项不可砍**（作品成立的下限）：48 kHz 采样率、4 复音、可复现正式码流、报告与演示视频。

## 二 范围两档

### 保底档

保底档是作品能够成立的最小闭环，W6 结束前必须整体可演示：

- 48 kHz 采样率。
- 4 复音，由统一演奏事件驱动。
- 两种频谱或合成机制明显不同的实时音色。
- 延迟效果，参数可调。
- UART 状态输出与错误计数器。
- 可复现的正式码流。
- 竞赛报告、演示视频和答辩材料。

### 加分档

加分档只在保底档通过 S5 验收后启动：

- 8 声部及以上，冲击 32 声部。
- 合唱效果。
- 每键独立压力检测。
- 滑音与颤音。
- 可视化方案。
- PCB 与机械结构。

规则：任何一周的保底任务未完成时，该周不得启动加分项。加分项不得占用 W7 与 W8。**进度落后时按上文 D019 的固定顺序整体降级，不逐项挑选。**

## 三 周计划

### W1 2026-09-07 至 09-13 治理与环境

- 目标：分支、模板、规范与工具链全部就绪。

- M2：建立 develop 与各起步分支，跑通持续集成。
- M3：确认板卡与仪器实物状态，启动采购跟进。
- 退出条件：D011 设施可用；五个分支就位；板卡到货时间已知。

### W2 2026-09-14 至 09-20 接口冻结与固定音输出

- 目标：S1 事件接口冻结，S2 440 Hz 固定音上板。
- M1：T002 Python DDS 黄金模型，T003 波表与 FCW 生成脚本。
- M2：T005 I2S 发送器与解码 Testbench，T007 官方示例上板。
- M3：T006 NEO Dock 引脚与电源核对，T011 设备贴标签并首次登记。
- 硬任务：资源预算初版，确定复音数上限定档。
- 退出条件：接口文档书面冻结；440 Hz 在板卡上可测；资源预算表完成。

### W3 2026-09-21 至 09-27 单声部打通

- 目标：S3 Note On 与 Note Off 逐样本正确。
- M1：T004 DDS RTL，T009 ADSR 参考模型与 RTL。
- M2：sample_tick 与时钟复位方案，集成骨架搭建。
- M3：临时按键与统一事件转换，输入去抖。
- 退出条件：单声部逐样本比较 PASS；集成骨架可综合。

### W4 2026-09-28 至 10-04 基础复音

- 目标：S4 四声部和弦、削波与事件 FIFO 正确。
- M1：T010 四声部管理与宽位混音器。
- M2：混音累加与饱和限幅的资源与时序处理。
- M3：UART 状态输出与上位机雏形。
- 退出条件：四声部和弦上板可听且不削波；事件 FIFO 压力测试 PASS。

### W5 2026-10-05 至 10-11 多音色与效果器

- 目标：第二种音色可用，延迟效果可开关调参。

- **止损检查点（D019）**：本周结束（10-11）时核对"最小可演示闭环"是否已通——
  板卡通电 → 固定音从 PT8211 出声 → 输入事件可改变音高 → 至少 2 复音。
  **未通即砍掉全部加分项**，资源全部转入保底档。

## 四 关键路径

板卡到位 → S2 固定音输出 → S3 单声部 → S4 基础复音 → S5 资源与时序 → S6 交互冻结 → S7 稳定码流 → 提交。

- 关键路径上的第一环是板卡。板卡在 W2 结束前无法下载时，W3 起的上板任务全部转阻塞，需要立即升级处理。
- 电脑端任务（模型、脚本、报告、上位机）不占用关键路径，可在板卡阻塞期间提前。

## 五 每周同步

- 每周固定一次，三人到齐，时间写入任务看板。
- 产出物至少包括：任务看板状态更新、风险登记表更新、资源使用记录更新、下周集成窗口确认，以及写入 `每周同步记录.md` 的当周记录。
- 缺少任一产出物视为同步未完成，未完成同步不计入本周进度。
- 集成窗口从共享配额支出，参与方必须先把各自模块推进到 L2 以上。

## 六 工时口径

- 板卡配额与人的工时是两个独立口径。板卡配额限制的是设备时间，不是工作量。
- 每人每周 12 小时为已确认的排期基线（三人于 2026-09-11 确认）。
- 核心开发窗口 W2 至 W6 共五个工作周，按基线折算每人可用开发工时约 60 小时，需同时容纳实现、集成与验证，不含报告与视频的收尾时间。
- 周投入低于假设时按 `风险登记表.md` 中 R06 处理，先触发软件分担，再重排窗口。

## 七 更新规则

- 每周同步后由当周主负责人更新本文件。
- 同步点状态变化必须同时更新 `任务看板.md` 和 `当前状态.md`。
- 调整冻结日需要走 `变更与决策流程.md`，不得由单人决定。
