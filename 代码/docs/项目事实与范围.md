# 项目事实与范围

更新时间：2026-09-10。

## 项目目标

- 赛题：高云选题二 基于 FPGA 的实时多音色合成电子乐器引擎。
- 开发板：Sipeed Tang Mega 60K 加 NEO Dock。
- FPGA：`GW5AT-LV60PG484AC1/I0`。
- 核心原则：正式音频样本由 FPGA 逐采样生成，电脑、MCU 或树莓派不得代替 FPGA 完成核心合成通路。

## 当前已冻结

- 系统采用模块化架构。
- 音频输出协议采用 I2S。
- 基础合成采用 DDS 加单周期波表。
- 每个活跃声部具有独立相位、频率和 ADSR 状态。
- 多声部混音必须使用宽位累加、舍入和饱和限幅。
- 不同交互硬件必须转换为统一演奏事件，音频核心不得依赖具体传感器。
- 第一阶段必须具备 UART 状态、错误计数器和调试 GPIO。

## 当前阶段目标

- 目标采样率：48 kHz，待板载音频链路实测确认。
- 基础节点：单声部、4复音。
- 正式规模：32个独立活跃振荡器或达到赛题认可的等效并行规模。
- 多音色：至少两种频谱或合成机制明显不同的实时音色。
- 效果器：延迟优先，合唱为推荐拓展。
- 端到端延迟：基础要求不高于10 ms，项目目标低于5 ms。

## 尚未冻结

- 琴键、触摸、压力、光电、摇杆或MIDI等具体交互方案。
- 是否每键独立压力检测。
- 最终DAC使用板载音频还是PCM5102A。
- 最终输出位宽、声道表现和功放方案。
- 第三种音色、Karplus Strong和复杂物理建模。
- HDMI、OLED或电脑上位机作为最终可视化方式。
- 是否制作PCB、最终机械结构和是否挑战64复音。

## 明确不允许

- 播放完整预录音符、歌曲或PCM片段冒充实时合成。
- 未经验证将5 V信号直接连接3.3 V FPGA GPIO。
- 在没有测试结果时将候选方案写成已完成或唯一实现。
- 为赶进度绕过统一接口，让交互模块直接控制合成模块内部状态。
