# 三人开工任务说明

更新时间：2026-09-12。适用阶段：W1 收尾至 W2，目标是在 2026-09-20 前完成 S1 接口冻结和 S2 固定音链路的关键准备。

## 一 当前结论

三个人现在可以开始工作，不需要继续等待管理框架完善。

- M1 立即开始 Python DDS 参考模型和波表、FCW 生成工具。
- M2 用一至两天建立正式 FPGA 技术骨架，并组织接口冻结。
- M3 立即开始板卡、电源、引脚、外设和实验室资源核对。

开始工作不等于三个人同时随意修改 `代码/rtl/`。每个人必须使用任务看板中的任务编号和独立分支，只修改授权目录。

## 二 共同前置任务

三人应在第一次同步会中评审 `模块接口规范.md` 第七节的 Q1 至 Q8，并完成 T001。至少确认：

1. `performance_event` 字段、编码和总位宽。
2. Note On、Note Off 和 Velocity 为零的语义。
3. `valid/ready` 的握手规则。
4. FIFO 满时阻塞、丢弃或错误计数的处理方式。
5. 连续控制参数是否与音符事件共用 FIFO。
6. PCM 有效位宽、符号和左右声道格式。
7. I2S 有效数据位宽、槽位宽度和数据相位。
8. `sample_tick`、系统时钟域和复位释放方式。

接口冻结前允许建立独立模型、testbench 和局部模块，但不得让未确认的字段扩散到多个正式模块。

## 三 M1 立即任务

岗位：音频算法、验证与竞赛交付负责人。

### 当前任务

|---|---|---|---|

### 授权目录


### 第一批交付要求

- 参数至少包括 48 kHz 采样率、32 位相位和 16 位波表样本。
- 输出至少覆盖正弦、方波和锯齿波中的两种。
- 写明定点格式、舍入方式和预期误差。
- 测试不能只由肉眼看曲线判断，必须输出 PASS 或 FAIL。
- 暂不依赖开发板，不等待 M2 的完整顶层。

### 不要做

- 不自行修改公共接口、系统时钟和 I2S 格式。
- 不把 Python 或电脑音频作为正式实时合成通路。
- 不直接在冻结原型 `legacy-prototype/` 上扩展正式算法。

### M2 的边界

- PCM 数学格式和算法行为由 M1 定义，M2负责工程实现和时序可行性。
- 实物引脚、电压和接线依据由 M3提供，M2将确认结果写入 CST、SDC和顶层。
- 未确认的引脚不得写成正式约束。
- 第一版目标是固定 PCM 能被 testbench 正确解码，不是立即实现32复音。

- 两套板卡、两个逻辑分析仪及实验室公共仪器的实际状态。

- 不在带电状态修改跳线或焊接。
- 不在没有记录 Git 提交和码流来源时进行上板结论登记。

## 七 分支和交付规则

每个人开始前执行：

```powershell
git switch develop
git pull --ff-only origin develop
git switch -c feature/任务名
```

如果目标分支已经存在，切换到已有分支，不重复创建。提交前至少运行：

```powershell
. .\代码\scripts\enter_fpga_env.ps1
.\代码\scripts\check_repo.ps1
git diff --check
git status --short
```

每次交付必须说明：任务编号、修改文件、运行命令、实际结果、L0至L7验证等级、未验证项目和公共接口影响。

## 九 第一次共同验收线

第一次集成不要求真实开发板发声，先完成数字链路：

```text
固定 PCM 测试向量
    -> I2S 发送器
    -> testbench I2S monitor
    -> 解码 PCM
    -> 与原输入逐样本比较
    -> 自动 PASS 或 FAIL
```

通过后再接 M1 的 DDS 和 ADSR。开发板到货后，M3按照同一测试向量核对真实 BCLK、LRCLK和DATA。
