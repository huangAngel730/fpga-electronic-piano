# 变更与决策流程

## 需要三人共同确认的事项

- 公共事件接口和PCM接口。
- 系统时钟、复位方式和采样率。
- 内部主要数据位宽和定点格式。
- 顶层端口、CST引脚和I/O电压。
- 最大复音架构和声部状态布局。
- 正式DAC、最终交互方案和正式显示方案。
- 新增会显著占用DSP、BSRAM或DDR3的功能。

## 决策顺序

1. 明确问题和验收指标。
2. 列出候选方案，不超过三个主要候选。
3. 分配原型实验或仿真负责人。
4. 记录数据：延迟、资源、稳定性、成本和工作量。
5. 三人评审，选择方案和回退方案。
6. 更新技术决策记录和接口规范。
7. 创建实施任务，完成后运行全回归。

## 紧急修复

影响安全、供电或可能损坏硬件时，任何人可立即停止实验。修复仍需记录原因、变更和验证结果。

## 禁止行为

- AI或个人未经确认直接修改公共接口。
- 先修改代码，后补接口文档。
- 仅凭听感决定定点位宽、滤波或效果器方案。
- 仅凭单次上板成功就标记已冻结。
