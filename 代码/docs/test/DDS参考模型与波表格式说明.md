## 二 定点格式

### 2.1 相位累加器

| 项目 | 值 | 说明 |
|---|---|---|
| 位宽 | 32 位无符号 | 溢出自然回绕，等价 mod 2^32 |
| 频率控制字 FCW | 32 位无符号 | `FCW = round(f * 2^32 / fs)`，半值远离零 |
| 频率分辨率 | `fs / 2^32` ≈ 1.1176e-5 Hz | 决定音高量化误差 |
| 累加时机 | 每个 `sample_tick` 累加一次 | 不用 `sample_tick` 当时钟 |

**先取样、后累加。** 复位后第 0 个输出样本对应相位 0，累加发生在输出之后。
这一条决定 T004 逐样本比较时的对齐关系，RTL 写反会整体错一拍。

### 2.2 波表

| 项目 | 值 |
|---|---|
| 长度 | 1024 点单周期 |
| 样本格式 | 16 位有符号，等效 Q1.15 |
| 满幅 | ±32767 |
| 寻址 | 相位高 10 位 `phase[31:22]` |
| 相位小数 | 低 22 位 `phase[21:0]` |
| v1 取值方式 | **相位截断，不插值** |

满幅取 32767 而不是 32768，是为了让正负满幅对称。若取 -32768，做取反或
调制时会立刻溢出 16 位，需要额外一位保护，得不偿失。

三种波形的数学定义（`i` 为表地址 0 至 1023，`A = 32767`，`N = 1024`）：

| 波形 | 定义 | 特征值 |
|---|---|---|
| `sine` | `round(A * sin(2*pi*i/N))` | `t[0]=0`，`t[256]=32767`，`t[512]=0`，`t[768]=-32767` |
| `square` | 前半周期 `+A`，后半周期 `-A` | 占空比 50%，全表和为 0 |
| `saw` | `round(A * (2i/N - 1))` | `t[0]=-32767`，`t[512]=0`，`t[1023]=32703`，单调不减 |

正弦表按奇对称构造：只算前半周期，后半周期取反填充，保证
`t[i + 512] == -t[i]` 在数值上严格成立，而不是依赖 `sin(x + pi)` 的浮点结果。

**给 T004 的实现提示**：正弦表还满足四分之一周期对称，RTL 上只存 256 个点
即可，ROM 占用降到四分之一；锯齿波可以直接由 `phase[31:16]` 翻转符号位得到，
根本不必占 ROM。这两项优化在 T016 资源预算里再决定是否采用。

### 2.3 波表样本到 PCM

```text
pcm24 = saturate( round_half_away( (wt16 << 8) * gain_q15 / 32768 ) )
```

| 步骤 | 规则 |
|---|---|
| 定标 | 左移 8 位，等价乘 256，**无舍入误差** |
| 增益 | Q1.15，32768 表示 1.0；等于 32768 时跳过乘除，为纯移位 |
| 舍入 | 半值远离零，全程整数运算，不经过浮点 |
| 限幅 | 饱和到 [-8388608, 8388607]，并计一次削波 |

满幅波表样本经定标后为 `32767 * 256 = 8388352`，相当于 -0.0003 dBFS，
比 24 位满量程低 256 个 LSB，不会自己撞上限幅。

**禁止用低位截断或回绕代替饱和限幅。** 回绕在音频上是正负满幅之间的瞬时跳变，
听感是剧烈爆音，是这条链路最危险的失效模式。自检里专门有一项用 2.0 倍增益
制造溢出，确认输出被限幅且削波计数递增。

不使用 Python 内置 `round`，因为它是银行家舍入（半值取偶），与 RTL 中常用的
「加半个 LSB 再截断」不一致，会造成偶发的一 LSB 失配。

## 三 音高换算

```text
f(note) = 440 * 2^((note - 69) / 12)      十二平均律，A4 = 440 Hz
FCW     = round(f * 2^32 / 48000)
f_actual = FCW * 48000 / 2^32
```

超过奈奎斯特频率的频率默认拒绝并报错，避免无意中合成出混叠音。
MIDI 全表（`build_note_table`）显式允许超奈奎斯特，因为表要覆盖 0 至 127；
高音区实际能不能用由使用方判断，见第七节已知限制。

## 四 生成文件格式

生成命令（仓库根目录执行）：

```powershell
python -X utf8 代码/model/wavetable_gen.py
python -X utf8 代码/model/wavetable_gen.py --check
```

输出目录 `代码/model/generated/`，由脚本完全托管，不要手工编辑。

### 4.1 通用格式约定

- 纯文本，UTF-8，**LF 换行**，文件末尾有一个换行。
- 十六进制一律小写、定长补零，**不含注释行、不含表头**（`.csv` 除外），
  可直接被 Verilog `$readmemh` 读取。
- 每行一个数值，**行序即地址序**：第 1 行是地址 0。
- 每行内高位在左，即 MSB first。
- 全部为文本格式，**不涉及二进制字节序**。将来若需要二进制，约定按大端存放，
  届时另行发布新版本。

### 4.2 文件清单

| 文件 | 行数 | 每行 | 内容 |
|---|---|---|---|
| `wt_sine_1024x16.hex` | 1024 | 4 位十六进制 | 16 位有符号正弦波表 |
| `wt_square_1024x16.hex` | 1024 | 4 位十六进制 | 16 位有符号方波表 |
| `wt_saw_1024x16.hex` | 1024 | 4 位十六进制 | 16 位有符号锯齿波表 |
| `fcw_midi_48k.hex` | 128 | 8 位十六进制 | MIDI 0 至 127 的 32 位 FCW，行号即音符号 |
| `fcw_midi_48k.csv` | 129 | 带表头 | 音符号、音名、理想频率、FCW、实际频率、误差 Hz、误差音分 |
| `pcm_ref_440hz_sine_left.hex` | 4800 | 6 位十六进制 | 440 Hz 正弦，满幅 |
| `pcm_ref_440hz_sine_right.hex` | 4800 | 6 位十六进制 | 440 Hz 正弦，精确一半幅度 |

## 五 给 M2 的交付说明（T005 用）

### 5.1 440 Hz 参考 PCM

- 4800 个样本 = 100 ms = 约 44 个周期，够做频率复核。
- 左声道满幅，正负峰值 ±8388352，用来检查符号位、MSB 和 24 位有效数据。
- 右声道是左声道的**精确一半**（增益 Q15 = 16384，可整除，无舍入误差），
  正负峰值 ±4194176。

右声道故意做成一半幅度，是为了让「左右声道接反」这个错误一眼可见：
如果解码出来的左声道幅度只有右声道的一半，就是 LRCLK 极性或者声道顺序反了，
不必去看波形猜。判定方法：对每一组样本断言 `right * 2 == left`。

### 5.2 边界测试向量

14 组，依次为：

```text
0x000000  0x000001  0xffffff  0x7fffff  0x800000  0x7ffffe  0x800001
0x400000  0xc00000  0x555555  0xaaaaaa  0x0000ff  0x00ff00  0xff0000
```

分别对应 0、+1、-1、正满幅、负满幅、正满幅减一、负满幅加一、正半满幅、
负半满幅、两种交替位型、只有低 8 位有效、只有中间 8 位有效、只有高 8 位有效。

这组向量针对 I2S 链路最容易出的三类错误：

| 现象 | 会被哪个向量抓到 |
|---|---|
| 符号扩展做错 | `0xffffff`、`0x800000` |
| MSB first 写成 LSB first | `0x555555` 与 `0xaaaaaa` 互换，`0x0000ff` 与 `0xff0000` 互换 |
| 24 位有效数据与 8 位填充零错位 | `0x0000ff` 的低位被填充零吃掉 |

右声道整体错开一位，任何左右互换都会在第一组样本就暴露。

### 5.3 建议的判定方式

I2S monitor 解码出的每一组样本，与上面两个文件逐样本比较，
全等才算 PASS。不要只看波形，也不要只比对前几个样本。

### 5.4 接口影响

本批交付**不改动任何公共接口**，只提供数据和格式说明。
PCM 位宽、采样率、I2S 槽位全部沿用接口规范 v1.0。

## 六 验收阈值与实测结果

### 6.1 阈值及其依据

阈值全部定义在 `代码/model/audio_defs.py`，测试直接引用，不在测试里另写数值。

| 阈值 | 取值 | 依据 |
|---|---|---|
| 音高误差 | ≤ 1 音分 | 受过训练的听音者对稳态音高的辨别阈约 5 音分，取 5 倍余量 |
| FCW 量化误差 | ≤ 0.002 音分 | 理论上界为半个 FCW LSB 折算到最低音 MIDI 0（8.1758 Hz）处，约 1.19e-3 音分；取约 1.7 倍余量 |
| 正弦 SINAD | ≥ 50 dB | 相位截断理论 SFDR ≈ 6.02 × 10 − 3.92 = 56.3 dB，取约 6 dB 工程余量 |
| 正弦 THD | ≤ -40 dBc | 附加检查，相位截断杂散多为非谐波，主判据是 SINAD |
| 直流偏置 | ≤ 16 LSB | 相当于 24 位满量程的 -114 dB，用于发现波表构造或舍入方向写错这类系统性偏置 |

**为什么主判据是 SINAD 而不是 THD**：相位截断 DDS 的主要杂散不落在谐波上，
只统计谐波的 THD 会给出过于乐观的结论。实测这一点很明显，见下表：THD 有
-118 dBc，SINAD 只有 55 dB，两者差了 60 多 dB。SINAD 用最小二乘拟合出基波后
统计全部残差功率，谐波和非谐波杂散都算在内，不会漏。

### 6.3 线性插值的收益记录

模型同时实现了线性插值取值方式，不属于 v1 判定基准，只作为 T004 的决策依据：

| 取值方式 | SINAD | 代价 |
|---|---|---|
| 相位截断 | 55.03 dB | 1 次查表 |
| 线性插值 | 95.70 dB | 2 次查表 + 1 次乘法 + 1 次移位 |

提升 40.67 dB。是否上插值在 T016 资源预算出来之后决定：如果目标是最大化
振荡器数量，55 dB 对第一版够用；如果 DSP 和 BRAM 有余量，插值能明显改善音质。
另一条路是把表加长到 4096 点，SINAD 理论上能到 68 dB 而不需要乘法器。

## 七 已知限制与未验证项

1. **未做 RTL 比较**。T004 的 DDS RTL 还没写，逐样本比较尚未进行。
   本批只是建立基准，不能视为算法已在硬件上验证。
2. **未上板**。没有任何 L4 以上结论。
3. **高音区混叠未处理**。MIDI 表覆盖 0 至 127，其中较高的音符本身低于奈奎斯特，
   但方波和锯齿波的高次谐波会折返。第一版不做带限波形，等确定音域和音色方案
   后再决定是否上 BLEP 或多级带限波表。
4. **未建模 ADSR、复音与混音**。T009、T010、T023 再补，届时 PCM 的定标可能
   需要为多声部累加留出增长位，本文件会随之出新版本。
5. **未建模实时变调**。相位累加器支持随时改 FCW，但换字瞬间的相位连续性
   与滑音行为还没定义。
6. **A0 测量误差偏大**属正常。16384 个样本在 27.5 Hz 下只有约 9 个周期，
   两段相位差法的精度受周期数限制，不是算法误差。需要更准的数值时加长测量窗。
