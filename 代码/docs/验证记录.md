# 验证记录

更新时间：2026-09-11。验证等级定义见 `测试验收标准.md`，任务编号见 `任务看板.md`。

## 一 用途

本文件是全部验证结果的唯一落点。任何"已通过"的结论都必须能在这里找到对应行，否则视为未验证。

`代码/AGENTS.md`、`协作入口.md`、`角色分工.md`、`model/AGENTS.md` 和 `抉择与并行开发顺序.md` 中提到的"验证记录"都指本文件。

禁止把通过结论只留在聊天记录、AI 会话或个人笔记里。全队使用 AI 的情况下，本文件是复核和答辩时唯一的证据索引。

## 二 记录格式

| 字段 | 填写要求 |
|---|---|
| 编号 | V 加四位序号，按登记顺序递增 |
| 日期 | 实际执行日期，格式 YYYY-MM-DD |
| 任务 | 任务看板中的任务编号，无编号时写模块名 |
| 模块 | 被测模块或文件的仓库相对路径 |
| 等级 | L0 至 L7，只能取 `测试验收标准.md` 中的定义 |
| 运行命令 | 可复制执行的真实命令，注明工作目录 |
| 结果 | PASS、FAIL 或部分通过，FAIL 与部分通过必须写清现象 |
| 证据位置 | 波形、日志、报告或对比数据的仓库相对路径 |
| 执行人 | 实际执行者，由 AI 代为执行时填写发起该任务的队员 |
| 复核人 | 按 `角色分工.md` 填写，不得与执行人相同 |

结果不得只写"正常""看起来没问题"这类无法复核的描述，也不得省略等级。

## 四 登记时机

- 每次运行模块自检、逐样本比较、综合、布局布线、时序分析或上板实测后立即登记。
- 由 AI 代为执行时，由发起该任务的队员负责登记，不得由 AI 自行宣告通过。
- 复核人核对证据后确认结果，并补填复核人字段。

## 五 与任务看板的关系

- 任务看板中标记"已完成"的任务，本文件必须有对应 PASS 行，且等级不低于该任务的验收条件。
- 等级不足时只能标记为"进行中"或"待复核"，不得标记为已完成。
- 上板相关任务缺少 L6 及以上记录时，不得写成已上板。

## 六 更新规则

- 只允许追加，不允许删除或改写历史行。
- 需要更正时追加一行新的更正记录，并注明被更正的原编号。
- 等级判定有争议时以 `测试验收标准.md` 为准，必要时走 `变更与决策流程.md`。
