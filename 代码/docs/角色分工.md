# 三人团队角色分工

## 硬件一 音频核心负责人

主责模块：复音管理、音频合成、包络与音色控制、混音与效果、I2S数字发送。

交付物：

- 可综合RTL和自检Testbench。
- 定点格式说明、资源和时序报告。
- 声部管理、削波及错误计数器。
- 与Python参考模型一致的样本输出。

复核：软件负责人复核数值；硬件二复核I2S上板结果。

## 硬件二 交互与板级负责人

主责模块：交互输入、板级时钟复位、约束、接线、电平、ADC、DAC和仪器验证。

交付物：

- 候选琴键和传感器实验数据。
- 输入驱动RTL和自检Testbench。
- CST约束、引脚表、接线图和电源说明。
- I2S、SPI、输入延迟及稳定性测量。

复核：硬件一复核事件输出；软件负责人复核日志可解析性。

## 软件 验证与自动化负责人

主责模块：Python黄金模型、仿真、构建脚本、串口工具、音频分析和数据报告。

交付物：

- DDS、ADSR、混音和效果参考模型。
- 波表及频率控制字生成器。
- 自动PASS或FAIL的回归测试。
- Gowin构建、报告检查、串口和WAV分析脚本。
- 可复现测试记录和图表。

限制：不直接替FPGA完成正式音频合成；修改功能RTL需由对应负责人复核。

## 共同责任

- 三人都能解释总体数据流、DDS、ADSR、复音、I2S和延迟测量。
- 公共接口由三人共同冻结。
- 每个模块至少一名非作者复核。
- 稳定主板和实验板的码流版本必须可追踪。
