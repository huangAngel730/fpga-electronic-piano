# 抉择与并行开发顺序

## 第一批 立即抉择

这些项目决定团队能否并行：

1. 统一演奏事件字段和握手方式。
2. 第一版音频数据格式：48 kHz目标、32位相位、16位波表、24位PCM、32位混音累加。
3. 时钟、复位和 `sample_tick` 使用方式。
4. 音频核心与I2S输出的边界。
5. Git分支、任务编号和验证记录格式（已定，登记格式见 `代码/docs/验证记录.md`）。

## 第二批 板卡到手后一周抉择

1. 板载音频或PCM5102A作为正式输出。
2. I2S数据位宽、槽位宽度、声道极性及是否需要MCLK。
3. 实际系统时钟和PLL配置。
4. 4条或8条声部处理流水线的初步架构。
5. NEO Dock可用引脚和调试测试点。

## 第三批 音频核心稳定后抉择

1. 正式琴键与力度方案。
2. 滑音、颤音和连续表情的物理控制器。
3. 第二种和第三种音色。
4. 延迟、合唱及其参数范围。
5. UART上位机、OLED或HDMI可视化方案。

## 第四批 后期抉择

1. 是否制作PCB和最终机械结构。
2. 是否每键独立压力。
3. 是否加入Karplus Strong。
4. 是否挑战64复音。
5. 是否加入手机或蓝牙功能。

## 三条并行工作线

### 工作线A 音频RTL

```text
采样节拍 -> DDS -> 波表 -> ADSR -> 单声部 -> 4复音 -> 32声部 -> 多音色 -> 效果器
```

### 工作线B 交互板级

```text
原理图和引脚 -> LED UART -> I2S实测 -> 临时按键 -> ADC传感器原型 -> 正式交互对比
```

### 工作线C 软件验证

```text
Python DDS -> 波表生成 -> ADSR模型 -> RTL回归 -> 构建脚本 -> 串口解析 -> WAV和FFT分析
```

## 同步点

| 同步点 | 前置条件 | 三方共同验收 |
|---|---|---|
| S1 接口冻结 | 事件和PCM草案完成 | 接口字段、位宽和握手 |
| S2 固定音输出 | DDS模型、I2S RTL、板级音频可用 | 440 Hz频率和I2S时序 |
| S3 单声部完成 | DDS、ADSR、事件注入 | Note On和Note Off逐样本正确 |
| S4 基础复音 | 4声部和混音 | 和弦、削波、事件FIFO |
| S5 32规模 | 资源及时序报告 | 吞吐、资源和稳定性 |
| S6 交互冻结 | 候选输入实测 | 延迟、稳定性、演奏体验 |
| S7 提交冻结 | 整机稳定 | 视频、报告、备用方案 |
