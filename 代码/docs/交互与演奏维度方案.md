# 交互与演奏维度方案

状态：**草案，未冻结**。对应任务拟编号 T050，决策拟编号 D017。

起草日期：2026-09-12。起草人：M2。

本文件回答一个问题：在两个月工期内，做什么样的演奏交互，既能满足赛题基础要求（≥2 个独立可控维度）和拓展要求（≥3 维表情调控），又不至于做不完。

## 一 赛题原文要求

基础要求原文：

> 系统依托电容触摸、光电感应、压力检测、无接触手势等**任意自研交互方案**，实现至少 2 个独立可控演奏维度的动作采集，精准识别选音、和弦、触发、拨弦等演奏指令。

拓展要求原文：

> 自主设计演奏交互形态，基于各类传感器实现演奏动作精准采集，支持选音、触发、拨弦、**力度感应**等操作，具备**至少 2 个独立可控维度**，交互逻辑灵敏稳定，适配乐器演奏场景。

> 搭建 **≥3 维演奏表情调控逻辑**，支持**力度动态、滑音、颤音**等演奏效果；支持 ≥2 种乐器音色自由切换。

## 二 方案选型与合规性论证

### 2.1 候选方案

| 方案 | 交互载体 | 维度来源 | 工期风险 | 演示直观性 |
|---|---|---|---|---|
| A 全自研键盘矩阵 | 自建机械结构 | 自建扫描与力度检测 | 中 | 高 |
| **B 外购 MIDI 键盘直读** | **外购 25 键力度键盘** | **MIDI 流解析** | **低** | **高** |
| C 外购键盘硬件 + 自研扫描 | 外购键盘总成 | 自研扫描与力度算法 | 低 | 高 |
| D 电容触摸 / 光电 / 手势 | 自研传感器 | 自研传感器 | 高 | 中 |

### 2.2 选定方案：B

选定 **方案 B：外购带力度的 MIDI 键盘，FPGA 侧解析 MIDI 流并转换为统一演奏事件**。

选择理由：

- **赛题的"自研"指自主选择与设计交互方案，不限定必须自制传感器**。赛题原文列举"电容触摸、光电感应、压力检测、无接触手势等**任意**自研交互方案"，其中"任意"一词表明方案形态由参赛队自主决定。选择力度键盘作为交互载体、并围绕它设计维度划分与事件映射，本身就是自主决策的结果。
- **工期风险最低**。两个月内，把时间投在算法与合成引擎上比投在机械结构上收益更高，而算法正是本赛题的核心评分点（实时多音色合成引擎）。
- **力度天然满足基础要求的第二维**。带力度键盘直接提供 velocity，无需自行设计力度检测机构。
- **演示直观**。键盘形态评委一眼可识别，交互意图无需解释。

### 2.3 本方案中仍属自研的部分

选择外购键盘不等于交互侧没有工作量。以下部分由本项目自行设计与实现：

| 自研内容 | 归属 | 说明 |
|---|---|---|
| MIDI 接收与解析 | M3 | UART 采样、字节流同步、运行状态解析、实时性保证 |
| MIDI 到统一事件转换 | M3 | 依据接口规范 3.2 节映射到 `performance_event_t` |
| 连续控制器限速与合并 | M3 | 满足接口规范 3.7 节的 1 kHz 限制 |
| 维度划分与映射策略 | M3 | 决定哪些 MIDI 控制器承载哪个演奏维度 |
| 踏板/弯音轮采集 | M3 | 若键盘自带则解析 MIDI，否则自行接入 |
| 和弦识别 | M1 | 依据同时进入的 Note On 判定 |
| 拨弦判定 | M1 | 依据力度与触发包络特征 |
| 全部合成算法 | M1 | 与交互解耦 |

**技术要点**：MIDI 是 31.25 kbaud 的异步串行协议，需要处理起始位检测、字节边界同步、运行状态（running status）压缩、以及 3 字节消息的原子性。这些不是"直接可用"的现成功能，属于交互适配层的实际工作量。

### 2.4 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 键盘 MIDI 输出电平为 5 V | 可能损坏 FPGA IO | 接入前必须确认电平；5 V 时加分压或电平转换 |
| 键盘使用 USB-MIDI 而非 UART MIDI | 无法直接接入 | 采购时确认具备标准 MIDI OUT 或可引出 UART TX |
| MIDI 31.25 kbaud 的采样与同步 | 解析错误导致丢音 | UART 采样率取 16 倍过采样，加帧错误与溢出计数 |
| 力度来自键盘内部，映射曲线不可控 | 力度听感受限于键盘 | 在适配层做曲线重映射，不改变键盘原始输出 |
| 键盘延迟未实测 | 影响 R11 灵敏稳定 | T036 实测端到端延迟 |

### 2.5 待核实

- 键盘型号、价格、MIDI 输出形式（标准 MIDI OUT / UART TX / 仅 USB）、供电与逻辑电平，**未核实**，由 M3 在 T050 前期完成。
- **采购前置条件**：必须确认键盘可输出标准 MIDI 或可引出 UART TX。仅支持 USB-MIDI 的型号无法直接接入，采购前需确认。
- 键盘自身力度响应特性与延迟，**未实测**。

## 三 演奏维度定义

第一版定义三个维度，与赛题的 R1、R6、R7 对应。

### 维度 1：选音（对应 R1、R2）

| 项目 | 内容 |
|---|---|
| 物理来源 | 键盘按键位置，经 MIDI Note On / Note Off 消息 |
| 事件字段 | `note_number`（7 位，0 至 127） |
| 更新方式 | Note On / Note Off 离散事件 |
| 接口编码 | `EVENT_NOTE_ON`（0）、`EVENT_NOTE_OFF`（1） |
| 键盘规模 | 25 键，两个八度 |
| 音域 | C3 至 C5，覆盖演示曲目 |

25 键而非 13 键的理由：演示曲目通常需要两个八度。使用 MIDI 键盘后，键数由所选型号决定，FPGA 侧不增加任何扫描或引脚负担，因此键数不再是工程约束，可按演奏需要选择。若选 49 键或 61 键型号，FPGA 侧实现不变。

### 维度 2：力度（对应 R6、R1 的第二维）

| 项目 | 内容 |
|---|---|
| 物理来源 | 键盘自身力度检测，经 MIDI 消息的 7 位 Velocity 给出 |
| 事件字段 | `velocity`（10 位，1 至 1023） |
| 更新方式 | 随 Note On 一次性给出 |
| 接口编码 | 承载于 `EVENT_NOTE_ON` 的 `velocity` |
| MIDI 映射 | 按接口规范 3.2 节 `{velocity_7bit, velocity_7bit[6:4]}` 扩展为 10 位 |
| 无力度时的退路 | 固定值 512，保持接口语义不变 |

力度是 R1 要求的第二个独立维度：同一个键按下轻重不同，输出不同，满足"独立可控"。

**力度相关待定项**：键盘型号确定后需实测其力度输出范围与分布，确认是否覆盖 1 至 127 全范围；若键盘力度响应不理想，可在适配层做曲线重映射（不改变键盘原始输出）。映射曲线由 M3 在 T050 中依据实测数据确定。

**注意**：接口规范 3.4 节规定输入适配层收到 Velocity 为 0 的 Note On 时必须转换为 Note Off。MIDI 键盘在松键时可能发送 Note On Velocity 0（部分型号以此代替 Note Off），该情况必须正确处理。

### 维度 3：延音踏板或弯音轮（对应 R7、R8）

| 项目 | 内容 |
|---|---|
| 物理来源 | 键盘自带踏板接口 或 弯音轮，经 MIDI CC 消息 |
| 事件字段 | 均使用 `control_value` |
| 接口编码 | 踏板建议新增 `CTRL_SUSTAIN`；弯音轮用已有的 `CTRL_PITCH_BEND`（0） |
| 更新方式 | 限速连续事件，受接口规范 3.7 节 1 kHz 限制 |

**优先做弯音轮**，理由：接口规范 3.2.1 节已完整定义 `CTRL_PITCH_BEND` 的语义、中心点和弯音范围，无需新增接口定义；MIDI 键盘普遍自带弯音轮，无需额外硬件；且直接满足 R8（滑音）。

**MIDI 映射注意**：MIDI Pitch Bend 为 14 位无符号、中心 8192，需按接口规范 3.2.1 节给出的公式转换为 12 位有符号：

```systemverilog
control_value = $signed({1'b0, midi_bend_14bit} - 15'd8192) >>> 2;
```

延音踏板作为备选：多数 MIDI 键盘带踏板接口，使用标准 CC64 消息。若采用，需在接口规范 3.2.1 节新增 `CTRL_SUSTAIN` 编码。是否采用取决于键盘型号与 M3 的判断。

### 3.4 维度与要求的对照

| 赛题要求 | 覆盖情况 | 承载方式 |
|---|---|---|
| R1 ≥2 个独立可控维度 | 已覆盖 | 维度 1 选音 + 维度 2 力度 |
| R2 选音 | 已覆盖 | 维度 1 |
| R3 触发 | 已覆盖 | Note On / Note Off |
| R4 和弦 | 待实现 | M1 算法，见 G2 |
| R5 拨弦 | 待实现 | M1 算法，见 G2 |
| R6 力度感应 | 已覆盖 | 维度 2 |
| R7 ≥3 维表情调控 | 已覆盖 | 三维度合计 |
| R8 滑音 | 已覆盖 | 维度 3 弯音轮 |

## 四 需实测的指标

以下指标必须在 T036 实测，不得凭估计写入对外材料：

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 按键到事件延迟 | ≤2 ms（FPGA 侧） | 逻辑分析仪测 MIDI 字节到达到 `event_valid` |
| 键盘到发声总延迟 | ≤10 ms，目标 ≤5 ms | 见下方说明 |
| MIDI 解析正确率 | 100%，无丢字节 | 长时间连续演奏，检查帧错误与溢出计数 |
| 力度分辨级数 | ≥16 级 | 逐级按压记录 velocity |
| 力度重复性 | 同力度偏差 ≤10% | 同一力度重复 30 次 |
| 连续控制更新率 | ≤1 kHz | 受接口规范 3.7 限制 |
| 和弦识别同时性窗口 | 待定 | 依据人手生理极限，建议 30 至 50 ms |

**关于总延迟**：使用外购 MIDI 键盘后，延迟链路增加两段本项目不可控的环节。

- MIDI 串行传输：一条 3 字节消息在 31.25 kbaud 下约需 0.96 ms。
- 键盘内部扫描与力度检测：**待实测**，不同型号差异明显，是总延迟的主要不确定项。

因此本方案的总延迟**部分取决于所选键盘**，不能仅由 FPGA 侧决定。T036 必须实测"按键到发声"的完整链路，不能只测 FPGA 侧。若实测总延迟超出 10 ms 基础要求，应对措施包括：在适配层缩短缓冲、优先选用延迟较低的键盘型号。

**与接口规范的衔接**：接口规范 3.7 节规定单一连续控制源更新率不超过 1 kHz。三维度中只有维度 3 属于连续控制，1 kHz 对其足够（颤音通常 5 至 7 Hz，弯音手速远低于 1 kHz）。此外 MIDI CC 消息本身受 31.25 kbaud 带宽限制，实际更新率远低于 1 kHz，接口限制不构成瓶颈。

## 五 与现有差距的对应

本方案解决的差距（编号见 `赛题要求对照表.md`）：

| 差距 | 原本问题 | 本方案的解决方式 |
|---|---|---|
| G1 | 交互维度无设计任务，T036 排到 W6 | 本文件即维度设计，见下方排期说明 |
| G3 | velocity / expression 无传感器来源 | 维度 2 提供 velocity 来源；expression 见 5.1 |

关于 G1 的排期说明：W3 已排入 T021、T022、T015 三个 M3 任务，不宜再插入新任务造成过载。建议的处理方式是把 **T036 的冻结时间从 W6 提前到 W4**，并让 T050 的产出物（键盘选型、力度标定方案）作为 T036 的输入，而不是新增一条并行任务线。T036 是基础要求的冻结节点，排在 W6 确实偏晚。

### 5.1 关于 expression 字段的说明

接口规范中 `expression`（10 位）与 `control_id` 的 `CTRL_MODULATION` 存在语义重叠，该问题已在接口审查中记录但尚未澄清。本次交互方案**不依赖 expression 字段**：

- 力度走 `velocity`
- 弯音走 `control_value`（`CTRL_PITCH_BEND`）
- 颤音走 `control_value`（`CTRL_MODULATION`）

即三个维度全部通过**已定义的字段**承载，不引入新的未定义语义。`expression` 的定位问题留待接口澄清时一并处理。

### 5.2 关于 R9 颤音

`CTRL_MODULATION` 编码已存在，但"调制轮到颤音深度与速率"的映射属算法侧，需 M1 定义。本方案只保证**输入侧能产生该事件**，不承诺音效听感。

## 六 硬件与接线待确认项

以下必须在接线前核实，不得直接连接：

- 键盘的 MIDI 输出形式，**待核实**。需确认是标准 MIDI OUT（电流环，5 针 DIN）、UART TX 电平输出，还是仅 USB-MIDI。**仅 USB-MIDI 的型号无法直接接入 FPGA**，采购前必须确认。
- MIDI 输出电平，**待核实**。标准 MIDI 为电流环，需光耦隔离并转换为 3.3 V UART 电平；若为 5 V UART 输出，接入 FPGA 前必须分压或电平转换。
- 与开发板 IO Bank 电压的匹配关系，**待核实**，见 `板级硬件事实.md`。接入前核对 I/O Bank 电压与引脚容限。
- 最终占用的 FPGA 引脚编号与约束文件，**待核实**，需与 M2 的约束同步更新。
- 键盘是否需要外部供电，**待核实**。
