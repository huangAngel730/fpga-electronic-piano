# FPGA 电子琴串口调试助手：使用教程和示例

本教程对应 T026 Python 串口上位机。它只负责接收、检查、显示和保存 FPGA 状态，
不会生成声音，也不会替代 FPGA 内部的音频处理。

## 一键打开图形界面

在资源管理器中进入本目录，然后双击：

**`打开串口调试助手.cmd`**

也可以尝试点击下面的相对链接；如果 Markdown 阅读器出于安全原因不允许运行 `.cmd`，
请回到资源管理器中双击该文件：

[点击打开串口调试助手](./打开串口调试助手.cmd)

启动文件会调用与测试脚本相同的 Python 发现逻辑。运行期间会保留命令窗口，便于看到启动错误；关闭 GUI 后该窗口会退出。

## 第一次使用：先运行模拟模式

模拟模式不需要开发板，也不需要填写串口参数。

1. 双击 `打开串口调试助手.cmd`。
2. 等待“FPGA 电子琴 · 串口调试助手”窗口出现。
3. 点击顶部的“模拟模式”。
4. 观察七张状态卡片、实时趋势图和右侧日志。
5. 点击“停止”结束模拟监视。

模拟数据会循环演示以下情况：

- 空闲：0 个复音。
- 单音：1 个复音。
- 基础复音：4 个复音。
- 出现一次削波计数。

如果界面不断更新且日志中出现“有效”，说明 Python、Tkinter、解析器和 GUI 数据通路工作正常。

## 界面区域说明

### 串口控制区

| 控件 | 作用 |
|---|---|
| 串口 | 选择 Windows 中检测到的 COM 端口 |
| 波特率 | 填写 T025 最终确认的 UART 波特率 |
| 数据位 | 选择 5、6、7 或 8 |
| 校验 | `N` 无校验、`E` 偶校验、`O` 奇校验、`M` Mark、`S` Space |
| 停止位 | 选择 1、1.5 或 2 |
| 刷新串口 | 重新扫描当前连接的串口 |
| 连接串口 | 使用填写的参数开始接收真实数据 |
| 模拟模式 | 不使用串口，运行内置演示数据 |
| 停止 | 安全停止当前串口或模拟线程 |
| 选择 CSV 日志 | 选择保存位置并开始追加记录；再次点击停止记录 |

真实串口参数没有默认值，因为 T025 尚未冻结波特率和串口格式。不得直接把网上示例参数当成项目参数。

### 七个状态字段

| 字段 | 界面名称 | 含义 |
|---|---|---|
| `active_voice_count` | 当前复音数 | 当前正在发声的声部数量，例如基础目标为 4，扩展目标可到 32 |
| `clip_count` | 削波计数 | 混音或输出超过允许幅度并被限幅的累计次数 |
| `event_fifo_level` | FIFO 当前水位 | 事件 FIFO 当前占用项数 |
| `event_fifo_high_watermark` | FIFO 历史峰值 | 复位后 FIFO 曾达到的最高占用量 |
| `event_fifo_overflow` | FIFO 溢出 | 事件输入无法正常写入的累计异常值 |
| `audio_underrun` | 音频欠载 | 音频样本没有按时交付的累计异常值 |
| `max_processing_cycles` | 最大处理周期 | 单次音频处理曾使用的最大系统时钟周期数 |

事件 FIFO 深度按照已冻结接口规范固定为 32，所以界面把当前水位和历史峰值显示为 `/ 32`。

### 状态提示

界面右上角提示采用保守规则：

- `event_fifo_overflow > 0` 或 `audio_underrun > 0`：显示“需要检查”。
- 没有溢出或欠载，但 `clip_count > 0`：显示“注意”。
- 三个异常计数都为 0 且状态行格式正确：显示“数据有效”。
- 输入缺字段、重复字段、未知字段或非法数值：显示“数据格式错误”。

这里的“数据有效”只表示状态行格式正确且当前异常计数为 0，不等于整个 FPGA 系统已经完成上板验收。

## FPGA 状态行格式

每条记录必须是单独一行，以 `STAT` 开头，并包含全部七个字段。

完整合法示例：

```text
STAT active_voice_count=4 clip_count=0 event_fifo_level=2 event_fifo_high_watermark=4 event_fifo_overflow=0 audio_underrun=0 max_processing_cycles=910
```

字段顺序可以改变，数值可以使用十进制，也可以使用 `0x` 开头的十六进制。

改变顺序和使用十六进制的合法示例：

```text
STAT max_processing_cycles=0x38E audio_underrun=0 event_fifo_overflow=0 event_fifo_high_watermark=4 event_fifo_level=2 clip_count=0 active_voice_count=4
```

缺少字段的错误示例：

```text
STAT active_voice_count=4 clip_count=0 event_fifo_level=2
```

该错误行不会让程序崩溃，右侧日志会显示缺少哪些字段，然后继续等待下一行。

## 连接真实开发板

真实联调需要先完成 T025 FPGA UART 状态发送逻辑。

1. 使用正确的 USB 数据线连接开发板。
2. 给开发板正常上电。当前板卡记录要求长按电源键约 2 秒，并确认多色电源指示灯亮起。
3. 打开本界面并点击“刷新串口”。
4. 从下拉列表中选择新出现的开发板串口。
5. 按 T025 最终文档填写波特率、数据位、校验位和停止位。
6. 点击“连接串口”。
7. 观察状态卡片和右侧日志是否持续更新。
8. 完成测试后点击“停止”，再断开开发板。

如果只看到蓝牙或其他无关串口，不要逐个尝试，应先检查 USB 数据线、开发板是否真正开机、Windows 设备管理器和板载调试器/串口驱动。串口列表因电脑而异，不能据此认定哪个是 FPGA。

### 串口参数填写示例

下面只演示填写形式，不是已经确认的 T025 参数：

```text
串口：COMx（选择开发板实际出现的端口）
波特率：填写 T025 文档确认值
数据位：填写 T025 文档确认值
校验：填写 T025 文档确认值
停止位：填写 T025 文档确认值
```

在 T025 发布参数前，禁止把 `115200 / 8 / N / 1` 当作本项目正式配置。

## CSV 记录方法

1. 点击“选择 CSV 日志”。
2. 选择保存目录和文件名，例如 `fpga_status.csv`。
3. 启动模拟模式或连接真实串口。
4. 每条合法状态都会立即追加到 CSV。
5. 再次点击“停止 CSV 记录”关闭文件。

CSV 表头示例：

```csv
timestamp_utc,active_voice_count,clip_count,event_fifo_level,event_fifo_high_watermark,event_fifo_overflow,audio_underrun,max_processing_cycles
```

数据行示例：

```csv
2026-09-16T08:00:00+00:00,4,0,2,4,0,0,910
```

如果选择已经存在且非空的 CSV，程序会追加数据，不会覆盖原有记录，也不会重复写表头。

## 命令行备用方法

如果暂时不想使用 GUI，可以在仓库根目录打开 PowerShell，运行命令行版。

模拟模式：

```powershell
python -X utf8 .\code\software\uart_status_monitor.py --simulate
```

模拟四条并保存 CSV：

```powershell
python -X utf8 .\code\software\uart_status_monitor.py --simulate --count 4 --interval 0.2 --log fpga_status.csv
```

列出串口：

```powershell
python -X utf8 .\code\software\uart_status_monitor.py --list-ports
```

真实串口命令格式：

```powershell
python -X utf8 .\code\software\uart_status_monitor.py --port COMx --baud <确认值> --bytesize <确认值> --parity <确认值> --stopbits <确认值> --log fpga_status.csv
```

尖括号内容必须替换为 T025 确认值，命令中不要保留 `<` 和 `>`。

## 常见问题

### 双击启动文件没有出现窗口

1. 等待几秒，确认窗口没有被其他窗口遮挡。
2. 确认以下文件存在：

```text
本目录\uart_status_gui.py
本目录\uart_status_monitor.py
上一级目录\scripts\run_t026_gui.ps1
```

3. 在 PowerShell 中使用直接运行命令，以便看到错误信息：

```powershell
.\code\scripts\run_t026_gui.ps1
```

### 提示缺少 pyserial

运行：

```powershell
python -m pip install -r .\code\software\requirements.txt
```

安装后请在同一终端运行 `python -X utf8 .\code\software\uart_status_monitor.py --list-ports` 确认枚举结果。若电脑有多个 Python，可用 `-PythonExe` 指定脚本所用解释器，并通过该解释器的 `-m pip` 安装依赖。

### 串口无法打开

- 检查串口是否被 Gowin Programmer、串口助手或另一个 Python 程序占用。
- 点击“停止”后再重新连接。
- 不要同时用两个程序打开同一个 COM 口。
- 确认选择的是开发板串口，而不是蓝牙串口。

### 一直没有状态数据

- 先确认 T025 已经综合、下载并实际输出 UART 文本。
- 确认 FPGA 每条状态最后发送换行符。
- 确认全部串口参数与 T025 完全一致。
- 先使用“模拟模式”区分是 GUI 问题还是开发板链路问题。

### 出现 PARSE_ERROR 或“数据格式错误”

把右侧日志中的原始状态行与本教程的完整合法示例逐字段比较。重点检查：

- 是否以 `STAT` 开头。
- 七个字段是否全部存在。
- 是否有重复字段或拼写错误。
- 数值是否为 0 至 4294967295 范围内的整数。
- `event_fifo_level` 是否错误地大于 `event_fifo_high_watermark`。
