## 两种实际实现

**C_payload_buffer：一级索引＋payload 缓存。** 在隔离 parser 中寄存 RR 前三名的 valid/rank/index，并在同一个寄存边界缓存各自的 12 位 pending value。用上一拍更新的 index/value 修正缓存，再让当前 MIDI 字节按原优先级覆盖。这样尝试减少仲裁后的 32 选 1 payload 组合链，同时不改变公开 ready/valid、事件、水位与计数的拍号。基于既有提前寄存原型新增 48 个声明状态位，总计 88 位；物理 FF 数以综合/PnR 报告为准，不把声明位数当资源测量。

**D_rotation_pipeline：更深的旋转→优先级树流水。** 在 C 的结构上再增加 32 位旋转位图寄存器，分开 RR 位图旋转和优先级树。为避免额外旧一拍，该寄存器提前计算本拍原 pending/RR 更新后的旋转结果。每拍断言其内容严格等于 `rotate(current_control_pending, current_RR)`，同时保留原 FIFO 与状态更新逻辑。总计 120 个新增声明状态位。它是带当拍前馈修正的内部流水，不是未经授权的公开接口加拍。

C 和 D 各自从成功基线复制 56 个输入／47 个 GPRJ 项，只替换隔离 `sources/midi_event_parser.sv`。没有用 C 生成的失败网表作为 D 输入。此前 failed A/B 工程也没有被改。
