# 给 M2：把138K有效的物理优化思路用于60K

日期：2026-10-05。整理：M3。状态：**待用户转发，尚未送达**。

本文件是方法交接，不是正式补丁，也不代表60K新优化已经执行或通过。主项目仍使用 Tang Mega 60K；138K只是隔离比较实验，不要求换板。

## 1. 先做什么

**对你正在优化的、功能自检已通过的精确60K版本，冻结输入，保留60K已经验证的复位位置，单独对照 `route_option 0` 和 `route_option 1`。**

不要直接把138K坐标抄入60K，也不要把138K新工程整体移植回来。先不改RTL、PLL、引脚、电压、SDC或复位逻辑。
如果当前60K精确版本已经用算法1并有完整报告，先核对报告，不重复这次对照。如果你已有PnR正在运行，不改它的目录或输入；等该版本结束后冻结，或另建不共享可变输入的隔离副本。

## 2. 已经核实的事实

以下60K事实对应用户提供的 **V0171完整四声部音频＋HDMI冻结工程**，不是所有最新未交付工程。

| 项目 | 60K V0171 | 138K C有效实验 |
|---|---|---|
| 器件 | GW5AT-LV60PG484AC1/I0，B | GW5AST-LV138PG484AC1/I0，C |
| 两级串行复位固定位置 | R49C101[1][A/B] | R44C168[1][A/B] |
| place_option | 0 | 0 |
| route_option | 0 | 1 |
| 时序驱动 | 实际cmd.do有 `-timing` | 实际cmd.do有 `-timing` |
| Hold自动修复 | 实际cmd.do有 `-correct_hold 1` | 同左 |
| 时钟 | 50/25/125 MHz | 同左 |
| 系统uncertainty | Setup1.000/Hold0.550 ns | 同左 |

60K已使用“精准固定串行复位FF位置”这一方法，不是从未做过物理优化。待验证的是：**在当前60K布局上换成算法1能否进一步改善**。

官方工具本地 `IDE/data/config/rtlrouteoptions.xml` 的定义：

- 算法0：按拥塞情况选择默认布线算法。
- 算法1：按时序布线。
- 算法2：更偏向提高布线速度，不代表余量更好。
- Hold自动修复会为受影响寄存器插入额外布线路径，也可能影响Setup；本轮保持开启。

因此，`route_option 0` **不等于没有开启时序驱动**；不能把这次实验说成“第一次打开时序优化”。

## 3. 为什么值得试，但不能保证收益

138K C完整工程的真实结果如下，单位ns：

| 配置 | Setup | Hold | Recovery | Removal | Setup/Hold违例端点 |
|---|---:|---:|---:|---:|---|
| 原迁移基线：原位置＋算法0 | -1.356 | -0.348 | -1.411 | -0.152 | 196/2355 |
| 原位置＋布局2/布线1 | -1.405 | -0.404 | -1.419 | -0.148 | 80/2611 |
| 原位置＋布局2/布线2 | -1.405 | -0.404 | -1.435 | -0.148 | 81/2482 |
| 新位置＋布局0/布线0 | -0.179 | -0.352 | -0.090 | -0.163 | 21/2296 |
| 新位置＋布局0/布线1 | +0.025 | 0.000 | +0.873 | +0.008 | 0/0 |

最后一组通过严格离线时序门禁，但余量薄，未达+0.5ns工程目标，未烧录。
这说明**物理位置与布线策略的组合**可能有效；不是算法1在任何设计里都能解决问题，也不能仅凭结果归因到单一位置或选项。

原138K复位到OSER10的最差网延迟4.502ns，调整位置后有所改善。值得迁移的是“从真实报告定位长网、选合法位置、单变量对照并回读”的流程，不是资源坐标。
此外，改变布局也会影响其他逻辑的位置，所以复位位置实验带来的parser Setup改善是全工程物理结果，不能宣称已经改进parser RTL。

## 4. 实验前冻结输入

由你选择当前最新且功能验收通过的60K版本；不要为了套用旧数字而替换成陈旧V0171。

记录完整料号、Device Version、工具版本、顶层名、Git提交及所有未提交覆盖源。冻结并核对：

1. GPRJ里启用的所有源文件和顺序，包括加密DVI IP。
2. include头文件、ROM以及 `$readmemh` 所用真实文件。
3. CST、SDC、PLL/DVI配置及源码、工程user选项和器件配置。
4. 实际PnR `cmd.do` 中的全部非路径选项，而不是只看GUI勾选。

每个输入留路径、大小、SHA-256；A/B除了工程目录重定位和预先声明的一个布线选项，内容应一致。
旧V0171为47项工程输入＋7 ROM＋2头文件，共56个物理文件；**新工程依赖数量可能不同，不可强行按56个验收**。

## 5. 先做一次严格A/B

在你自己的机器新建两个全新隔离工程目录，目录名可用 `60K_A_route0`、`60K_B_route1`。不要覆盖正式工程或旧报告，也不要复制旧impl报告当成新结果。
重定位GPRJ、include、ROM等绝对路径，保证所有会被写入的产物只落到各自隔离目录。不要仅复制GPRJ却继续引用一份可能被修改的RTL/ROM。

- A：冻结60K基线配置，route_option0。
- B：同样配置，只改route_option1。
- 两边相同RTL、CST、SDC、PLL和器件选项，各从源码完整 `run all` 一次。
- 实验前记录采用门槛和单次运行上限；建议每次1800秒，超时保留日志并记“物理未完成”，不得称STA FAIL或PASS。
- 先做这一对，不一上来同时扫位置、布局算法、布线算法或种子；避免无法归因。

### Tcl示例：以V0171已知配置为模板

下列例子假设 `run.tcl` 与已重定位的 `audio_visual_coexistence_top.gprj` 同目录。**不是已在60K算法1上验证过的成品脚本。**
若当前顶层/工程文件名或基线选项不同，应使用实际值，不要为套模板顺手改变其他参数。

```tcl
set experiment_dir [file normalize [file dirname [info script]]]
open_project [file join $experiment_dir audio_visual_coexistence_top.gprj]
set_option -top_module audio_visual_coexistence_top
set_option -verilog_std sysv2017
set_option -place_option 0
set_option -route_option 1
set_option -ireg_in_iob 1
set_option -oreg_in_iob 1
set_option -ioreg_in_iob 1
set_option -correct_hold_violation 1
set_option -clock_route_order 0
set_option -route_maxfan 23
run all
```

A的示例仅将 `set_option -route_option 1` 改为0。
使用你已确认的 `gw_sh.exe` 运行各自Tcl，保存stdout/stderr、实际退出码、开始/结束时间及日志SHA。
运行后必须检查真实 `impl/pnr/cmd.do`：B应有 `-route_option 1`，A应有0；`-timing`、`-correct_hold 1`等其他非路径选项应保持。
不要使用未核实的GUI菜单路径或工具参数，也不要仅看到Tcl写了1就认定工具实际用了1。

### CST保持60K已有位置

V0171的两条是：

```text
INS_LOC "u_visual/u_serial_reset/sync_chain_0_s0" R49C101[1][A];
INS_LOC "u_visual/u_serial_reset/sync_chain_1_s0" R49C101[1][B];
```

首轮A/B保持这些已有约束，**不要改成138K的R44C168**。
如果你当前60K顶层路径或位置已不同，先核对该版本的CST与真实落点，保留其已验配置，而不是强制套旧路径。

## 6. 必须检查的门禁

工具退出码0、生成fs、Fmax看起来更高，都不够。

| 门禁 | 要检查的证据 |
|---|---|
| 完整运行 | 新日志中综合、PnR、STA完成标记；实际退出码；新报告时间与哈希 |
| 约束未偷放宽 | 实际时钟50/25/125MHz；系统Setup1.000/Hold0.550ns；所有冻结命令Active；无额外宽泛false path |
| 全局时序 | 各域及跨域Setup/Hold无负余量；三域TNS0、违例端点0；不能只检查sys_clk |
| 异步复位 | 全部Recovery/Removal非负、最差路径真实存在；OSER10 RESET路径未被切掉 |
| 最短脉宽 | 最短脉宽检查存在且无负余量 |
| CDC | 首级例外范围精确；7组后级14条Setup/Hold均保留；两类载荷报告非空且满足界限 |
| 固定位置 | 两级串行复位FF在详细STA中的实际LOC与CST一致，不能只读约束文本 |
| 引脚与配置 | 球位、Bank、电压、差分配对、PLL与器件选项未意外变化 |
| 功能与资源 | 现有自检通过；无FIFO旁路/同拍计数/事件语义变化；Logic/FF/DSP/BSRAM及资源上限记录完整 |

V0171优化后载荷实际存活23/50条路径。若用新RTL，可能合法变化，应由其来源/综合结果确认预期集合；不要放弃非空与端点身份检查，也不要把23/50冒充完整64/98位覆盖。
PR1014警告需原样登记；不要为了消除它改时钟脚、电压或删时序路径。

## 7. 怎样决定采用

采用标准必须在跑之前写清楚，避免结果出来后只挑一个变好的指标。

- 最低：完整门禁全部通过，无新功能/CDC/引脚问题。一个门禁FAIL就保留基线、不交烧录。
- 如果A已经全通过，B不能因为Fmax高一点就自动采用；应达到你当前任务冻结的收益/余量门槛，并保证其他受控门禁不退化。
- 明确列出Setup、Hold、Recovery、Removal以及各域余量变化和资源变化。发生取舍时由你评估并记录，不由M3替你定案。
- 将“工具零违例”与“工程余量达到目标”分开。若目标是+0.5ns，应检查合同指定的每个指标；Hold报告0.000ns不能算达标。
- 物理优化使位置/布线改变，既有L6不可自动沿用到新fs。后续上板需另外授权、绑定版本和哈希。
- 本轮不直接烧录，不替换当前可演示60K码流。

## 8. 若算法1仍无收益

先回到报告，不无限扫参数。

1. 找真实最差路径，拆分时钟偏斜、逻辑延迟、网延迟和扇出；分别处理Setup、Hold、Recovery/Removal，不能只盯最长组合链。
2. 只有复位仍是具体阻塞时，再提一个独立的60K位置实验：根据**该60K真实报告**中合法资源、目的端OSER10位置和时钟延迟选择候选，保留两级逻辑及同样SDC，一次只改两条INS_LOC并回读实际位置。
3. 若瓶颈是parser/ROM短路径或音频控制结构，按岗位授权进入独立RTL候选和逐拍等价/功能自检，之后同版PnR；不取消公共FIFO满队列旁路，不把计数或控制事件未经合同延后一拍。
4. 不自动混入已经拒收的提前寄存/onehot候选；不把位置试验变成跨模块正式改动。

正式应用若触及受控约束或共享文件，按仓库的群内范围通知、变更和复核规则执行。本文不扩大跨岗位写入授权。
