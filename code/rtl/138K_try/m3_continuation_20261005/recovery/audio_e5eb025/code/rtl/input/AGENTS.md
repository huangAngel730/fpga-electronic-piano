# 交互与板级岗位规则

负责人：M3 实体硬件、交互与上板验证负责人。岗位定义见 `code/docs/角色分工.md`。

## 主责范围

- 琴键、压力、编码器、光电、距离或 MIDI 输入候选实验。
- GPIO、SPI、I2C、UART 从设备侧驱动、去抖、滤波和事件生成。
- NEO Dock 原理图、供电、电平、接线与实物核验。
- DAC、功放、音频输出链路和机械结构。
- 逻辑分析仪、示波器和音频采集卡的测量与数据采集自动化。

## 写入范围

- `code/rtl/input/`
- `code/software/`
- `code/scripts/`（串口、仪器、采集）
- `code/docs/hardware/`
- `code/docs/pinout/`
- 对应的 `code/tb/` 文件

## 与 M2 的边界

- `code/constraints/`、`code/rtl/board/`、`code/rtl/common/` 和顶层模块归 M2 负责；M3 提供引脚、电平、供电和实物接线依据，并复核约束与接线表一致。
- UART 状态通道的协议和顶层实现由 M2 负责，M3 负责上位机解析和采集脚本。

## 约束

- 输出必须符合统一演奏事件接口。
- 任何 5 V 信号接入前必须确认电平转换。
- 改接线必须同步通知 M2 修改 CST 并更新引脚文档。
- 连续传感器数据必须给出更新率、抖动和延迟实测。
- 未经确认不占用 HDMI、音频或其他复用引脚。
- 上位机与仪器软件只用于测量和自动化，不得替代 FPGA 生成正式音频。
