# 抉择与并行开发顺序

## 第一批 立即抉择

这些项目决定团队能否并行：

1. 统一演奏事件字段和握手方式。
2. 第一版音频数据格式：48 kHz目标、32位相位、16位波表、24位PCM、32位混音累加。
3. 时钟、复位和 `sample_tick` 使用方式。
4. 音频核心与I2S输出的边界。
5. Git分支、任务编号和验证记录格式（已定，登记格式见 `code/docs/验证记录.md`）。

## 第二批 板卡到手后一周抉择

> 状态（2026-09-12 更新）：第 1、2、3、5 项已决，见各条后的指向；第 4 项仍未决。
> 本清单保留原始措辞作为历史记录，**当前有效结论以指向的文档为准**。

1. 板载音频或PCM5102A作为正式输出。
   → **已决：以板载 PT8211 为正式输出**（16 位 LSBJ DAC，无需 MCLK），见 D017。
   代价是 PCM5102A 属标准 I2S 器件，与 PT8211 的 LSBJ 格式不兼容，
   若后续改用 PCM5102A 需重新走接口变更流程。
2. I2S数据位宽、槽位宽度、声道极性及是否需要MCLK。
   → **已决**：每声道 32 位槽位、24 位 PCM 有效、24→16 位舍入饱和后在发送器内完成、
   LSBJ 右对齐、LRCLK 低电平为左声道、不需要 MCLK。见 `模块接口规范.md` v1.1 第五节。
3. 实际系统时钟和PLL配置。
   → **已决（但尚未立决策记录条目）**：50 MHz 直接使用，**不启用 PLL**
   （最佳 rPLL 配置 IDIV=59/FBDIV=116 → 98.305085 MHz，误差 +11.03 ppm，
   反而比 50 MHz 直接相位累加的 +0.096 ppm 更差）。
   依据与算式见 `constraints/audio_timing.sdc` 第一节与
   `scripts/analyze_clock_50m.py`；验证结果见 `验证记录.md` V0018。
   **待办**：该结论目前只散落在约束与脚本注释中，应补一条正式决策记录。
4. 4条或8条声部处理流水线的初步架构。**（仍未决）**
5. NEO Dock可用引脚和调试测试点。
   → **已决**：`sys_clk` = V22 / LVCMOS33，`sys_rst_n` = AA13 / LVCMOS15；
   板载 MIDI RX 引脚 `V14` 电平标准与 Bank 冲突，**禁止采用**，替代路径未定，
   见 `当前状态.md` 阻塞事项。

## 第三批 音频核心稳定后抉择

1. 是否制作PCB和最终机械结构。

## 三条并行工作线

### 工作线A 音频RTL

```text
采样节拍 -> DDS -> 波表 -> ADSR -> 单声部 -> 4复音 -> 32声部 -> 多音色 -> 效果器
```

### 工作线B 交互板级

```text
原理图和引脚 -> LED UART -> I2S实测 -> 临时按键 -> ADC传感器原型 -> 正式交互对比
```

### 工作线C 软件验证

```text
Python DDS -> 波表生成 -> ADSR模型 -> RTL回归 -> 构建脚本 -> 串口解析 -> WAV和FFT分析
```
