# AI 交接上下文

更新时间：2026-09-11。对应决策：D008 三人岗位冻结、D011 AI 交接与协作设施。

本文件用于把当前项目上下文完整交接给一个新的 AI 会话，避免把聊天记录当作事实来源。队员换电脑、换 AI 工具或任务跨周续接时，按本文件操作。

## 一 使用方式

1. 队员确认自己的岗位是 M1、M2 还是 M3。
2. 在任务看板确定任务编号和授权目录。
3. 把第二节的提示词连同岗位、任务号、授权目录一起发给 AI。
4. AI 读完必读文件后，先复述任务边界和验收条件，再开始改动。
5. 任务完成后按第六节格式汇报。

## 三 当前已冻结事实

- 赛题：高云选题二 基于 FPGA 的实时多音色合成电子乐器引擎。
- 平台：Sipeed Tang Mega 60K 加 NEO Dock，FPGA 为 `GW5AT-LV60PG484AC1/I0`。
- 正式音频样本必须由 FPGA 逐采样生成，上位机和树莓派只做测量与自动化。
- 模块化架构，音频输出使用 I2S，第一版为 DDS 加单周期波表加独立 ADSR。
- 交互硬件统一转换为演奏事件，音频核心不依赖具体传感器。
- 内部 PCM 暂定有符号 24 位，混音累加暂定 32 位或更宽，波表样本暂定 16 位。
- 目标采样率 48 kHz，待板载音频链路实测确认。
- `performance_event_t` 已冻结为 64 位，事件 FIFO 深度 32，采用 valid ready 反压；连续控制入 FIFO 前限速和合并。
- I2S 已冻结为每声道 32 位槽位、24→16 位有效 PCM、**LSBJ 右对齐（v1.1，D017）**，格式实现归 M2。
- 复位低有效、异步拉低同步释放；`sample_tick` 是 48 kHz 单周期计算请求，由 M2 在顶层产生。
- 阶段目标为单声部和 4 复音，正式规模为 32 个独立活跃振荡器。
- 三人岗位 M1、M2、M3 及其所有权见 `角色分工.md`。

未冻结事项见 `项目事实与范围.md`，不要在方案里把它们写成已确定。

## 四 岗位授权目录

| 岗位 | 授权目录 |
|---|---|
| M1 | `code/rtl/audio/`、`synth/`、`voice/`、`mixer/`、`effects/`、`code/model/`、`code/docs/test/` |
| M2 | 顶层模块、`code/rtl/board/`、`code/rtl/common/`、`code/rtl/audio_out/`、`code/constraints/`、`code/sim/` |
| M3 | `code/rtl/input/`、`code/software/`、`code/scripts/`、`code/docs/hardware/`、`code/docs/pinout/` |

`code/docs/` 下的协作文件由任务单指定负责人，至少一名非作者复核。共享目录修改必须经过复核。

## 五 禁止事项

- 直接把 5 V 信号接到 3.3 V FPGA GPIO。
- 用预录音符、歌曲或 PCM 片段冒充实时合成。
- 修改公共接口、位宽、采样率或引脚而不提案。
- 把仿真通过、综合通过写成上板通过。
- 把未通过测试的码流标记为稳定版。
- 提交 `.tools/`、安装包、波形、码流和厂商缓存目录。
- 未经授权扩大写入范围，或同时重写队友正在修改的公共文件。
