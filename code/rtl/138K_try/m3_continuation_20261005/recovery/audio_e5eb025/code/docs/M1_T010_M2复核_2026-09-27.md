## 复现方法和验证等级

在仓库根目录运行：

```powershell
.\code\scripts\run_t010_allocator_review.ps1
```

脚本先加载本机 FPGA 工具环境，复制原始 M1 RTL 到 Git 忽略的 `code/output/t010_allocator_review/`，使用 Yosys `read_slang`、`proc`、`opt`、`techmap` 转换结构体数组为通用 Verilog，再用 Icarus/VVP 对端口测试台分别运行六种场景。输出 `summary.json`、逐场景日志和源文件 SHA-256；任一场景失败即非零退出。转换是为了绕开本机 Icarus 对原始结构体数组访问的内部断言；**不是 Gowin 网表仿真或时序验证**。单独对原始源码运行 Verilator lint 与 Gowin 单模块综合均退出 0；Gowin 有一处“4 位表达式截成 3 位”的年龄计数警告。该静态/综合结果不改变失败的功能结论。

验证等级：**L2 层级的独立功能反例仿真**（端口刺激经过语义转换的网表；3 项未通过）。未做完整参考模型逐事件 L3、正式顶层 PnR 或实物。不能把 PASS 的3项写作整个 T010 仿真通过。

## 精确场景与结果

| 场景 | 端口激励与预期 | 实测 |
|---|---|---|
| baseline | 4音依序填满0～3；重触发槽1；第5音按最旧槽抢占0；复位后首音回槽0 | PASS |
| identity | 不同 source/channel 的同音分别占不同槽；只关闭匹配身份；未匹配 Note Off 不产生目标；活动中的同身份重触发原槽 | PASS |
| single_release | 单槽 Note Off 后 `release_done=1`，该槽可重新分配 | PASS |
| release_retrigger | 槽0的 `(source=0,channel=0,note=60)` 进入 Release 后同身份再按，按“Release中的音仍占槽”应复用0 | **FAIL：分配槽1**。查找仅检 `note_active`，Release 时被清0；有空闲槽就新分配，原槽尾音仍在运行。 |
| release_isolation | 四槽中槽1、槽3先后进入 Release，仅槽1结束；新音先占1，下一个应从仍占用的槽里按既定抢占规则处理 | **FAIL：下一个占槽3**。唯一的 `release_done` 使所有 `in_release` 槽同时清除，无法标识只完成的槽1，提前截掉槽3尾音。 |
| age_wrap | 初始四次分配后，连续五次同身份刷新槽0；计数从7到0后槽0最新，下一新音应抢真正最旧的槽1 | **FAIL：抢槽0**。3位 `global_age` 回绕后直接取最小 `age`，把刚更新的槽0误认作最旧。 |

这些失配由 M1 模块的外部 `allocated_slot`/`release_slot` 可观察，不依赖读取内部寄存器。总入口实际打印三项 FAIL 并退出 1，避免“显示失败但 shell 返回成功”。

## 请 M1 确认并修复的接口问题

1. `release_done` 当前只有一位，无法表达哪个槽的包络 Release 结束；若采用每声部独立完成标志，需明确编码/采样沿、与 Note On 同拍的优先级和最多同时完成数。该接口属于 M1 音频声部布局，**M2 不自行更改模块端口或决定偷声策略**。
2. 同身份再次 Note On 在 Release 中应重触发原槽还是新分配？现行接口规范 3.4 写“已有声部重触发原槽”，请由 M1 与正式包络生命周期统一，避免尾音重复或悬空。若有意另选语义，先走受控变更。
3. 3位按分配事件计数的年龄不足以直接做跨回绕最小值比较；需定义稳定的 LRU 顺序和满载、Release 槽优先级，并覆盖多次回绕与同时事件。
4. 当前旧 `run_t010_voice_sim.ps1` 未加载项目工具环境、TB 使用 `$finish(1)` 不能保证失败退出非零；M1 修 RTL 时需同时更新正式模块自检。此 M2 新检查器只是复核入口，不能替代 M1 的最终黄金参考。
