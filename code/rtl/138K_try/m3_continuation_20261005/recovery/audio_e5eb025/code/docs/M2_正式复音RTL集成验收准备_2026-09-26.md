# M2 正式复音 RTL 集成验收准备（2026-09-26）

范围：T004／T009／T010／T023 由 M1 提交正式算法 RTL 和黄金模型，M2 执行顶层接线、接口复核、逐帧联调、综合与时序资源复核（T024）。本表是验收准备，不新增或修改冻结接口。当前 **正式四声部 RTL 尚未交付，本表各 RTL 门禁尚未通过**。

## 当前可执行的证据预检

从仓库根目录运行：

```powershell
python -m unittest discover -s code/tb/board -p test_check_polyphony_vectors.py -v
python code/tb/board/check_polyphony_vectors.py
```

第一条是 M2 检查器自检，覆盖成功、缺第四声部、四声部全静音、PCM 十六进制不一致、帧号跳跃、削波标志错误六种情况。第二条读取 M1 当前的 `code/model/generated/polyphony_test/polyphony_4voice.txt`；截至本表创建时 **应退出 1**：该文件虽然有四列声部活动标志，最多只有三声部同时激活，不能作为四声部通过证据。检查器核对连续帧号、24 位有符号 PCM 的十进制/补码一致性、活动与削波标志、四声部同时激活且有非零混音输出；**这些标志和非零混音不能单独证明四个独立音高实际发声**。正式证明还需要事件日志、四路声部逐帧数据及 RTL 对照。

## M1 提交后 M2 的接线前核对

| 核对项 | 接受条件 | 证据 |
|---|---|---|
| 输入身份 | `performance_event_t` 64 位；`(source_id,channel,note_number)` 为音符身份；同身份重触发原槽，不同来源/通道的同音符互不误关 | M1 事件测试向量 + RTL 自检 |
| 声部生命周期 | Note Off 进入 Release，未归零前继续参与混音；Release 期间同身份重触发、满四声部时按 M1 已定义的抢占规则运行；复位清零 | 状态／逐帧声部数据与断言 |
| 输入握手 | `event_valid && event_ready` 同拍接收，反压期间事件保持；不从公共 FIFO 越界取数；32 深度 FIFO 已由 M2 顶层实现 | 接口仿真／事件计数 |
| 采样请求 | 唯一节拍是 I2S 完整帧 `sample_req`；每接受一次请求 DDS/ADSR 各推进一次；提交 `pcm_valid && pcm_ready` 不使其再次推进 | 请求、代次和相位／包络逐帧对照 |
| 双声道 PCM | 有符号 24 位左右声道随同一请求代次提交；至少一组结果缓存；第 N 帧请求于 N+1 边界前交付；迟到结果作废 | `pcm_frame_buffer` 链路 TB 与 RTL 数据 |
| 混音和幅度 | 单声部峰值口径 2,097,152；至少有符号 32 位累加，中间位宽、舍入可说明；最终对 24 位上下限饱和而不回绕；削波标志／计数与实际一致 | 满幅、正负溢出与不削波向量逐样本对照 |
| 复位与欠载 | 复位后首次有效样本前左右 0；欠载每个音频帧重复上一组左右样本且计数只加一；晚到结果不能污染下一帧 | 当前 T055 链路 TB + 正式声部连接后的回归 |

上述口径引用 `code/docs/模块接口规范.md` v1.3 与 `code/docs/音频逐帧契约_2026-09-24.md`。M1 实际模块端口、流水线时延、声部抢占策略、饱和标志接口在正式交付后核对，**不能凭现有 Python 模型或单声部占位 RTL 猜测端口并编写正式顶层连接**。若交付口径与冻结接口冲突，先给出影响分析和用户裁决，再修改受控文件。

## 到件后的验证顺序与放行标准

1. M2 复核 M1 的提交范围、独立单模块自检及黄金向量：真正四声部同时活动且各有非零逐路样本；验证不同音高、不同力度、同音重触发、跨通道同音、松键 Release 和异常抢占。预检脚本通过只是输入证据门槛。
2. 获得 M1 的模块端口和逐帧数据格式后，在 M2 范围的 `code/tb/board/` 添加整链自检：从公共事件到请求、声部、混音、PCM 缓冲和 I2S，逐帧和黄金模型比较，并注入反压、复位、跨帧迟到和连续欠载；重新运行 T005／T007／T019／T055 相关回归。
3. 集成必须变更 `code/rtl/board/electronic_piano_top.sv` 或 `code/rtl/common/audio_defs_pkg.sv` 时，先按 D026／D027 在群里说明接口影响；再小范围接线，不改 M1 的音色数学定义。`clip_count` 接真实饱和事件后，T025 才能从阶段 `DIAG` 切到正式 `STAT`。
4. 跑 Gowin 综合、布局布线和 50 MHz Setup/Hold 时序，记录目标器件、工具版本、Fmax、WNS/TNS、最坏路径起终点与 LUT/FF/DSP/BSRAM；用正式四声部实测更新 T016/T024，不能沿用旧单声部 Fmax 或占位外推。时序收敛且资源满足实测预算后才生成稳定码流。
5. 上板需记录四键并按、不同力度、松键尾音与无爆音、长运行欠载增量和真实 UART `STAT`／音频证据；软件仿真和占位码流不能替代该级验收。

当前等级：M2 检查器 **L1 自检通过**；现有 M1 四声部文件 **未通过覆盖门槛**；正式四声部 RTL 的逐样本仿真、综合、时序、上板均待做。
