# 新队员上手指南

更新时间：2026-09-16（按 D025 改为直推 `develop`，不再建功能分支）。面向第一次使用 Git 的队员，从一台空电脑做到能提交代码。阅读顺序见 `code/docs/协作入口.md`，本节只讲怎么把环境接上。

## 一 先用一句话理解这套协作

三个人共用一个 GitHub 仓库。`main` 是稳定版，`develop` 是集成版。**2026-09-16 起不建功能分支、不开 PR**：三个人都直接往 `develop` 推，推之前跑一遍 `.\code\scripts\check_repo.ps1`，推之后由 M2 复核（M2 自己的改动标「自审」）。`main` 只在阶段同步点由 M2 从 `develop` 合并并打标签。

没有"把文件夹发给队友"这一步。那个做法已经作废，见第八节。

## 三 先让管理员把你加进仓库

这一步必须在 clone 之前完成，否则你推不上去。

1. 让仓库管理员在 GitHub 的 `Settings → Collaborators` 里添加你的 GitHub 账号。
2. 你的账号会收到邀请邮件，也可能在网页右上角出现提示。必须点 Accept invitation，只被添加不接受是没有权限的。
3. 确认方式：网页能打开仓库并看到分支列表。

## 四 把自己的电脑接到仓库

### 4.1 设置提交身份

```powershell
git config --global user.name "你的名字或GitHub昵称"
git config --global user.email "你的GitHub邮箱"
```

这决定每个提交上写谁的名字，第一次用一定要做。

### 4.2 配置 SSH 密钥

远程仓库用的是 SSH 地址，需要先在 GitHub 登记你的公钥。

```powershell
ssh-keygen -t ed25519 -C "你的GitHub邮箱"
```

一路回车，默认保存到 `C:\Users\你的用户名\.ssh\id_ed25519`。私钥不要发给任何人，只把公钥贴到 GitHub：

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

复制输出的整行，打开 GitHub 右上角头像 → `Settings` → `SSH and GPG keys` → `New SSH key`，标题随便填（例如"实验室台式机"），内容粘贴公钥，保存。

验证：

```powershell
ssh -T git@github.com
```

看到 `Hi 你的用户名! You've successfully authenticated` 就成功了。第一次连接会问是否信任主机，输入 `yes`。

### 4.3 克隆仓库

**克隆到纯 ASCII 路径。** 路径里有中文会让 Gowin 的 Tcl 命令行无法打开工程，
详见 `code/docs/开发环境.md`。例如：

```powershell
cd D:\17\project_17
git clone git@github.com:huangAngel730/fpga-electronic-piano.git fpga_gowin
cd fpga_gowin
```

不要用网页上的 Download ZIP。ZIP 里没有 Git 历史，在里面改的代码没有提交记录、推不上去，等于白做。

如果 SSH 实在配不通，可以暂时改用 HTTPS 地址 `https://github.com/huangAngel730/fpga-electronic-piano.git`，推送时输入用户名和 Personal Access Token，注意不是账号密码。

### 4.4 认识远端的分支

```powershell
git branch -a
```

`main` 是稳定版，不要直接提交。**你只需要 `develop` 一条分支**——2026-09-16 起所有开发
都在 `develop` 上直接进行（D025）。

远端可能还能看到 `feature/input`、`feature/model-dds`、`feature/board`、`feature/i2s`、
`docs/interface` 等旧分支。**它们全部是历史遗留，只读：不要在上面工作、不要 rebase、
不要删除。** 里面的成果该迁的都已经迁进 `develop` 了，逐条状态见
`code/docs/Git协作规范.md`「历史分支」小节。

## 六 切到 develop，不要建分支

**2026-09-16 起不再建功能分支**（决策 D025）。开工只要三步：

```powershell
git switch develop
git fetch origin
git pull --rebase origin develop
```

原来的命名规则 `feature/<名字>`、`fix/<名字>`、`docs/<名字>` **已作废**，不要再建这类分支。
如果你之前已经建过，把它留成只读存档即可：**不要 rebase，也不要删**——`b0d6479`、
`eb82185` 等提交已经把你分支上的成果迁进 `develop` 了。详见 `code/docs/Git协作规范.md`
的「历史分支」与「为什么取消按人分支」两节。

## 七 每次开工的固定动作

1. 拉最新：`git switch develop`，然后 `git pull --rebase origin develop`
2. 读规范：按 `code/docs/协作入口.md` 的必读四份过一遍
3. 领任务：在 `code/docs/任务看板.md` 找到自己那一行，确认任务编号、复核人和验收条件
4. 只改授权目录。需要跨目录先停下来找队友
5. 小步提交：

```powershell
git add 具体文件路径
git commit -m "feat(dds): add 32-bit phase accumulator"
```

提交信息格式是 `类型(范围): 摘要`，类型用 `feat`、`fix`、`test`、`docs`、`build`、`refactor`、`chore`。不要写"update"、"改了一下"这类看不出内容的摘要。

6. 推送前先自检：

```powershell
.\code\scripts\check_repo.ps1
```

**必须全部 PASS（当前 8 项）才能推送。** 有一项 FAIL 就先修，不要带着失败推送。

7. 推送：

```powershell
git push origin develop
```

被拒（`fetch first`）说明队友推过新提交，先 `git fetch origin`、
`git pull --rebase origin develop`，然后重新推。**任何时候都不要用 `--force`。**

8. 通知 M2 复核。M2 自己主责的任务标「自审」。复核通过不强制留痕，M2 发现问题才会提出来。

## 九 常见故障

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `Permission denied (publickey)` | SSH 公钥没登记 | 回到 4.2 重配 |
| `remote: Permission to ... denied` 或 403 | 没被加为协作者，或没点 Accept | 找管理员确认，并检查邀请邮件 |
| `Updates were rejected because the remote contains work` | 队友推过新提交，本地落后 | 先 `git pull`，处理提示后重新推送，不要用 `--force` |
| `Your local changes would be overwritten by checkout` | 有未提交的改动 | 先 `git add` 加 `git commit`，再切换 |
| `fatal: not a git repository` | 当前目录不对 | `cd` 回仓库根目录 |
| `LF will be replaced by CRLF` | 仓库早期未统一换行符时的提示 | 仓库已加 `.gitattributes` 固定为 LF，正常不再出现；若仍出现，执行 `git add --renormalize .` 后提交 |
| 终端里中文显示成乱码 | 终端编码问题 | 文件内容本身是好的，用编辑器打开确认，不要因此重写文件 |
| `git push` 要求输入密码 | 用的是 HTTPS 地址 | 改用 SSH，或用 Personal Access Token 而不是账号密码 |

## 十 绝对不能做

- 不要 `git push --force`，会覆盖队友的提交。要回退用 `git revert` 产生新提交。
- 不要往 `main` 直接推，`main` 只由 M2 在阶段同步点从 `develop` 合并并打标签。
- 不要提交 `.tools/`、安装包、波形（`.vcd`、`.vvp`、`*.out`）、码流（`.fs`、`.bit`）和厂商缓存。
- 不要改公共接口、时钟、复位、数据位宽、采样率、顶层端口和引脚。确有必要先提交影响分析。
- 不要把仿真通过写成上板通过。
- 不要两个人同时改同一个文件，开工前在群里说一声你要改哪几个。**接口组的四个共享
  文件**（`electronic_piano_top.sv`、`audio_defs_pkg.sv`、`electronic_piano.cst`、
  `模块接口规范.md`）**尤其要先说**；**编号表组**（`验证记录.md`、
  `技术决策记录.md`、`任务看板.md`、`当前状态.md`）**不用提前说**，
  但必须按下一条取号（D027）。
- 不要在开工时就把 `V00xx`／`D0xx`／`T0xx` 编号写死。编号只在**推送前最后一步**
  `git fetch` 之后、看表末尾时才取（D026）。
- 不要建功能分支。旧分支只读：不要往上面推、不要删、不要 rebase。
- 推送被拒就 `git pull --rebase` 后重推，绝不用 `--force`。
