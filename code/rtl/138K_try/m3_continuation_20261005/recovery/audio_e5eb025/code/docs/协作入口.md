## 阅读顺序

文档按主题的完整索引见 `code/docs/README.md`。本文件只规定开工时的最小阅读集。

### 一 每次开工必读

下面四份按顺序读完再动手，不要跳读。这四份决定你能不能开工、能改哪些文件：

1. 根目录 `AGENTS.md`
2. `code/AGENTS.md`
3. 与本人岗位对应的局部 `AGENTS.md`。M1 见 `code/rtl/audio/AGENTS.md`，M2 见 `code/rtl/AGENTS.md`，M3 见 `code/rtl/input/AGENTS.md`
4. `code/docs/任务看板.md`，用于确定自己的任务编号、复核人和授权目录
5. 当前启动阶段额外阅读 `code/docs/三人开工任务说明.md`

读完先用一句话向任务发起人复述：我的岗位、我的任务编号、本次授权目录、验收条件。复述不通过先不要改代码。

## 三个岗位

| 岗位 | 定位 | 所有权核心 | 专业把关对象（复核统一归 M2） |
|---|---|---|---|
| M1 | 音频算法、验证与竞赛交付负责人 | 算法定义、黄金模型、算法 RTL 行为、逐样本验证 | M2 的 I2S 数据相位与位宽实现 |
| M2 | FPGA 技术与系统集成负责人 | 时钟、CDC、接口、顶层、约束、构建与时序收敛 | M1 的流水线与资源实现，M3 的引脚约束一致性 |
| M3 | 实体硬件、交互与上板验证负责人 | 供电、电平、接线、传感器、仪器实测 | M2 的约束与实物接线一致性，M1 的上板实证 |

岗位所有权、决策权和一票否决的完整定义见 `code/docs/角色分工.md`。日常流程见 `code/docs/三人协作执行手册.md`。

**复核（D025，2026-09-16）**：**统一归 M2**。M1、M3 推送后由 M2 复核该次推送的 diff，
一般没问题即通过，**不强制留痕**；M2 自己主责的改动标记「自审」。三人一律直接推
`develop`，不再有功能分支与合并请求。推送前五条检查见 `code/docs/Git协作规范.md`
「推送前检查清单」（D025 §3.3 + D026 + D027）：① `check_repo.ps1` 全 PASS；
② 先 `git fetch`、编号从现表末尾取；③ **改「接口组」共享文件前先在群里说一句**
（`electronic_piano_top.sv`／`audio_defs_pkg.sv`／`electronic_piano.cst`／`模块接口规范.md`；
「编号表组」`验证记录.md`／`技术决策记录.md`／`任务看板.md`／`当前状态.md`
**不需要提前说明**，只按第 ④ 条取号）；
④ **编号只在推送前最后一步取**：开工不写、干活不写，`git fetch` 后看表末尾才写，
做成一个只含编号的独立小提交就立刻推；⑤ 禁止 `git push --force`。

## AI 开工提示词

每位队员可将下面内容发给自己的 AI。按岗位定制的版本见 `code/docs/AI开工提示词.md`；交接模板和汇报格式见 `code/docs/AI交接上下文.md`。

```text
先完整阅读根目录 AGENTS.md、code/AGENTS.md 和code/docs/协作入口.md 中列出的全部必读文件，再阅读本岗位目录中的 AGENTS.md。
只执行任务看板中分配给我的任务，只修改授权目录。
如果需要修改公共接口、时钟、复位、数据位宽、采样率、顶层端口或引脚，先停止并提交影响分析，不要直接修改。
完成后运行规定测试，推送前运行 `.\code\scripts\check_repo.ps1` 并确认全 PASS，更新当前状态与任务看板，并把验证等级登记到 `code/docs/验证记录.md`。三人一律直接推 develop，不新建分支（D025）。
```

## 共享资源

板卡、逻辑分析仪和其他仪器均为实验室共享资源，**不编号、不登记、不设配额**（D023／D024，2026-09-16）。原 `板卡与仪器资源管理.md` 与 `资源使用记录.md` 已删除，全部使用注意合并到 `code/docs/板级硬件事实.md` §三补2。

- **不编号**（D023）：两块开发板和两台分析仪同型号、可互换，原 BD-01／BD-02／LA-01／LA-02 编号已作废。
- **不登记、不设配额**（D024）：设备数量与可用性已确认，不再要求状态登记，原每周 40 小时配额一并撤销。
- 判断某块板能否用于正式验收，看它的**当下状态**（当前码流版本 + 板上有没有临时接线），**不看它是哪一块**。
