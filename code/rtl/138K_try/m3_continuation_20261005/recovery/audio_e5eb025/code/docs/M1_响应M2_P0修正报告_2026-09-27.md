## 二、ADSR修正（P0问题4）

### 2.1 Velocity缩放的Decay目标

**M2指出问题**：
> Decay 目标固定13107，没有按当前 velocity 增益缩放，不匹配 Python。

**修正**：
```systemverilog
// 在ROM输出稳定后计算Decay目标
if (sample_counter == 16'hFFFF) begin
    target_gain <= rom_dout;
    level <= start_level;
    // Decay目标 = velocity_gain * 0.4
    decay_target <= {rom_dout, 16'h0} * SUSTAIN_LEVEL_Q15 / 32768;
    state <= ATTACK;
    sample_counter <= 16'h0;
end
```

**结果**：
- Decay目标按照velocity动态计算
- Python模型：`sustain_level = 0.4 * velocity_gain`
- RTL实现：`decay_target = (rom_dout << 16) * 13107 / 32768`
- 数学等价：`13107 / 32768 ≈ 0.4`

### 2.2 ROM有效时序

**M2指出问题**：
> rom_addr 与同步 rom_dout 分别使用非阻塞赋值，下一拍消费仍可能读旧地址结果，须有显式 ROM 有效等待。

**修正**：
```systemverilog
// Note On时标记等待ROM
if (note_on) begin
    rom_addr <= velocity;
    start_level <= (state == RELEASE) ? level : 32'h0;
    sample_counter <= 16'hFFFF;  // 标记等待ROM
end

// 采样时钟：检查ROM有效标志
else if (sample_tick) begin
    if (sample_counter == 16'hFFFF) begin
        // ROM输出已稳定，进入ATTACK
        target_gain <= rom_dout;
        // ...
    end else begin
        // 正常状态机执行
        case (state)
            // ...
    end
end
```

**时序保证**：
- 第1拍：Note On触发，rom_addr更新，sample_counter=0xFFFF
- 第2拍：ROM同步读取，rom_dout稳定
- 第3拍（首个sample_tick）：检测到0xFFFF标志，消费rom_dout，进入ATTACK

### 2.3 语法修正

**问题**：代码中有重复的`else begin`导致语法错误
**修正**：删除重复行

## 三、声部分配器修正（P0问题5、6）

### 3.1 公共身份定义

**M2指出问题**：
> 公共身份是 source_id + channel + note_number，不能把4位来源与通道混为一个字段。

**修正**：
```systemverilog
module voice_allocator_4 (
    input  logic [3:0] source_id,      // 来源ID
    input  logic [3:0] channel_id,     // 通道ID（新增）
    input  logic [7:0] midi_note,
    // ...
);

typedef struct packed {
    logic [3:0] source;
    logic [3:0] channel;  // 新增
    logic [7:0] note;
    // ...
} voice_slot_t;

// 匹配时比较三项
if (slots[i].source == source_id &&
    slots[i].channel == channel_id &&
    slots[i].note == midi_note) begin
    // 同身份重触发
end
```

**结果**：公共身份现为 `(source_id, channel_id, midi_note)` 三元组

### 3.2 Release生命周期

**M2指出问题**：
> Note Off 仍立即 active=0，下一 Note On 可立刻复用槽；保留 note/source 数据本身不等于保留 Release 生命周期。

**修正**：
```systemverilog
typedef struct packed {
    logic       note_active;   // Note On活跃
    logic       in_release;    // Release阶段（新增）
    // ...
} voice_slot_t;

// Note Off：进入Release，不清除槽位
if (note_off) begin
    slots[i].note_active <= 1'b0;
    slots[i].in_release <= 1'b1;      // 标记Release中
    release_slot <= i[1:0];           // 输出槽位号
    release_target_valid <= 1'b1;
end

// Release完成：由外部ADSR反馈
if (release_done) begin
    slots[i].in_release <= 1'b0;  // 清除Release标志
end

// IDLE判断：既不活跃也不在Release
if (!slots[i].note_active && !slots[i].in_release) begin
    // 可分配
end
```

**新增接口**：
- `input logic release_done` - Release完成信号
- `output logic [1:0] release_slot` - Release目标槽位
- `output logic release_target_valid` - Release目标有效

**生命周期**：
1. Note On → `note_active=1, in_release=0`
2. Note Off → `note_active=0, in_release=1`（保持槽位）
3. Release完成 → `in_release=0`（可复用）

### 3.3 LRU策略修正

**M2指出问题**：
> 16位 timestamp 每50MHz增长，回绕周期约1.31072ms；有符号差值比较仅在跨度小于半量程等限定条件下可靠，实际演奏无此限制。

**修正**：
```systemverilog
typedef struct packed {
    logic [2:0] age;  // 0-7年龄计数器
    // ...
} voice_slot_t;

logic [2:0] global_age;  // 全局年龄

// 分配时更新年龄
slots[target_slot].age <= global_age;
global_age <= global_age + 1;  // 自然回绕0-7

// LRU窃取：选最小age
logic [2:0] oldest_age;
oldest_age = slots[0].age;
target_slot = 2'h0;

for (i = 1; i < 4; i = i + 1) begin
    if (slots[i].age < oldest_age) begin
        oldest_age = slots[i].age;
        target_slot = i[1:0];
    end
end
```

**优势**：
- 3位计数器0-7循环，避免时间戳回绕问题
- 最多4个槽位，年龄差最多3，远小于8的回绕周期
- 无符号比较即可正确判断相对新旧
