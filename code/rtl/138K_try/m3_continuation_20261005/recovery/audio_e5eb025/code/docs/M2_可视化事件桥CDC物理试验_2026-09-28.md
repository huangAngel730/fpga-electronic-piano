## 实验目的及边界

`code/rtl/board/visual_cdc_probe.sv` 为**不可上板**的独立合成顶层：50 MHz 系统域，PLLA 输出 25 MHz 显示时钟；64 位 `stimulus_data` 为完全独立的外部合成输入，测试电路以动态串行选择将捕获的所有 payload 位传至输出，阻止综合静态折叠。64 个外部输入没有按板级物理接口约束，构建产物 `.fs` 不准下载。只为使 `payload_hold → video_data` 的 64 条路径全部出现在时序报告。它没有 M3 渲染器、真实 MIDI/音频、score/mode CDC 或 DVI TMDS。保留 `PR1014` 时钟普通布线警告，实屏锁定/抖动未验证。

约束 `code/constraints/visual_cdc_probe.sdc` 单独定义 50/125/25 MHz 时钟；只对 ACK/REQ/desync 三个异步同步器**首级 D 端**设置例外，后级 `ack_meta→ack_sync`、`req_meta→req_sync`、`desync_meta→video_desync` 的 Setup/Hold 六条路径以 `report_timing` 明确分析。对 `payload_hold*→video_data*` 施加 10 ns `set_max_delay`。10 ns 为这次 40 ns 像素周期内留有余量的试验上界，尚未作为正式设计冻结值；工具 SDC 语义参照本机 SUG940-2.0E §5.4/§5.5。**不把两时钟全组设异步，也不把 64 位数据路径 false path。**

## 可复跑与反向证明

下列命令在本隔离 worktree 的仓库根运行；每种模式独立生成报告，不会互相覆盖。`ReferenceRoot` 须指向 Sipeed 固定参考提交 `f0347d830305ef3efb921f47bb51701e569beefd` 的 60K 仓库，脚本校验原始与派生 PLLA 源哈希。`run syn` 和 `run pnr` 明确各执行一次。**任何生成的 `.fs` 都不能用于下载**。

```powershell
.\code\scripts\build_visual_cdc_probe.ps1 -ReferenceRoot 'D:\Temp\Angel17\sipeed_mega60k_example_20260927' -Mode sentinel
.\code\scripts\build_visual_cdc_probe.ps1 -ReferenceRoot 'D:\Temp\Angel17\sipeed_mega60k_example_20260927' -Mode bounded
```

- `sentinel`：将同一载荷时限收紧到不可能满足的 **0.001 ns**。Gowin 记录 64 个 Setup 违例端点、Hold 0，最差 `payload_hold.event_type_0 → video_data.event_type_0` 为 **−2.318 ns**。检查器要求**恰好 64 个**，由此证明当前合成图中 64 位数据都能被相同的范围约束命中；该模式的脚本成功意味着“预期失败被观察到”，不意味着时序通过。
- `bounded`：恢复 **10.000 ns** 时限，同源路径最差余量 **+7.681 ns**；Setup/Hold 违例端点均 0，恢复/移除路径正余量。三个同步器后级建立余量 **+19.109/+39.154/+38.919 ns**，保持余量 **+0.380/+0.335/+0.476 ns**（依次 ACK/REQ/desync）。脚本/检查器还确认三首级例外、10ns时限和六条显式路径均处于 `Actived` 状态，逐条报告了实际 Q→D 节点及非负余量。两模式共分析 1126 条路径，资源 Logic 169/59904、Register 232/60780、PLLA 1/8；结果见 `evidence/visual_cdc_probe_20260928.json`。
- 将现有真实报告中的载荷时限换成错误值、把哨兵“64”改为“63”、或令一个后级报告命令失效，`check_visual_cdc_report.py` 均按预期返回失败；因此漏约束/漏后级报告不能静默 PASS。

## 限制与后续工作

1. 此探针是**独立桥电路的物理路径证据**，不是 CDC 亚稳态概率认证，不证明正式集成布局、显示器信号或音频无欠载。真实工程载荷扇出和 PLL 布局变化时必须重新验证 64 位覆盖、10ns余量及同步器后级路径；发生名称优化时应更新精准约束并重新通过 1ps 哨兵。
2. 独立的桥通信源/宿握手已由现有模块仿真覆盖；正式顶层接入仍需事件为**音频实际接收的那一拍**的副本，视觉侧丢失不得反压音频，PLL 失锁需向桥两域共同断言复位。`mode_toggle` 和曲谱多位数据从非视频域来时仍须另做 CDC 设计，这次未验证。
3. M3 的 `visual_score_tracker.sv` 对无 duration 的停留时间与 M1 模型不一致，`visual_live_state.sv` 多来源同音高亮也有误释放风险；本轮不改 M3 目录，需由 M1/M3 确认后处理。
4. **最关键阻碍仍是 M3 渲染器组合路径。**同一 25MHz 模式下的画面+HDMI 资源探针最差 Setup −86.486ns、72个违例，另有Hold与Recovery违例；见 `M2_可视化联合仿真与资源时序预检_2026-09-28.md`。当前 CDC 试验 PASS 不能解除这个失败，也不能把任何全链码流交上板。

验证等级：本试验对象仅 **L5（独立事件桥 CDC 物理路径及约束专项）**；可视化整体仅联合行为仿真 L2、画面资源探针 PnR FAIL。未开展实物 L6；本阶段无 V 编号，按仓库推送前最后一步规则处理。
