# M2 T016/T024 独立 ADSR 声部规模 PnR 对照（2026-09-27）

本实验只测**相同 RTL、相同工具和50 MHz约束下，1份与4份 ADSR 包络**的真实 PnR。虽然测试台对每份提供独立 Note On/Off/Velocity 输入，并把包络/状态全部引出，避免被优化掉，**它不是正式四复音声部**：没有 DDS、分配器、混音、PCM 请求/削波、UART 和真实演奏；不能据此宣称保底四复音已实现或时序达标。M1 算法 RTL 和模型完全不改，探针在 M2 `code/rtl/board/`，构建产物在忽略的 `code/output/t016_adsr_scale/`。

## 复现与实际数据

```powershell
.\code\scripts\run_t016_adsr_scale.ps1
python -m unittest discover -s code/tb/board -p test_t016_adsr_scale.py -v
```

Gowin V1.9.11.03 Education / GW5AT-LV60PG484AC1/I0；两种规模均使用同一 `adsr_piano_envelope.sv`、ROM、无板级 CST，仅 `sys_clk` 20.000ns SDC。2026-09-27 实际报告：

| PnR读数 | 1份 ADSR | 4份 ADSR | 差值 4−1 |
|---|---:|---:|---:|
| Logic | 643 | 2606 | 1963 |
| Register | 147 | 588 | 441 |
| DSP | 5 | 20 | 15 |
| BSRAM | 1 | 4 | 3 |
| Logic FF | 137 | 548 | 411 |
| Fmax @50 MHz | 54.583 MHz | 52.556 MHz | 无法线性外推 |
| 最差 Setup slack | +1.680 ns | +0.973 ns | 不用于累加估计 |
| 最差 Hold slack | +0.278 ns | +0.275 ns | — |

两种规模的 Setup/Hold 违例端点和TNS均0、无推断锁存器。四份包络的最坏路径来自 `g_voice[2]` 的 `elapsed` 到乘法器输入，表示独立四份在该布局下余量仅约0.973ns，**加入 DDS/ROM、多音色、混音及UART后可能变化，必须整机重跑**。4份的 I/O 为大量独立探针端口，参考引脚数量不能作为实际底板端口预算；若共享 ROM 或乘法单元也要另建真正调度架构后重新综合。这份结果只作为资源风险边界，不算 T016 保底档验收，也不作为 T024 混音链路已完成依据。

脚本自动为1/4份分别生成独立Gowin工程并保留原始报告、记录源码哈希；严格报告检查器要求正确器件、工具一致、50 MHz时钟、两档实际Setup/Hold路径及无负余量、Resource完整且四份ROM未被优化；报告检查器5项反例自检已通过。`code/docs/evidence/t016_adsr_scale_20260927.json` 保存原始报告/源码/脚本/码流10项SHA256和真实数字，便于以后从新源码版本复测，不可直接跨版本沿用旧数值。
