## 起终点和因果判据

- 起点A：TB接到R17角色的RX线上，完整90 note velocity三字节消息第一个状态字节起始位下降沿。包含MIDI传输时间，不包含真实键盘触键/扫描、DIN光耦在R17之前的传播或USB。
- 起点B：uart_rx.rx_valid输出最终velocity数据字节完成的系统边沿。它采停止位中点，不是整个停止位结束。3字节约0.96ms的线速传输，实测A→B0.94404ms，测试字节间有1sysclk边界等待，正常记录而不是人为减去传输时间。
- 中间阶段：公共FIFO事件成功接受、真实slot_note_on、第一次相关lane_tick、实际PCM成功提交、第一次混合buffer不同、第一次I2S帧采用量化后的不同样本。
- 终点：从实际BCLK上升沿、WS/DIN引脚读取完整32位半帧，最后16位为PT8211有效数。记录该完整字最后一个真实BCLK上升沿，不把在下一个WS边界才完成的软件判定延后当作多一个位延迟。WS低为右、WS高为左。

两份生产top同时例化，预热/所有准备消息完全相同，reference只在目标整个NoteOn消息期间保持RX idle。测试前两份PCM严格相等、相同时钟/reset；目标之后分别解码全部物理样本，并独立与各自在帧边沿采用的PCM24→16舍入饱和值逐字核对。第一次DUT与reference的完整字不同才记目标响应，不把和弦已有非零声误认为新输入起音。这个差分还包括目标消息造成的分配/相位/包络变化，不是用参考重新造一个人为PCM音符。

数字终点是完整字送达边沿，不假设DAC模拟何时更新或多大幅度人耳才可闻。首次声道字差为1~数LSB时可以低于模拟测量阈值，尤其最低音/极轻力度；不可拿数字第一差值等同可闻起音。原ADSR240采样Attack持续5ms不是本“第一数字响应”最大值；如果改定义为达到某百分比或可闻阈值，M3必须另外注明，不挪时间起点/终点凑结果。
