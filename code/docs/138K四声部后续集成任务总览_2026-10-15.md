## 4. 基础达标后才排拓展，按既有次序止损

10-09《成果优先的范围收缩与时序准入》给出的**可见成果主线**是稳定演奏/声音 → 真实 PCM 波形 → 手机传一份曲谱并逐条 READ → 最高稳定复音档与其纯正弦自证。第一项属 B1–B3 基础。最新用户把**复用60K的双音色切换**排为拓展首项，滑块上飘＋下落调整为第二项；均优先于波形，但不取消基础功能、电气、时序与下载准入。后续只在基础出口通过且不挤占冻结/材料时实施：

1. **双音色切换，拓展第一项**：复用60K现有MIDI演奏与Program Change 0/1→`CTRL_VOICE_SELECT`→每来源/通道下次Note On锁存的代码；138K `_06` 已包含该解析器、路由和钢琴/三角音源。先核当前MIDI源是否发出原始`Cn 00`/`Cn 01`，用同版后续音符的录音/PCM比较两音色及持音不突变；无可用实体切换键则记录UNKNOWN，不抢占两枚演奏键、不过早增加引脚。只在证明需要独立板载按键并选定安全端口后，另写该**一枚音色切换键**的最小事件适配代码。M1核算法，M3核实际MIDI消息与试听，M2核正式同版/STA/码流；不重写60K合成/MIDI模块。
2. **滑块上飘＋下落双模式，拓展第二项**：沿用现有视觉 RTL 和 40 MHz 视频时钟方案，只接当前获准整机的必要模式入口；先验上飘按键长条/松键上移、下落音符连续移动与退出、双模式切换/复位、同版音画共存和视频时序。60K 旧码流的上飘有 M3 限定 L6 实屏记录；旧下落能显示，但**命中闪光时机/效果 FAIL**。首轮为尽快上板，明确**暂缓修下落命中闪光**，只验上述最小范围，记录“闪光已知失败／未验”，不得把下落完整交互、命中反馈或两模式整机 L6 写成通过。首轮候选不得靠删掉失败记录、放宽其他音频/电气/STA 条件放行。M3 负责同版实屏动作与原始记录，M2 负责接入、CDC/完整 STA、精确码流身份和下载准入，M1 只核视觉接入后音频帧/欠载不退化；后续任务单要有各自明确授权目录。
3. **复用现有真实波形候选**：只验证冻结左声道/区域/窗口的一版实屏结果；不加菜单、缩放、双声道切换、频谱或李萨如新模式。
4. **传谱最小闭环**：一份真实文件从手机/有线链路传到 FPGA，核来源、真实 ACK、完整 READ 与错误反例；传输成功只声明存储/读回，不声明自动播放。BLE 后台、多设备、编辑器、续传和自动播放后置。
5. **最高稳定复音档（低优先级、条件启动）**：仅一套 N32 主候选，8/16 是调试关卡，按实际通过的功能、833 拍期限、同版资源/PnR/STA 和 N 路纯正弦谱峰报告最高稳定 N；V0336 的 N32 隔离重放 L3 是归档证据，**不触发现在开发/上板生产 N32**；只有基础与前面双音色、双滑块、固定波形、最小传谱均闭合，且仍留得出功能/时序/实物完整验证时间才启动。否则沿用最高实际通过的档位、T061 维持 PARTIAL；做不到 32 就如实写实际 N，不牺牲 48 kHz 或假报独立声部。
