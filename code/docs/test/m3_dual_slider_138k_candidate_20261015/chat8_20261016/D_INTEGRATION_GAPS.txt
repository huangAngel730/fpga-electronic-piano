三、接入最小差异与不变项（以下是提案，尚未修改RTL）
A. 保留时钟骨架。R06 probe:70–72不仅产生25/125MHz，还输出整机40MHz core_clk；
   不得整块删probe直接换D。只在新复制候选替换旧事件/控制CDC和m3_visualizer场景段。
   保留PLL、scanner、串行复位和唯一DVI_TX_Top；D本身不含PLL/扫描器/TMDS。
B. accepted副本。top:679–685仅复制shared_event_valid && shared_event_ready及原64bit数据；
   显示ready、mode_ready、score_ready绝不返回音频ready链。队列满时沿用丢弃/失同步诊断。
   新发现：probe:73原DEPTH=32，D:55固定DEPTH=8。8个显示槽不等于8深度事件队列。
   最小建议在获批复制候选中参数化并保持32；若保留8，需明确变更和突发容量证明。
   当前慢速单音夹具不能证明8深度可替代32，不能静默缩容。
C. 模式。40MHz请求生产者需保持valid直到ready，一次操作只交一次；原5秒自动切换
   是诊断，不是用户控制。SOURCE_MODE是音频诊断选择，不可借作显示mode。
   D:78–85在25MHz域frame_start提交mode_request；mode_pulse和frame_start同沿时，
   NBA语义为本帧用旧请求、下一个frame_start才提交该脉冲，测试/预期须显式覆盖。
D. 曲谱。visual_control_bridge:16–38保持16+7+32+1+32+10=98bit整包，握手等待时所有
   字段稳定；hit_frame/duration仍是帧单位，不换成MIDI tick或样本tick。
   TB:136直接读current_frame+6是仿真观察，不可复制成40MHz跨读25MHz多位计数器。
   正式生产者/帧epoch来源需M2确认；若读回帧号应有独立握手CDC，不私改时间合同。
E. 复位。probe:22共同sys_rst_n && pll_lock异步拉低，各域本地同步释放；D的
   sys_reset_done/video_reset_done分别汇合事件与控制桥。scanner使用D video_reset_done；
   串行复位保持原125MHz reset_sync。模式/曲谱生产者也需遵守40MHz释放就绪。
   禁止只复位像素域而留下在途邮箱。PLL失锁影响core_clk，夜间理想双时钟TB未测此项。
F. 单RGB路径。probe:100–134保留扫描→D组合RGB→原一拍RGB/HS/VS/DE寄存→唯一DVI/TMDS。
   不保留旧桥后再串D桥，不并行驱动两套RGB，不只加RGB延迟却不同时对齐HS/VS/DE。
G. 首个下落帧边界：D:105 match_enabled用旧display_mode；旧m3_visualizer在切换沿
   可用待提交模式。需登记同沿事件语义差异，不把首轮运动/切换通过写成命中反馈等价。
   命中闪光仍暂缓，不借本轮扩大修复范围。
