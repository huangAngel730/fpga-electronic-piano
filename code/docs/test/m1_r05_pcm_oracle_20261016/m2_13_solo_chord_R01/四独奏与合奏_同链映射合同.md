逐推进相位满足`phase_after=(phase_before+FCW) mod 2^32`；连续推进的前相位等于上一推进的后相位。精确分子/分母及十进制值见`FREQUENCY_TABLE_R02.json`；本表修正前批README中note63的打印笔误，不修改旧原件，向量中的FCW及计算值一直按公式生成。四个FCW/相位源分别对应四个note身份。Piano取推进后相位及其active_table；Triangle取推进前相位高位地址。M3须比较每个源的身份/FCW/相位/音色/包络及贡献，不能以Piano/Triangle谐波多峰增加声部计数。Triangle首样本为0合法；不要求四声在每一行都非零，只检查窗口中各声确有非零贡献以及全部逐样本值正确。

`solo_i`的lane0应与`all4`中该note对应lane_i逐样本一致：generation、FCW、phase_before/after、timbre、wave16、env_q15与voice_pcm24均整数零容差。不能按两个文件中的同一物理lane编号直接匹配。各场单独绑定scene_id和输入SHA；epoch/request_id可在不同场景从0重新开始，五文件不直接拼成含重复ID的单文件。

数值顺序为：`voice24=((signed_wave16*unsigned_env_q15)>>15)<<8`，负数算术右移向负无穷取整；四路先用足够宽的有符号和求和，再饱和到PCM24[-8388608,8388607]。clip是严格超出边界，边界自身不算。每场随后用自己的效果历史：`out[n]=sat24((mixed[n]*32767>>15)+(mixed[n-1]*16384>>15))`，首项历史为0，feedback0；左右数值同源，但这不证明真实左右接线/串行字顺序。

**不能把四个独奏的最终left/right直接相加充当合奏黄金。**应先按四路voice贡献重建合奏混音，再按合奏自己的接受事务历史计算效果；逐项Q15取整和饱和可能使这两种算法不同。本包生成实际软件差异行witness用于说明，不用虚构可达的削波幅度。

## 真实R05/R06接手要求

各场保存输入日历、完整每槽期望、紧凑CSV、规范化数学行及文件SHA；这些文件全部是`SYNTHETIC_ONLY`。最终入口为`run_R02/vectors/`；`run_R01/`的source1合成版本、11项已执行测试与生成原件保留为历史。主窗口在随后源核中发现source身份映射缺口，先保存`history_R01_source_id1/`再作最小修正；R02仅运行新增source0定向测试及新五场景生成，不能把历史11项写成最终版12项全组重跑。新软件校验与反例只检查五场景映射/数学准备，不认证真实捕获。前批Reference支持的其他边界与不支持的CC64/panic/PB/mod、同沿组合等限制继续有效；不扩成完整MIDI/router周期模型。

M3接真实链时，须给同次源/ROM/工具/输入/完整原始trace身份，独立导出事件应用沿、slot-generation、全部lane_tick、取消/reset/配置与全部效果接受沿，再用原Reference重生期望；不能用实际DUT wave/env/phase/table填黄金。规范化`NORMALIZED_MATH.json`只携数值/代数，不携source身份，单靠数值相等不能认证MIDI来源；须先在完整输入与scene映射中独立核source0、channel、note及generation。真实事件时间、推进或效果接受顺序与本合成夹具不同，就不能直接套这五份固定PCM；应使用真实独立日历重生。现R06 TB的303条汇总提交尚不满足这些前提。

真实左右PCM24/clip/声部贡献的数值容差为0 LSB。I2S/PT8211字与完整下一帧期限由M3原工具接续，M2最后核同版；缺字段继续UNKNOWN/PENDING，不补0或裁短窗口。每请求commit必须早于实际下一frame，不能以max35或<834代替逐请求证明。
