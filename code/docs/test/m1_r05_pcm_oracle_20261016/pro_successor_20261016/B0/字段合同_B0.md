# B0 字段合同 V1（待用户转发，尚未送达）

本合同仅是 M1 本轮软件入口，不修改 M2/M3 正式共享接口。M3 日历须来自独立的事件应用/slot/接受事实，不能用待比 DUT 的 phase、wave、env、mix 或效果输出反推期望。当前 Pro 真采输入及 M2 签名映射均未交，真实状态 `PENDING_REAL_CAPTURE`。

所有 JSON 为 UTF-8；拒绝重复键、浮点数、NaN、Infinity、缺必填字段、未知字段、错误类型；`bool` 不能充当 `int`。文件最大 32 MiB。计数从零、行序号连续；cycle 为 0..2^63−1 的绝对时钟，request/generation/epoch 为 0..2^32−1。source/channel 为 0..15，note 为 0..127，velocity10 为 0..1023，program 为 0..4095，PCM 为 −8388608..8388607，clip 必须双 bool。

## 1. Bundle 清单

必填顶层：`schema=M1_PRO_CAPTURE_BUNDLE_V1`、`mode=SYNTHETIC|REAL`、非空 `capture_id`、非空 `scene`、`profile=R06_SETTLED_SIMULTANEOUS_LANE_TICKS_V1`、`reference`、`calendar`、`public_pcm`、`pro_binding`、`counts`。

`calendar/public_pcm` 均为 `{path,sha256,bytes}`；两者为本入口 normalized 输入，不是完整原始driver/full trace/observer。SHA 为完整小写 SHA256，绑定**所交文件字节**（含换行），不做隐式规范化。path 为同 bundle 下相对路径，拒绝绝对路径、`..`、符号链接越界。REAL 缺原件可填 null，返回 pending；已提供但 SHA/大小不符必须拒收，不借缺件掩盖错误。capture_id/producer 声明不构成同次真实性认证。

`reference={signed_files,frozen_files}` 精确等于已签来源。入口内钉住父 `oracle.py`、`DEPENDENCIES.json`、`REFERENCE_CONTRACT.json` 的 SHA，并按旧 manifest 核四个已签源和三份 ROM 字节。绑定缺失/漂移立即拒收，导入前验 SHA，旧黄金/ROM 只读。

`pro_binding=null` 表示缺件；或 `{top_sources:[原文件描述符...],rom_files:[原文件描述符...],port_reset_map:原文件描述符|null}`。必须交实际 Pro top/源、ROM 和端口/复位/ROM 对照原件，不能仅给聊天 SHA。当前未签任何 map，提供自称 approved 的 JSON 也不能升级；M2 最终签收并冻结映射后才可扩展代码内受信 map 哈希集。

`counts` 必须精确含 `calendar_rows,public_pcm_rows,resets,events,lane_ticks,effect_accepts,config_accepts,cancels` 八个非负整数。REAL 原输入完全缺失时可 null；任一输入已交时必须给全，并校核已有输入可见的计数分量，不能以缺另一输入或 null 跳过校验。文件各自另有 `declared_count`，与清单/实际行数交叉核对。

## 2. 独立应用日历

顶层必填：`schema=M1_PRO_INDEPENDENT_CALENDAR_V1`、`origin`、`producer`、`capture_id`、`scene`、`declared_count`、`rows`。真实为 `origin=M3_INDEPENDENT_APPLIED_CALENDAR,producer=M3`；合成为 `origin=SYNTHETIC_FIXTURE,producer=B0_SYNTHETIC_FIXTURE`。与 mode 严格互斥。

每行 `{seq,cycle,epoch,kind,payload}`。cycle 严格递增；同沿不在窄 profile 内。首行必须 reset/cycle0/epoch0；后续 reset 的 epoch 逐次+1，不能在旧请求计算窗口内 reset，也不能让公开样本越过 reset。request 只在同 epoch 内唯一，reset 后允许复用。

| kind | payload 必填字段 | 接受规则 |
|---|---|---|
| reset | `{}` | 恢复已签 Reference 的 phase/program/slot/env/fx；epoch 独立外部输入 |
| event | `event,source,channel,note,velocity10,program,decision,lane,generation` | event 仅 note_on/note_off/program；使用**已应用**周期，不是 UART 字节/路由 enqueue 周期；decision/lane/generation 与已签 allocator 比对，program 或无匹配off的 lane/generation 为空 |
| config_accept | `enable,length,dry,wet,feedback` | enable bool，length 0..1023，三gain 0..32767；是效果配置接受时刻 |
| lane_tick | `request_id,lane_cycles,identities` | lane_cycles 必须按 lane0..3 共四条 `{lane,cycle}`，cycle 全等于该行；未公开和未接受工作也要逐次交；快照固定+5 |
| effect_accept | `request_id,publish,publish_cycle` | 接受cycle至少 tick+7；publish bool，真时给实际公开cycle且 ≥接受cycle，假时 null；即使取消公开也须保留接受史 |
| cancel | `request_id,reason` | 每个不公开请求恰有一条；cycle至少 tick+5；公开请求禁止取消。这里只描述取消公开，不猜硬件仲裁 |

`identities` 是按 lane0..3 的四条 `{lane,source,channel,note,generation}`。活跃/释放槽保留 source/channel/note；空槽三者同时 null，但 generation 仍是已签 lane 保留的世代计数。禁止部分 null。reset epoch、每次 event 的槽决策、每次 lane_tick 身份先与 Reference 一致，才能进入公开 PCM 比较。

本 profile 不接收 CC64/panic/pitch bend/modulation；不接收 stagger lane tick、same-edge retire/retrigger 或据内部状态倒推的日历。若 Pro 新 top 采用不同流水/调度，只报告合同差异，不能把真实 trace 硬套旧 Reference。Effect 接受史和 lane_tick 完整性仍须 M3 原始 trace/计数证明；自报 counts 本身不是独立性证明。

## 3. 同次公开 PCM/ID/clip

顶层与日历相同七字段，`schema=M1_PRO_PUBLIC_PCM_V1`。真实为 `origin=REAL_DUT_PUBLIC_CAPTURE,producer=DUT_PUBLIC_CAPTURE`；合成 origin/producer 同上。capture_id 和 scene 与清单/日历一致。

每行必填 `{seq,cycle,epoch,request_id,identities,left,right,clip}`，唯一可选 `diagnostics`。cycle 严格递增；请求身份/epoch/公开cycle与日历 effect_accept 的 publish 集合逐项全等；取消、不存在、重复、漏样本、错 ID/世代均拒收。公开行 identities 是 M3 独立日历的关联标签；若 Pro 公开端口没有逐lane身份输出，不能称为逐lane内部实测。

先验证**全部**公开行的 scene/source/channel/note/generation/lane 身份，再比较任一行 PCM。left/right 使用 signed PCM24 十进制；clip 是左/右最终公开 clip，按已签 upstream clip OR fx output clip，比对容差为 0 LSB；feedback_clip 是期望内部诊断，不能与公开 clip 混用。

`diagnostics` 可含 `lanes` 和 `mixed_left,mixed_right,fx_left,fx_right`。lanes 各条必有 lane，可含 `timbre,wave16,env_q15,voice_pcm24,fcw,phase_before,phase_after`；不能重复lane。所有内容只是 **actual**。即使这些观察与黄金相等，也不能覆盖错误的公开 PCM；即使观察不同，也不拿它改变黄金。

首个 PCM 差异报告 scene/epoch/request/source、四 lane 的期望 identity/timbre/phase/wave/env/voice、期望 mix/fx/clip、实际公开 L/R/clip 及可选 actual 诊断。若实际 diagnostics 存在，按 lane0..3、各lane的 timbre/fcw/phase_before/phase_after/wave16/env_q15/voice_pcm24，再 mix，再 fx 找首个不同观察，填写 `observed_layer/lane/source`，仅为诊断线索，不认定唯一根因、不改变黄金。只有公开 PCM 时 `lane=null`，明确不能从总输出编造某 lane 根因。

## 4. 判定与交接

`SYNTHETIC_FIXTURE_PASS` 只证明新软件入口与合成正负例；`PENDING_REAL_CAPTURE` 不能签 RTL PASS。CLI exit0/1/2/3 分别表示接受、数学差异、合同拒收、真实缺件。输出用独占创建，原件和旧结果均不覆盖。所有结果保留 `board_release_allowed=false`。

当前窄 profile 只支持已知周期的 reset action，**不支持异步 RESET_EDGES 子周期捕获/重放**，此项始终列在 `missing_real_requirements`。不能把“port/reset map 已签”当成已覆盖异步复位。

真实接手还需 M3 的原始 driver/full trace/observer 及源码绑定、采集工具/版本/argv、stdout+stderr 双流、退出码与实际额度回执、原始连续性计数、RESET_EDGES 原件，以及证明 calendar/公开 PCM 来自同次运行的来源链；本轮不扩张全流 parser，这些原件未验时仍为 `PENDING_REAL_CAPTURE`。同时待 M2 交同版 Pro top/source/ROM SHA 与端口/复位映射。M1 仅在原件齐备并获得适用受信合同后进行真实比较。夜间不调用 ModelSim/Gowin/PnR/STA、不追加码流或设备工作，不从本字段合同恢复任何旧工具额度。
