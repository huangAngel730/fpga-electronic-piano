# Pro 同版现场采集人工步骤（当前 NOT_RUN）

## 1. 会话建档与只读核身

先复制 `SESSION_TEMPLATE.json` 为新会话记录，分配唯一 `session_id`。在不触发 Programmer、JTAG 或其他设备操作的前提下，拍摄实物 Core、Dock、芯片丝印、跳帽、电源和完整接线；将照片原件逐项登记大小和 SHA，不用参考 PDF 的候选值代替实物观察。

在接探头或上电前，先依据已核实的 Pro 资料与实物确认测试点、预期电压范围、仪器量程、探头倍率、接地位置、供电限流、MIDI 方向和安全音频负载。任一项未知时只拍照并记录 `UNKNOWN`，不接探头、不接外设、不触发设备。上述无源检查通过后，才可受控上电并测量相关 I/O Bank 实际电压、MIDI 适配器 FPGA 侧高低电平、共地连续性、PT8211 与 PA 路径；保存仪器原始读数。实物/供电/接口电平/安全接线全部确认后，才允许调用 Programmer/JTAG 枚举并记录完整料号/封装。未知电平、5 V 直接输入、供电异常或不明负载立即停，不接 FPGA。

## 2. 工程、物理和码流门槛

登记商业 Gowin IDE/Synthesis/Place & Route/Programmer 的版本、二进制 SHA、运行时许可状态和主机身份。绑定同一版 top、完整 source list、ROM、约束和 PLL 的 SHA。

完整 PnR/STA 至少要覆盖 setup、hold、recovery、removal、未约束路径、生成时钟、I/O 时序和 CDC 处理；保存报告原件与 SHA。任何失败、缺报告、未约束关键路径或目标器件不一致都阻断下载。

取得唯一 `.fs` 原文件，记录路径、字节数和 SHA，并核对它确由上述同版工程产生。另绑定断电/重新上电后的恢复身份与恢复步骤。最后取得一条针对该精确 SHA、该实物、该会话的一次 `SRAM-only` 明文许可；确认 `flash_write_allowed=false`、许可未消费。目录、日期、旧许可或“继续测试”字样都不能替代这条许可。

## 3. 一次 SRAM 操作与止损

只有所有门槛为 PASS 才可进入 `AUTHORIZED_NOT_RUN`。真实执行时记录完整 argv，或逐字记录 GUI 器件、模式和选项；保存 cwd、开始/结束时间、stdout/stderr 或 GUI 原日志、退出码，以及操作前后 SRAM 状态。下载计数只允许从 0 变为 1。

首个下载失败即停，保留原件；不换 `.fs`、不修工程后追加下载、不写 Flash。任何断电、工具重连或重新编程请求都视为新许可事项。

## 4. 同一时间基准的场景采集

全程保持同一 `.fs`、接线、增益和时基。先低音量执行 `S00_BOOT_RESET_MUTE_LOCK`，确认复位/锁定/PA 顺序安全，再依次执行：固定音、四个独奏、四音同时保持、逐个释放、同音不同 Velocity、演奏中复位与恢复后新音。

每一场景保存：

- 原始 MIDI 字节、发送时间戳、冻结输入计划和其 SHA；
- UART/状态原始字节流及解码版本（若公开可用）；
- PT8211 `BCLK/WS/DIN` 原始逻辑采集；
- `PA_EN/reset/pll_locked` 原始采集；
- 经过已确认安全输出与负载取得的原始模拟音频；
- 统一触发信号、时间基准、采样率、通道映射、量程、探头倍率、接地和校准信息；
- 命令/工具双流、退出码和首个异常。

输入到声音的延迟只能用同一时间基准上的 MIDI 输入原点和模拟起音阈值计算。听感、UART 时间或不同设备的独立时钟不能填成定量延迟。四声部也须由四个独奏与同一输入记录对照，不能仅凭“听见和弦”判定四路存在。

出现未知电平、异常大音量、削波、功放发热、失锁、挂音或错误串音，立即静音、断开不安全外设并保留首个现象；不为凑齐场景继续。

## 5. 封存和限定结论

原件只追加不覆盖。对每个文件记录 role/path/bytes/SHA/original_unmodified，对每个场景分别写 PASS/FAIL/UNKNOWN 和观察边界。未取得数字波形、模拟波形或共享时基的指标保持 UNKNOWN；诊断性采集不能自动提升为生产码流、G0–G3 或整机验收通过。

会话结束后把完整 session JSON、下载日志、MIDI、逻辑采集、模拟采集、照片/视频、仪器配置和失败原件交 M2 复核。M2 最终决定同版证据是否可接入；本包自身始终保持 `board_release_allowed=false`。
