Static conclusion
-----------------
The active R02 patch proposal addresses the original bypass in the intended
direction:

1. The next deadline comes from an independently frozen explicit frame plan,
   rather than from the next FRAME row observed in the trace.
2. The global frame cursor remains live after a transaction becomes CANCELED,
   so a missing FRAME cannot be erased by CANCEL, END, or RESET.
3. Every row passes the clock/deadline guard before its state mutation.  END
   and RESET additionally close all frame obligations through their cycle.
4. The proposed relation is exact: RETURN/CANCEL/unconsumed RESET must be
   strictly before the request's next frozen frame; CONSUME occurs at that
   frame.  It does not reintroduce the superseded uniform q+833 limit.
5. Equal-cycle input order is preserved.  The proposed guard permits ordinary
   rows before a same-cycle FRAME, but END/RESET cannot close that cycle before
   the scheduled FRAME.  FRAME can be followed by the old request's CONSUME,
   a new request, and then a planned RESET without reordering the trace.

whose CANCEL at age 833 equals the deadline and must be rejected.  BC09 covers
the D834 age-833 condition only with RESET, not CANCEL.  RESET and CANCEL take
different branches and perform different epoch/frame cleanup, so BC09 cannot
serve as direct evidence that a D834 request may be canceled at q+833 while
still strictly before f=q+834.
