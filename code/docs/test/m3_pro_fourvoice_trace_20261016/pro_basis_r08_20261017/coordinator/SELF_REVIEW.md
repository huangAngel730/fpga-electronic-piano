## 总控入口

自己的只读子智能体检查 run_group.py 后发现：总控与用例重复创建目录；相对 watchdog 启动时间和提前撤销导致收尾不受限；只读设备路径未阻止；缓存 SHA 使二次读取不复核；最终复核异常可能逃出且锁阻碍 watchdog。

首次运行前已修：只建用例父目录；用绝对 monotonic deadline，收据完成后才撤销；拒设备命名空间/保留设备名/非普通输入；每次仓库输入读取核冻结 SHA，结束再核；昂贵校验在收据锁外，异常写 FAIL_PARTIAL。固定解释器、实际 argv/cwd、禁止优化断言、UTF-8 与禁 pyc；独占 run 目录和消费先记账，剩余未知时不自动恢复消费。审计阻止子进程/网络/设备及本 run 外写入。此 Python 审计仅防御已审本地候选的误调用，不是恶意原生代码安全边界，更非真实 EDA 执行器准入。

协调入口仅做 AST 静态解析，候选导入 0；此静态检查不算 R/S/C/T/H 功能通过。最终冻结前再核新增协调脚本语法。

CASE 清单按同一缓存字节解析和封存，冻结结束再次核 selftest/CASE；运行入口将 CASE 的 group/id/expected/description 与冻结原件逐字段核同。子智能体复查此具体增量未发现首次执行接口阻断。发布清单补入 R17 两份精确 SPEC_ORIGINALS 和实际收据读取的新依赖，避免只有 ZIP 而新克隆缺输入；历史修复前版本仍由原快照保留。
