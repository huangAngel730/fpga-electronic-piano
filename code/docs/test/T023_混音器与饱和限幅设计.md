## 二、核心问题分析

### 2.1 数值溢出风险

**单声部PCM范围**（波表定标后）：
- 波表样本：16位有符号，±32767
- 定标：左移8位，得到 ±8388352
- 与24位满量程（±8388608）的关系：**留有256 LSB余量**

**4声部直接相加的风险**：
```
最坏情况：4路都是正满幅 8388352
直接相加：8388352 × 4 = 33553408
24位范围：-8388608 ~ 8388607
结果：溢出约4倍！
```

### 2.2 解决方案对比

| 方案 | 优点 | 缺点 | 是否采用 |
|------|------|------|----------|
| **方案A：先求和后限幅** | 实现简单，保留动态范围 | 需要宽位中间结果（至少26位） | ✅ 推荐 |
| 方案B：每路预衰减1/N | 永不溢出 | 损失6dB动态范围，多数时候浪费 | ❌ |
| 方案C：自动增益控制 | 动态最优 | 复杂，引入延迟和瞬态 | ❌ |

**选择方案A的理由**：
- 实际演奏时4路同时满幅的概率极低
- 保留完整动态范围，单声部和双声部不损失
- Python和RTL都容易实现宽位加法

## 三、定点格式设计

### 3.1 混音中间结果位宽

**推导**：
```
单路最大值：8388352 (约 2^23)
4路相加最大：33553408 (约 2^25)
需要位宽：26位有符号（1符号位 + 25数值位）
```

**定义**：
- **混音累加器**：`int32`（Python）/ `logic signed [31:0]`（RTL）
- 实际使用：低26位有效
- 溢出检测：检查是否超出 [-2^25, 2^25-1]

### 3.2 混音流程

```python
# 伪代码
mix_sum = 0  # 32位有符号
for voice in voices:
    mix_sum += voice_output  # 每个voice_output是24位有符号
    
# 饱和到24位
if mix_sum > PCM_MAX:
    pcm_out = PCM_MAX
    clip_count += 1
elif mix_sum < PCM_MIN:
    pcm_out = PCM_MIN
    clip_count += 1
else:
    pcm_out = mix_sum
```

## 四、算法定义

### 4.1 混音函数签名

```python
def mix_voices(
    voice_samples: list[int],  # 每个元素是24位有符号PCM
    max_voices: int = 4
) -> tuple[int, bool]:
    """
    多路音频混音并饱和限幅
    
    参数：
        voice_samples: 声部输出列表，每个是24位有符号PCM
        max_voices: 最大声部数（用于文档，不影响计算）
    
    返回：
        (混音后的24位PCM, 是否发生削波)
    
    要求：
        - 所有输入必须在 [PCM_MIN, PCM_MAX] 范围内
        - 输出保证在 [PCM_MIN, PCM_MAX] 范围内
        - 使用饱和限幅，不使用回绕
    """
```

### 4.2 边界条件

| 场景 | 输入 | 期望输出 | 削波标志 |
|------|------|----------|----------|
| 单声部满幅 | [8388352] | 8388352 | False |
| 双声部满幅 | [8388352, 8388352] | 8388607 (限幅) | True |
| 4声部满幅 | [8388352] × 4 | 8388607 (限幅) | True |
| 4声部负满幅 | [-8388352] × 4 | -8388608 (限幅) | True |
| 混合符号 | [8388352, -8388352] | 0 | False |
| 全零 | [0, 0, 0, 0] | 0 | False |

## 五、Python参考实现

位置：`code/model/mixer.py`

### 5.1 核心函数

```python
def mix_voices(voice_samples: list[int]) -> tuple[int, bool]:
    """多声部混音与饱和限幅（Python参考实现）"""
    # 输入验证
    for i, sample in enumerate(voice_samples):
        if not (PCM_MIN <= sample <= PCM_MAX):
            raise ValueError(f"声部{i}样本{sample}超出24位PCM范围")
    
    # 求和（使用Python原生int，无溢出）
    mix_sum = sum(voice_samples)
    
    # 饱和限幅
    if mix_sum > PCM_MAX:
        return PCM_MAX, True
    elif mix_sum < PCM_MIN:
        return PCM_MIN, True
    else:
        return mix_sum, False
```

1. **边界测试**：单声部到4声部，正负满幅组合
2. **随机测试**：1000组随机输入，验证无回绕
3. **实际信号测试**：4路正弦波混音，验证频谱无失真

## 六、RTL实现建议（供M2参考）

### 6.1 接口定义

```systemverilog
module voice_mixer #(
    parameter int NUM_VOICES = 4,
    parameter int PCM_WIDTH = 24
) (
    input  logic clk,
    input  logic rst_n,
    
    // 输入：各声部PCM
    input  logic signed [PCM_WIDTH-1:0] voice_pcm [NUM_VOICES-1:0],
    input  logic                         voice_valid,
    
    // 输出：混音后PCM
    output logic signed [PCM_WIDTH-1:0] mixed_pcm,
    output logic                         mixed_valid,
    output logic                         clipped
);
```

### 6.2 实现要点

1. **宽位加法**：
   - 使用 `logic signed [31:0]` 累加器
   - 或树形结构减少关键路径延迟

2. **饱和逻辑**：
   ```systemverilog
   if (mix_sum > 32'sd8388607)
       mixed_pcm = 24'sd8388607;
   else if (mix_sum < -32'sd8388608)
       mixed_pcm = -24'sd8388608;
   else
       mixed_pcm = mix_sum[23:0];
   ```

3. **削波检测**：
   ```systemverilog
   assign clipped = (mix_sum > 32'sd8388607) || 
                    (mix_sum < -32'sd8388608);
   ```

4. **流水线选项**（时序优化）：
   - 第1级：两两相加（2个加法器）
   - 第2级：再两两相加（1个加法器）
   - 第3级：饱和限幅

## 附录A：数学推导

### A.1 N声部混音所需位宽

```
单声部最大值：M = 2^23 (约8388352)
N声部相加最大值：N * M
所需范围：[-N*M, N*M]
最小位宽：W = ceil(log2(2*N*M)) = ceil(log2(N) + 24)

N=2: W=25位
N=4: W=26位
N=8: W=27位
N=16: W=28位
```

### A.2 削波概率估算

假设各声部幅度独立均匀分布在[-M, M]：
- 4声部相加：均值0，方差 `4*M^2/3`
- 超出±8388607的概率：约0.13%（理论值，实际更低）

**结论**：削波是小概率事件，不需要预衰减
