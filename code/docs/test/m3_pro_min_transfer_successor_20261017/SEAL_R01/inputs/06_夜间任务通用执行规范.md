# 夜间任务通用执行规范

适用于此后 M1／M2／M3 及其 AI 的夜间或其他无人实时协调时段。每次仍须以**用户当轮指令、最新有效岗位任务单和项目事实**确定目标与权限；本规范规定任务单形式和执行/交接方法，不自动批准新的写集、EDA 次数、板卡操作或正式发布。2026-10-15 的三份夜间单是已实例化案例，不应按其日期、时长、机器和工具 SHA 推定未来的条件。

## 一、开工前写出一页可自主执行的任务单

任务单应在开工前入仓，标题给岗位、夜间日期和时间盒。开头用一张简表写明：

| 必填项 | 要写清的内容 |
| --- | --- |
| 项目目标与优先级 | 对应最新总览和岗位单；当前关键路径、并行准备与明确暂缓项。旧任务和阶段成果不自动变成新优先级。 |
| 可用条件 | 人员/用户能否回复、能否使用实物、工具与许可证、输入字节是否在本机。**每晚实核**；有板不等于可下载，没板只做离线工作。 |
| 时间盒 | 总时长和最多几个阶段；这是**上限**，不是最低工时或工具次数。每阶段说明可核交付物、达到即结束的条件。 |
| 写入与执行范围 | 每个独立包的精确新目录、只读原件、允许的工具/机器/版本/次数/单步和总预算、独占输出与共享消费台账。多个窗口不各自领取相同额度。 |
| 验收和缺口 | 输入/产物 SHA、原始命令/双流/退出码、PASS/FAIL/UNKNOWN、实际 L0–L7；列清不支持的更高等级和下一责任人。 |
| 转轨与次晨交接 | 原因、首失败证据、下一个**确能解除当前瓶颈**且已授权的工作；没有就提前停，次晨由用户转发的消息及 M2 复核范围。 |

只拆可以独立推进且写集互不重叠的任务包。主窗口保留原始输入核对、集成判断和最后交付；子窗口不同时编辑相同源、输出目录或消费标记。按依赖推进关键路径，把与当前目标无关的后置拓展留在单外。能复用已签源码、模型和测试时只做变化影响范围的增量；不为填满夜间时间重跑已签专项、复制旧证据、另造用不上的工具或从零重写已够用的报告。

## 二、执行中按结果收口，不按时间凑任务

1. 先保存 Git HEAD/`origin/develop`、工作树已有修改和未跟踪文件，核对任务单引用的输入、工具、版本与已消费额度。缺件记 UNKNOWN 或 BLOCKED，不从路径、文件名或聊天猜 SHA。
2. 已授权的新隔离实现、静态检查和有界自检可自主完成；每次工具运行记录精确 argv、cwd、机器/版本、输入/输出 SHA、原始 stdout/stderr、退出码、耗时、失败史和实际验证等级。软件 PASS 不代 RTL 编译/仿真；离线 PnR/STA 不代真实上板。不要扩大已有一次性许可；首失败停、保留原件，除非任务单预先写明另一独立可消费的修复轮和适用条件。
3. 某包受阻时，只转向**已授权、无需该阻断输入、且能直接缩小当前关键路径缺口**的下一包；说明为何能推进。没有这样的工作，写 `NO_ACTIONABLE_WORK`、待决条件和已交原件，提前收工。必要成果已完成时也提前收工。空闲不触发低优先级项目或恢复旧许可。
4. 若当夜用户/成员不可达，已明确授权的隔离工作照常推进；需要新权限、跨写集代做、共享接口或正式顶层/约束变更时，停在差异说明和可逆补丁，转做另一项。**无人回复不是批准。**接口组的提前群内说明和跨岗位私发交接不能被仓库文件、另一个 AI 窗口或事后通知替代。
5. 板卡/仪器是否可用以当夜任务单为准。明确不可用时不安排 JTAG、SRAM/Flash、接线、测电压、录音/实屏或视频；可用时也必须有本次精确码流/电平/接线授权和安全检查。没有同版实测不得把模拟延迟、听感、Bank 电平或板级等级写成通过。

## 三、发布和晨间回执

- 每包留下**一份简短收据**：任务和实际写入文件、提交完整 SHA（未提交/未推送明确写出）、输入和工具身份、运行命令与原双流/退出码、正反结果与首次失败、额度消费、达到的等级、不能外推的项、下一责任人。旧失败不回填成功；多个成功阶段保留各自身份。
- 只发布任务单授权且仓库门禁全 PASS 的精确树：逐文件暂存、`git diff --cached --check`、`code/scripts/check_repo.ps1` 全 PASS；同步最新 `develop` 并处理并发变化，不强推。V/D/T 编号在最后一次 fetch 后才取，编号登记与功能提交分开。门禁或 Git 受阻则封存本地，报告实情，不绕过审批。M1/M3 的隔离成果可按已授权范围自审并普通推送，推后最终复核仍归 M2。
- 当夜不能私信时先备好给相应负责人的完整消息，统一标 **“待用户转发，尚未送达”**；用户确认实际转发后才记已通知，送达仍不等于对方已处理。次晨 M2 对已到原件限定复核，并更新活任务单、`当前状态.md`、`任务看板.md` 和必要验证记录。没有收到原件的包保持 PENDING/UNKNOWN，不把夜间计划写成执行结果。

## 可复制的最短模板

```text
# <岗位>：<日期>夜间<目标>（最长约N小时）
现行任务单/输入提交：...
当晚可用条件：用户/队员可否联系；实物可否使用；工具与输入是否可核。
当前关键路径和止损：...；明确暂缓：...
包A（优先）：写集...；只读源...；可用工具/额度...；退出物...；失败→包B/停止条件...
包B（并行）：写集...；只读源...；可用工具/额度...；退出物...；失败→...
达到必要结果即可提前收工；无可推进工作→NO_ACTIONABLE_WORK。
晨间回执：文件/提交/原始日志/SHA/等级/失败/消费/未验/下一责任人，待用户转发尚未送达。
```

实例（只学习形式，不搬运其工具身份或额度）：`M1_夜间八小时任务单_2026-10-15.md`、`M2_夜间五小时集成值守任务单_2026-10-15.md`、`M3_夜间八小时任务单_2026-10-15.md`。
