
### 1.3 Note Off 门控修正 ✅

**问题：** Note Off 后停止相位推进，破坏 ADSR Release

**修正：** 始终推进相位，不受 Note On/Off 影响
```systemverilog
// 修正前：
if (sample_tick && note_active) begin
    phase_acc <= phase_acc + fcw;
end

// 修正后：
if (sample_tick) begin
    // 始终累加，支持 Release 期间波形输出
    phase_acc <= phase_acc + fcw;
end
```

### 1.4 音色锁存修正 ✅

**问题：** 文档说保持原音色，RTL 却每拍跟随 timbre_select

**修正：** Note On 时锁存音色选择
```systemverilog
// 新增锁存寄存器
logic timbre_latched;

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        timbre_latched <= 1'b0;
    end else if (note_on) begin
        // Note On 时锁存当前音色选择
        timbre_latched <= timbre_select;
    end
end

// 使用锁存值而非实时值
sample_out <= timbre_pipe[2] ? triangle_data : sine_data;
```

### 1.5 相位连续性修正 ✅

**问题：** Note On 将相位清零，不符合连续重触发要求

**修正：** 删除相位清零逻辑
```systemverilog
// 修正前：
if (note_on) begin
    phase_acc <= '0;  // 清零
end

// 修正后：
// Note On 时不操作 phase_acc，保持连续
if (sample_tick) begin
    phase_acc <= phase_acc + fcw;
end
```

### 6.2 关键时序（2026-10-01 更正）

**原说法“总延迟 3 周期 / ROM 延迟 2 周期”不精确，已撤销。**
按真实数据路径，从采样边沿 **E** 到输出落在 **E+3**，共 **4 个寄存阶段**：

| 边沿 | 动作 |
|---|---|
| **E** | `addr_pipe[0] <- wt_addr`；`timbre_pipe[0] <- timbre_latched`；`valid_pipe[0] <- sample_tick` |
| **E+1** | `addr_pipe[1] <- addr_pipe[0]`；`timbre_pipe[1]`、`valid_pipe[1]` 同步移位 |
| **E+2** | 同步 ROM 数据寄存器 `<-- ROM[addr_pipe[1]]`（`sine_data` / `triangle_data`） |
| **E+3** | `sample_out <- 音色选择(ROM 数据)`；`sample_valid <- valid_pipe[2]` |

- `valid_pipe[0..2]` 与 `sample_valid` 同样构成 4 级。
- `timbre_pipe[2]` 与同一拍的 ROM 数据选择对齐。
- **Note On 与 `sample_tick` 同沿时**：本拍仍使用**旧的** `timbre_latched`，
  下一拍才用新值。这是模块的确定性行为，集成方必须按此对齐，不能沿用旧 E+2 预期。

源码注释已同步更正。

### 6.3 音色控制

- Note On 前设置 `timbre_select`
- Note On 时锁存到 `timbre_latched`
- 发声期间切换 `timbre_select` 不影响当前音符

## 七、已知限制

1. **音色切换时机**
   - 建议在音符间隙切换 `timbre_select`
   - 发声中切换不影响当前音符，下次 Note On 生效

2. **ROM 资源**
   - 每种音色：1024 × 16 = 16 Kbit
   - 双音色总计：32 Kbit

3. **延迟**
   - 采样边沿 E 到输出 E+3，共 4 个寄存阶段（详见 6.2 节）
   - 需要与 ADSR 对齐
   - 旧文档曾写“ROM 读取延迟 3 周期”，该说法**已作废**
