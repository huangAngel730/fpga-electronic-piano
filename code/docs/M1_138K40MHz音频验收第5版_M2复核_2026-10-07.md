## 原始双文件正例FAIL

提供原始JSONL和F时exit1，错误为`invalid literal for int() with base 10: '000d00'`。
原F的真实格式：

```text
R cycle epoch
M cycle request_id pcm_left_hex pcm_right_hex clip
```

M1却按`M epoch cycle request_id tick pcm_s24`读取，未跟踪R epoch，PCM没有按hex+signed24
解析，也错误假设原F是单声道。不能修改真实capture来迎合错误解析器；应修解析入口。
此外逐条检查只遍历F记录，在F为空/无M/垃圾文本时记录数0，三者均exit0并显示“0条完全一致”。
必须要求非空、完整END/格式、相同记录数、相同顺序并双向逐条校验(epoch/cycle/req/左右PCM)。
