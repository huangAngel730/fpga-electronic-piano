# M2 独立串行复位物理布局试验（2026-09-28）

**阶段结论：保留原两级串行时钟上升沿同步释放逻辑，仅在独立探针 CST 中固定复位末级触发器的位置后，OSER10 的恢复路径余量由 −0.020 ns 变为 +0.885 ns；全部恢复/移除路径正余量。M3 原版渲染器仍导致 61 个 Setup 端点违例，像素域实际 Fmax 9.805 MHz < 25 MHz，完整可视化不具备 L5、码流严禁下载。** 本阶段没有修改 M3 模块、正式顶层/CST/公共接口或 `reset_sync.sv`，没有实物验证。

## 物理证据与试验范围

目标 Gowin V1.9.11.03 Education、GW5AT-LV60PG484AC1/I0；输入 sys_clk 50 MHz，PLLA 输出 125 MHz serial、25 MHz pixel。原完整独立探针路径是 `u_serial_reset/sync_chain_1_s0/Q → u_video_tx/rgb2dvi_inst/u_OSER10_clk/RESET`，从 serial 上升沿到同周期下降沿只有约4ns恢复预算；原 M3 合成图首版触发器位置 R36C34[3][B]，时钟与数据布线让余量为 −0.020 ns。已通过的独立蓝灰传输探针中同一末级在 R49C101[1][B]，报告余量 +0.866 ns；由此只针对 M2 独立完整资源探针试验 `INS_LOC` 将两级复位 FF 分别放到 `R49C101[1][A/B]`。本试验没有放宽 SDC、缩短渲染路径或改变 PLL/DVI IP。Gowin Recovery 路径回读末级实际在 `R49C101[1][B]`，Recovery +0.885 ns、Removal +0.389 ns；`PR1014` 参考时钟走普通布线警告仍在。具体源/报告/生成 CST 哈希见 `code/docs/evidence/visual_serial_reset_placement_20260928.json`。这些位置只在现有器件、独立布局和时钟配置下是测量候选，正式顶层布局要重新验证。

## 淘汰的复位逻辑试验

- 原两级上升沿方案（无位置约束）Recovery **−0.020 ns**、Setup 65端点，保留为比较基线。
- 延长为三级上升沿：Recovery **−0.373 ns**，未改善，已拒绝。
- 在忽略源码内改成下降沿释放时，初次内联写法一度观察到 OSER10 的 Recovery +0.262 ns，但作为独立模块综合后，最差 Recovery 转移到 DVI 内部像素域 CLR 路径并退化为 **−0.341 ns**，Setup 92端点。模块的 8项行为 TB 和未修改本机 Gowin `OSER10` 原语模型80个串行周期的仿真通过只能算该候选 L2，不替代 PnR；**下降沿候选未采纳**，源码及失败报告留在忽略输出 `code/output/visual_full_path_probe/falling/`，不作为可交付模块。试验结束时有跟踪的 M2 构建脚本只保留 `auto`/`measured` 两种原上升沿布局方式。

下一步 M3 优化渲染路径后，M2 必须使用新版 M3 哈希再跑整个联合仿真和 `measured` 独立 PnR。只有 Setup/Hold/Recovery/Removal 全正、CDC真实端点非空、实物板卡与屏幕测试过后才能讨论 L6。正式音频+HDMI 共存尚未集成，S5 门槛与接口组受控流程不变。本轮 `./code/scripts/check_repo.ps1` 全项 PASS、`git diff --check` 及报告/源码 SHA、UTF-8/LF 静态检查通过；仓库门禁不改变独立全链时序 FAIL 的结论。

本阶段级别：**独立串行复位物理子项 L5，整体可视化 PnR FAIL（非 L5）**；无板级数据。
