## 整体项目影响

| 指标 | 50MHz | 40MHz | 边界 |
|---|---:|---:|---|
| 系统周期 | 20ns | 25ns | 同域组合逻辑每周期有更多时间；不能代替Hold检查 |
| 同结构每秒时钟数 | 5000万 | 4000万 | 相同II/并行度下的周期吞吐下降20%，不等于所有外部接口下降20% |
| 固定30拍内部处理 | 0.60μs | 0.75μs | 固定拍数耗时增长25%；不是模拟输出或端到端延迟 |
| 每个48kHz样本可用系统拍数 | 平均1041.667 | 平均833.333 | 预算按最短完整帧1041/833拍及保护开销计算，不按平均值承诺 |
| 音频采样目标 | 48kHz | 48kHz | 正确重算NCO，逻辑采样推进不变 |
| 像素/串行时钟 | 25/125MHz | 25/125MHz | 系统降频没有降低这两个视频时钟 |
| 原800×525扫描帧周期 | 16.8ms | 16.8ms | 25MHz像素时钟下约59.52fps，系统降频不会直接造成扫描掉帧 |

当前捕获已观察请求→提交30/31/32拍；原四声部处理主要30拍，40MHz相关音频/音画测试
未出现欠载。这只证明已测功能/场景，不证明所有未来声部/效果器能够赶上截止时间，也不能
将0.75μs当作键盘到扬声器延迟。端到端还包含UART字节、事件调度、帧采用、DAC和模拟链。

DDS、ADSR、LFO按48kHz逻辑采样推进，系统降频本身不应改变音高、音色数学或ADSR时长。
NCO边沿量化的系统时间网格由20ns变25ns；没有据此实测或宣称模拟音质提升/劣化。

## 共享PLL带来的行为变化

本次40MHz系统与25/125MHz视频共用PLL。音频不再独立于该PLL：LOCK低时核心异步复位、
PA_EN静音，锁定恢复后同步释放并重新启动，旧声部状态清除。后续修改视频PLL参数/复位
也可能影响音频，须同步审查。即使时钟来自同一PLL，多位跨域数据仍走已验证握手/邮箱或
适用FIFO，不能直接读其他域的寄存器总线。

已有启动/失锁验证属于仿真；实际上板PLL、模拟静音和恢复行为仍待验证。不得把它写成L6。

## 对新功能与可视化的设计约束

1. 新音频运算先核算最坏II、latency、ROM/BSRAM端口、事件服务和833拍最短帧预算，保留
   接入/混音/提交及安全保护开销；不能只看资源还剩多少或只跑单模块Fmax。
2. 保持音频接受不受视频ready阻塞。指标仪表盘可由软件显示，但真实故障计数/峰值仍需
   FPGA采集，遥测和软件断线不影响音频。软件仪表盘只是设计建议，本文件不实施或扩大授权。
3. 像素时钟不变；轻量视觉通常可在帧快照和常量几何结构上扩展，大量对象/复杂混色/
   分辨率变化必须另核算像素路径、存储带宽与CDC吞吐。不能把现有视频余量当任意扩展保证。
4. 增加流水线须带齐valid、request ID、声部代次、取消/复位和ready握手；不撤回已经背压
   的有效事务，不把旧快照当最新事件。保持原吞吐合同，不能用增加延迟掩盖错误。
5. 每次整合一个功能，先模型/模块/子系统，再一次有界完整构建；验收Setup/Hold/TNS/端点、
   Recovery/Removal、pulse、CDC、引脚、实际参数和固定LOC，不以工具exit0单独判PASS。
6. 当前V0197 Setup+1.279ns、Hold0且零违例，Recovery+0.706/Removal+0.331ns；Hold修复独立于
   降频。L同域Hold uncertainty0.650比旧0.550更严，不能写成“全局实测Hold+0.1ns”。修改后
   的布局/名字可能改变，原INS_LOC必须读回核对，不能直接复制到60K或不同结构。
7. 继续保留PR1014警告、40MHz成功快照和60K回退。只有新功能最坏吞吐证明40MHz不足时，
   再按受控流程讨论并行化或升频，不为追求更高主频重复盲扫PnR。
