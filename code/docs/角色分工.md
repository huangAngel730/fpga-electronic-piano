# 三人团队角色分工

更新时间：2026-09-16。对应决策：D008 三人岗位冻结、D010 软件工作量分担规则、D023 取消板卡与逻辑分析仪编号。

岗位代号 M1、M2、M3 是本项目正式称谓。早期文档中的“硬件一 音频核心”“硬件二 交互板级”“软件 验证自动化”是同一批人的过渡叫法，对应的局部 `AGENTS.md` 已按本文件更新。

## M1 音频算法 验证与竞赛交付负责人

主责方向：FPGA 内的 DDS、波表、ADSR、复音、混音和数字效果算法按软件工作管理，包括算法定义、Python 黄金模型、算法 RTL 行为和逐样本验证。

交付物：

- 各音色与包络的数学定义、定点格式说明和验收阈值。
- Python 黄金模型以及波表、频率控制字和测试向量生成器。
- DDS、ADSR、复音、混音和效果器的算法 RTL 行为描述。
- 与模型逐样本一致的验证记录（登记在 `code/docs/验证记录.md`）和音频分析结果。
- 竞赛报告和答辩材料中与算法、指标和验证相关的部分。

技术决策权：算法数学定义、定点格式、音色结构、验证容差和验收阈值。

一票否决：算法结果与模型不一致，或未完成逐样本验证。

复核对象：M2 的 I2S 数据相位和位宽实现是否符合 PCM 接口约定。

限制：AI 可以承担大部分代码生成，但算法定义和最终验收必须由 M1 独立完成。

## M2 FPGA 技术与系统集成负责人

主责方向：负责把各模块集成为可综合、可收敛、可下载的稳定系统，并兼任技术与集成负责人。

主责模块：

- 时钟、PLL、复位和 `sample_tick` 生成。
- 跨时钟域处理、同步器、握手和异步 FIFO。
- I2S 数字发送、UART 状态通道和调试 GPIO。
- 顶层模块、模块例化关系和公共数据类型整合。
- Gowin 工程、CST 与 SDC 约束、资源规划。
- 综合、布局布线、时序收敛和稳定码流管理。

交付物：

- 可综合顶层工程和约束文件。
- 时钟、CDC、FIFO 和接口时序的专项检查记录。
- 综合与时序报告、资源占用统计。
- 与提交号或标签对应的稳定码流。
- 集成窗口的组织和跨模块联调结论。

技术决策权：时钟与复位方案、CDC 与 FIFO 结构、I2S 实现方式、构建流程和时序收敛标准。

一票否决：时序未收敛，或 CDC 未完成专项检查的合并。

复核对象：M1 算法 RTL 的流水线和资源实现，M3 的引脚约束与顶层端口一致性。

## M3 实体硬件 交互与上板验证负责人

主责方向：负责从供电到测量的整条实体链路，以及输入、串口和仪器自动化相关软件。

主责内容：

- 供电、电平标准、共地关系和接线方案。
- 传感器、ADC、DAC、功放和音频输出链路。
- PCB、焊接、机械结构和连接可靠性。
- 琴键、压力、编码器、光电和距离等交互候选方案实测。
- 示波器、逻辑分析仪、可调电源和音频采集卡的测量。
- 输入驱动、串口协议、仪器控制和数据采集自动化软件。

交付物：

- 接线图、引脚表、电源说明和电平核对记录。
- 候选交互方案的实测数据，含更新率、抖动和延迟。
- 上板验证脚本和采集数据。
- PT8211 与 PCM5102A 输出链路的对比测试结果。
- 仪器测量记录和故障定位结论。

技术决策权：器件选型与接线、电平与供电方案、测量方法和上板验证流程。

一票否决：存在电气安全风险，或电平未核对就上电。

复核对象：M2 的引脚约束与实物接线一致性，M1 的算法上板实证结果。

## 共同责任

- 三人都能解释总体数据流、DDS、ADSR、复音、I2S 和端到端延迟测量方法。
- 公共接口、时钟、复位、位宽、采样率和引脚由 M2 统一发布；M1 提供算法与定点影响，M3 提供输入、电气和实物影响。
- 每个模块至少一名非作者复核。
- **每次上电前**，板上运行的码流版本必须可追踪；**板卡与分析仪不编号**，两套板卡同型号可互换，规则见 `板卡与仪器资源管理.md`（D023，2026-09-16）。
- 每周三方同步核对任务看板、资源使用记录和下周集成窗口。

## 软件工作量过多时的分工调整

按 D010 执行：当 M1 的软件任务积压并影响关键路径时，M2 分担算法 RTL 的流水线划分、资源优化、FIFO、CDC、I2S 和构建工作；M3 分担按键、传感器、串口、仪器控制和数据采集软件。算法数学定义和最终验收仍由 M1 负责，具体规则见 `三人协作执行手册.md`。
