## 曲谱数据合同v1（仅本独立任务）

先支持归一化JSON事件表；“.mid文件导入”可提出为后续工作，不是本轮验收前提。安卓未来
发送同样的归一化曲谱，不依赖手机逐音符实时定时。

```json
{
  "schema": 1,
  "sample_hz": 48000,
  "score_id": 1,
  "events": [
    {"tick": 0, "type": "note_on", "channel": 0, "note": 60, "velocity": 100},
    {"tick": 24000, "type": "note_off", "channel": 0, "note": 60, "velocity": 0}
  ]
}
```

- tick为从曲谱起点计的无符号32位48kHz逻辑采样序号，不是40MHz系统拍号，也不是手机时间。
- 事件按tick非递减排列；相同tick保持文件原顺序，拒绝擅自排序造成NoteOff/On语义变化。
- channel范围0..15，note范围0..127，velocity范围0..127；本阶段只有NoteOn/NoteOff。
- NoteOn velocity0在PC归一化为NoteOff；最终规范表不应保留零力度NoteOn。
- schema/sample_hz/字段缺失、未知字段、非法范围、tick乱序、超容量均明确拒绝，不静默截断。
- 空曲谱不作为正向验收。初版验证容量为512个事件；容量必须在软件、RTL及协议中一致。
  这是本任务新曲谱存储边界，不是修改公共32深度MIDI事件FIFO或正式复音规模。
- 规范化二进制事件记录为8bytes：tick uint32 little-endian、type uint8（本任务0=NoteOn，
  1=NoteOff）、channel uint8、note uint8、velocity uint8。类型码仅属传输文件，不能直接
  假设等于公共64位performance_event_t；不自动分配新的公共事件码或source_id。
- PC与独立验收器按上述顺序/字段逐条校验读回数据；不能只查总长度、CRC或文件名。

## 有线候选协议与接收要求

工作时钟40MHz，低有效复位，UART默认115200 8N1；保持48kHz曲谱时间单位。
115200只用于本独立数据通道，不改现有STAT/MIDI速率。PC不是音频计算通路。

M3先在授权文档内写出可执行的帧格式，再按同一版实现软件/RTL/TB：

1. 帧有同步标记、协议版本、命令、会话/序号、有效长度及CRC，明确端序、CRC算法/覆盖字节。
   只使用一种确定CRC，提供固定黄金向量，PC/RTL独立实现逐帧比对，不用“有校验即可”。
2. 最少包含BEGIN、DATA、COMMIT、ABORT、ACK/NACK以及状态/读回入口。BEGIN声明score_id、
   事件数/总长度、完整曲谱校验；DATA有明确offset/序号；COMMIT必须检查齐套与整包CRC。
3. 分包最大有效载荷初版128bytes、全曲谱最多4096bytes/512事件；BEGIN先检查上限，禁止
   越界写入。重复包要么幂等ACK要么明确NACK，不允许二次追加、漏包COMMIT或无界等待。
4. CRC错、未知命令、版本错、会话/序号错、长度错、乱序/缺包、事件非法都返回可定位错误。
   接收器在损坏/截断后能经ABORT、新BEGIN或确定超时重新同步；超时值明确且受限。
5. 使用暂存和已提交内容隔离，只有完整合法COMMIT才原子发布曲谱。上传失败/ABORT应保持
   已提交旧曲谱；复位可清全部状态，但要在合同中明确。不能依赖“对方不会传错”保证一致性。
6. PC实现ACK等待、有限重试、总超时、错误非零退出；记录实发/实收原bytes、退出码及SHA。
   是否有硬件流控由合同明确，本轮优先分包停等，不能假设UART物理端口有ready信号。
7. 提供读端公开接口用于验证曲谱数量/事件内容，不读私有存储层级当唯一验收证据。
   本阶段不生成自动演奏事件、不注入现有视觉曲谱状态、不改变音频deadline。

物理接口边界：R17当前MIDI输入、U15当前STAT输出，不得复用；V14接板载BL616输出，不能
连接另一个外部推挽TX造成争用。板载BL616/JTAG固件不改。正式有线接口球位/Bank/电平由M2
后续在受控流程安排；当前候选TB用逻辑端口即可，不杜撰接线或默认COM号。

## 正向验收与反例

一个入口须真实运行PC编码及原UART/接收RTL仿真，形成可核对的串行bytes和存储读回证据。
用PC模拟服务或纯Python模型通过只能标软件等级，不能冒称PC→实际RTL已跑通。

正向至少包括：单音、四音同tick、不同力度、同tick Off/On顺序、重复音、多个分包、
512事件上限、非整包尾长、跨包事件字节、旧曲谱更新成新曲谱、ACK/有限重发及错误后恢复。
自检须覆盖正常流程、边界、复位、至少一个异常；逐条验证所有512记录而非只查首尾。

实际损坏反例至少包括：坏CRC、坏版本/命令、长度超限、漏/重复/乱序包、错会话/offset、
错总CRC、COMMIT前缺DATA、非法channel/note/velocity、tick倒序、513事件、空/截断输入、
接收中复位、ACK丢失/超时、取消后新上传。坏曲谱必须不发布且错误可观察。
另外至少两个可编译RTL变异应运行后因具体行为拒收：如错offset写址、漏CRC仍COMMIT。
不得用编译失败、超时或零比较冒充反例成功。

读取数据的独立checker需检查非空记录数、结束marker、逐条内容、原串行输入身份和错误码；
正例/每个反例日志和SHA齐全。捕获/日志不覆盖旧结果，一次运行写唯一忽略output目录。
实际仿真器缺失时交合同与软件/模型证据及明确缺项，不用伪造PASS。Gowin综合/PnR、资源
报表和正式音画整合由M2复核后另安排，本轮不要求重跑V0197或烧录。
