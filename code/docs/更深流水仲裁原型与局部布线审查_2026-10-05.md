## 三段独立仲裁原型

code/tb/common/control_arbiter_deep_pipeline/control_snapshot_selector.sv新增模块，仅处理输入snapshot_mask32、rr5、request_id32/epoch32：

1. E成功request时按rr把候选分成高地址区/回绕低地址区，分别寄存32bit mask；无32bit循环barrelshift链。
2. E+1按四组各8slot计算局部first/second并寄存，两区分开；此阶段只看固定groupbitmap。
3. E+2把四组局部赢家归并，按先高区后低区给first/second和valid，结果进入保持状态；output id/epoch与快照一起冻结。

单事务设计：E→E+2结果valid，输入最小II4clk，busy期间request_ready0；held result在backpressure稳定，只有successful consume/cancel/reset退出。空bitmap也返回result token(first/second_valid0)，可区分没有赢家和没有计算完。cancel同时禁止request/result握手，清在途/held，reset清状态。输入值变化不修改已冻结快照结果。

快照selector不读取pending_value，不更新公共eventFIFO/locked event/cooldown或Modsentstate，不能因模块passed就说MIDI吞吐/1kHz/最新值/原同拍公平已经通过。后续若counterexample取消/新更早slot在深级间出现，需revalidate最终候选并在锁定payload时读取最新值；epochs标记只提供诊断校验能力，不让全局busyupdate引起永久重试。

## 实际验证

python -X utf8 code/scripts/run_control_snapshot_selector.py --output <新output目录>

- Python独立线性RR oracle生成18592组snapshots(32rr原点x581mask)，覆盖empty/full、32onehot、邻接二slot/回绕、两类交替图和512固定随机图。
- 原RTL实际Icarus18592结果，151154断言，E/E+1无prematurevalid、E+2有效、固定mask→正确first/second、id/epoch冻结、间隔>=4、heldbackpressure；三个计算/保持阶段cancel及inflightreset恢复通过。
- 三错误RTL由同检查器编译成功后拒收：高低回绕错、second错误重复first、epoch错1LSB；不是编译失败/超时。
- empty/onevectortruncated非零退出；runner初空EOF处理触发malformed而marker期待counter失败，修正TB scan==-1且feof结束后得到明确count0/1拒收，原失败日志保留；RTL算法在这次入口修复未改。最初生成runner引号未合exit，文件未生成/no sim，保存事实不隐瞒。
- Yosys read_slang/proc/opt通用网表结构检查exit0，205个寄存bit、无latch；不是Gowin映射、不对应实际205 DFF占用保证、没有vendor资源/STA结论。三个register边界真实存在，整个parser需要的额外寄存数量仍待系统设计。

## 深流水正式接入必须解决的合同

独立反例文件integration_semantic_counterexamples.json证明：
- 快照first3/second7后live取消3并新插入1，直接发旧first非法；需候选valid/优先更新政策。
- 同slot值100→900期间pipeline进行，最终事件应在冻结点读最新值，不直接发送snapshotvalue。
- 每byte更新aggregate epoch就取消重试，可连续12次无任何commit，不能作为有界调度方法。
- event_valid1/ready0已呈现FIFOhead被“pipeline busy”门控到valid0违反hold协议；只能在新head呈现前预留机会，或设计review过的outputpresentation register。

建议下一合同方向是独立“调度准备→合法候选确认→事件呈现/消费反馈”分级，并把离散输入FIFO/连续合并与准备结果用稳定接口连接。保持最多8个成功离散握手(以及burst1/16参数配置)的控制服务条件；准备耗时2clk不允许第9个离散成功才让出，也不允许撤回已背压事件。新增presentationbuffer若必要，先说明占用/容量/水位计数和FIFO满同拍pop-push，不隐形加slot或删除满旁路。这里是候选建议，不冻结接口，不写parser来强行实现所有新语义。

不能仅取深pipeline模块E+2+原FIFO就假称正常演奏零副作用；新标签校验/取消/竞态都需真实parser及音频输入联合测试。采样中音频管线已有31clk证据，后续可以用更完整data-controlregisteredstage，但要和最新T027/面板/效果器逐功能融合，不覆盖旧源，不拿旧冻结V0171资源当新整机余量。
