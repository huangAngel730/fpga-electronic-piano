## 执行器判据阻断

原件在输出判定中用 `BAD` 正则筛日志错误，用普通子串检测 `PASS M2_M1TD_REAL_CHAIN_BOARD_FUNCTIONAL_ONLY`。对以下内容代入原判据：

```text
Error: synthetic compile issue
NOT PASS M2_M1TD_REAL_CHAIN_BOARD_FUNCTIONAL_ONLY
```

静态复现得到 `bad_match=False`、`pass_substring=True`。即使某工具进程退出码为 0，只要打印这种失败内容，现行判据可误报通过；这不是一次真实 ModelSim 运行，也不是证明当前 RTL 失败。**M2 不确认原执行器的那次精确 R04 执行，`m2_confirmed` 不得设为 true。**

M1 在自有执行器写集做最小修复：识别工具 `Error:`/`Errors: 1` 等失败诊断，PASS 必须匹配独立整行且排除 `NOT PASS`；用合成退出码 0 的错误日志、假 PASS、无 PASS、退出非零等负例留下命令/退出码/原始双流。修复后补交执行器新字节及 SHA，并重绑预检/确认所指原件；不得默默复用旧 SHA 或一次运行额度。M2 再按新精确字节、工具绝对路径/版本、cwd、独占 stage/output、命令、300 秒单步与 900 秒预算核一次运行准入。若需把“900 秒”写成严格全程硬上限，还需实际覆盖创建/清理与失败收据，不以现有等待预算冒充硬上限。M3 的只读 checker 可并行检查这一负例，不修改 M1 执行器。
