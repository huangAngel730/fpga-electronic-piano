## max_processing_cycles=0不能解释为正常预计算

既定单位是50MHz sys_clk下接受PCM请求边沿至同代次成功缓冲提交边沿的历史最大周期，非MIDI到模拟音频、非提前计算全成本。预计算可降低请求后周期，但源中的WAIT_DISPATCH/SETTLE/ADVANCE/SNAPSHOT/HOLD及结果保持依旧多拍，原RTL UART回归测得11周期；持续122秒声部/提交工作时该值不能长期0。

原发布Gowin综合日志NL0002删除u_latency，层级资源表该延迟计数器无寄存器，顶层u_system_status只剩32 ALU/32 LUT的溢出组合加法。过去将此警告解释为“重复计数器正常优化”缺少保留有效延迟寄存器证据，已被本次实物0值推翻，M2修正原判定。

隔离同源对照：

| 版本 | 改动 | u_latency寄存器 |
| --- | --- | ---: |
| 原交付 | 无 | 0（被删除） |
| 最小显式提交端口 | u_commit新增commit_pulse，core接该端口，不再层次读取内部valid/ready | 65（保留） |
| 仅停重复测量 | 顶层正常模式重复计数输入置0，core仍层次读提交 | 0（仍删除） |
| 组合候选 | 两项都改 | 65（保留） |

因此修复范围可限制在polyphonic_pcm_commit和polyphonic_audio_core的内部连接，测量公式/公共STAT字段/外部引脚不改。独立Yosys/slang综合网表保留原连接，而Gowin删除，说明是工具层次引用综合可观测性问题，非预计算合法的零周期值。

组合候选仅忽略目录：RTL6194项28行STAT仍11周期；完整Gowin50MHz Fmax50.717MHz、Setup+0.283/Hold+0.001/Recovery+13.307/Removal+0.399ns、4873Logic/2670FF/24DSP/8BSRAM，报告门禁PASS。最小显式端口单独已综合保留65寄存器，但没有单独PnR/板级；不可把组合候选的报告冒充最小补丁报告。正式源码、54774f1.fs没改，候选没有下载发布。
