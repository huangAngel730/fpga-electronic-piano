## 四项仍阻断架构决策

### 1. 截止判定使用了错误指标，反例不能有效拒收

原check_deadline仅AVAILABLE(1031)-ii_cycles，完全不读latency_cycles。

| 输入II/Latency | 原结果 | 正确解释 |
|---|---|---|
|1 / 1032|满足，余量1030|输出超可用1031周期，不满足完成截止|
|1031 / 1036|满足，余量0|流启动吞吐恰好，但本请求迟到，不满足完成截止|
|8 / 12|满足|可保留为本简化日历可行，前后处理须明确计入|
|0或−1 /10|满足|非法启动间隔，必须拒收|

应分别判断：请求间隔(最短1041)必须不小于可实现II；从实际接受请求到同一代PCM提交完成的最坏Latency加未包含的前/后处理及保护必须小于等于1041。如果保护已从1041扣10得到1031，就明确Latency含什么，避免双计或漏计。10拍是预算提案，不是已冻结系统接口常数，宜参数化。

独立实际变异：只让全并行(ii=1)Latency增加1,000,000周期，原七自检exit0全PASS；证明目前检查抓不到输出迟到。另一个把所有Latency加大版本因timeshared固定latency==13被拒收(exit1)，该历史如实保留，不混写“所有变异都漏检”。少算voice/漏开销目前只是正确函数和另一个合法输入的数字比较，没有独立期待完整请求日历的故障拒收，应增加迟到/漏最后voice实际输入记录或构造错误评估函数的拒收断言。

架构函数也未调用validate_config：parallel(-1)等能返回资源数字，hybrid(4,8)可直接构造，M=0仅ZeroDivisionError。校验helper单独通过不代表真实公开入口失败关闭。

### 2. 107位状态表仍不对应已签收算法，2DSP无法作事实成本

VoiceState=32phase+32FCW+8velocity+2ADSRstate+16counter+16level+1NoteOn=107，只证明这些数字能求和，不是完整每voice状态。

当前源码证据：velocity接口10位；ADSR内部state3位且7个态(public也5态，2位不足)；Q16的level/start/peak/sustain各32位、step33位、elapsed13位、state3位仅这一组持久ADSR寄存就177位。此177是当前源码状态清单，不是要求重设计必须逐寄存复制，若共享/压缩/重算，应给出重触发/Release连续性和逐sample数学等价依据。

还须分列DDSphase/baseFCW、LFOphase、source/channel/note/generation、occupied/key-down/deferred/releasing、音色/力度、控制快照持有状态。寄存器、RAM、复用运算临时pipeline各一栏，未知映射允许unknown，不擅自用Q15可见level16代替内部Q16精度或减位。

原乘法段采用(sample*velocity_gain*adsr_level)>>30，且描述“两16x16”第二级实际中间32bit输入，与现合同不符：当前包络峰值本来已经包含Velocity，正式gain只执行(sample*envelope)>>15再<<8。额外再乘velocity会改变力度响应/幅度，不是资源估算可以自行简化的步骤；Sustain乘法/事件step预计算/PitchMod查表与乘法另需计入。DSP2可以标某个明确新共享架构的待验证算子数量提案，但不能直接写已收算法需要2DSP/voice或映射上界，原始位宽如何映射硬块未知。

### 3. 混音位宽与端口/存储预算仍矛盾

MixerStructure固定26bit。四PCM24求和数值下限26，但N8/16/32分别至少27/28/29；项目冻结累加统一>=32bit。本预算应沿32bit宽和/末级PCM24饱和，不另改幅度。ResourceCost ff=26*tree_depth还未统计每级节点寄存和持久累加；可先unknown或提供各stage保留节点，不把深度当节点。

原全并行声明N路ROM读、模型resource一直共享2KB；混合M4声明4读口而budget也一直2KB，report又写8KB?。应每方案明确一个可实现的端口假设(物理复制/双口映射/仲裁分时)，并让模型存储与日历一致；不需M1猜Gowin最大口数，不确定写unknown，随后M2选小探针验证。双音色/PitchMod/Velocity各表的访问也需分项，不仅一张正弦表。

报告说32份2KB=64KB“超器件容量”是直接数值错误：报告/模型自己的容量265.5KB，64KB小于265.5KB(约24.1%)。这不证明32份共享方案可行(块颗粒/其他功能/端口/时序仍待)，但不能据此排除全并行。去掉这一错误否定，恢复三种架构比较。

### 4. 运算日历仍只有N+3，缺支撑真实完整功能的操作级依据

II/Latency字段不同是进步，但公式timeshare N+3/N+5、hybrid ceil(N/M)+3/...+5仍未描述每voice状态读取、真实ADSR更新/事件计算、waveROM、FCW/PitchMod、多位增益、写回、累加、最后提交间依赖以及每共享硬单元的可实现II。报告“单声部状态107完整／2DSP保守／deadline全满足”无法独立成立。

先列必要操作/位宽/读写端口与是否可缓存：更新条件=NoteOn/Off/CC64/PitchMod/音色/正常采样，缓存失效与同代标记说明即可；无法给工具latency先作明确配置参数/unknown，不编造数值，不进行新RTL或综合。资源负载、II、Latency及预留项要可追溯到此表，不要求现阶段声称每档实际收敛。
