## P0：本轮必须先修

### 1. `rtl_verifier.py` 失败时仍返回 0

当前 `code/model/rtl_verifier.py` 主入口没有 `sys.exit(...)`，也没有使用
`verify_mixer_rtl()` 的布尔返回值。2026-09-20 实跑结果：

```text
RTL输出目录不存在: rtl_outputs
RTL_VERIFIER_EXIT=0
```

这会让 CI 或批处理把“未验证、失配或异常”当作成功。

整改要求：

- 验证通过返回 0。
- 样本失配、长度不一致、非法 hex、文件不存在均返回非 0。
- 主入口必须显式传播验证结果，不能只打印 PASS/FAIL。
- 增加自动测试，至少覆盖：完全匹配、一个样本失配、长度不一致、非法 hex、缺文件。

### 2. 削波标志没有参与 RTL 对比

当前验证器只比较 `mixer_outputs.txt` 与 `mixer_rtl_outputs.txt`，全文没有读取或比较
`mixer_clipped.txt`。因此即使 RTL 的 PCM 数值碰巧正确、削波标志错误，工具仍会报 PASS。

整改要求：

- 将 RTL 削波标志与参考 `mixer_clipped.txt` 逐样本比较。
- 明确 RTL 削波标志文件的名称和格式，并在工具说明中写清楚。
- PCM 或削波标志任一失配时返回非 0。
- 增加“PCM 相同但削波标志错误”的失败用例。

## P1：与 P0 同一轮完成

### 3. 长度错误的诊断路径不完整

`compare_samples()` 在长度不一致时返回 `error/ref_len/rtl_len`，但
`verify_mixer_rtl()` 没有打印这些字段；`verify_dds_rtl()` 还会直接访问不存在的
`total_samples`，从而触发 `KeyError`。

整改要求：

- 长度不一致时打印参考长度和 RTL 长度。
- mixer 与 DDS 两条验证路径都不能抛 `KeyError`。
- 非法 hex 应报告准确行号和原因；不要把 BOM 或非法字符误报成普通长度错误。

### 4. `generated/` 尚不可重复生成

已确认的问题包括：

- `generate_test_mode_reference.py` 的文本输出未显式固定 LF。
- `tests/test_mixer.py` 生成三个向量文件时同样未显式固定 LF。
- `.gitignore` 与已经跟踪的 `test_mode/*.wav|png`、`timbre/*.wav|png` 存在矛盾。
- 两个 PNG 会随 Matplotlib 版本产生真实字节差异。

整改要求：

- 文本生成统一固定为 LF，符合根目录 `.gitattributes`。
- 明确哪些生成物必须入库、哪些只作为本地产物；同步修正 `.gitignore` 和 manifest。
- 对必须入库的确定性生成物提供 `--check` 或等价校验。
- 依次重跑项目现有模型生成入口后，`git status --porcelain` 必须为空。

## P2：口径和文档修正

### 5. 修正幅度、余量和累加位宽口径

- `audio_defs.py` 第 69 行仍说明波表满幅为 `32767 << 8 = 8388352`，但第 70 行实际常量使用
  `WT_AMPLITUDE = 8192`，即 D028 冻结的 `8192 << 8 = 2097152`。注释与代码公式冲突，
  应统一到冻结工作点；如需保留理论波表满幅，只能作为单独概念明确命名。
- `mixer.estimate_headroom_db(4)` 当前默认得到 `-12.0409358 dB`；按 D028 单声部峰值
  `2097152` 计算应约为 `0 dB`。默认值、注释和测试需统一到冻结口径，或明确区分
  “理论满幅压力测试”和“正式工作点”。
- 正式混音累加器位宽必须遵循接口规范 v1.2：**不少于 32 位**。26/27 位只能作为
  数学最小位宽分析，不能作为正式 RTL 规格。
