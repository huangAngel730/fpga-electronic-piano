## 最差路径

| 指标 | 报告结果 |
|---|---|
| 起点 | `u_simple_voice/note_q_4_s0/Q` |
| 终点 | `u_simple_voice/phase_q_30_s0/D` |
| Setup slack | +1.851 ns |
| 数据延迟 | 17.095 ns（cell 8.960 ns，route 7.753 ns，tC2Q 0.382 ns） |
| 报告逻辑级数 | 21（以 Gowin Timing Analysis Report 的定义为准） |

`Setup Paths Table` 列出的前 25 条最差 Setup 路径全部起于 `note_q_4_s0/Q`，终点分别为 `phase_q` 的不同位（最差到 bit 30）。路径节点依次涉及 `u_note_pitch` 的 semitone/octave/step 逻辑和 `phase_sum` 进位链。源码中 `note_q` 送入组合 `note_pitch`，其 `phase_step` 随后进入 `phase_sum = phase_q + step_q`；这使音符变更到相位寄存器的同周期组合路径较长。这里的归因是基于工具实际路径节点与 RTL 连接的推断，尚未通过结构替换对照实验验证。

## M2 集成时的复测条件

1. M1 交付 T004/T009/T010/T023 的正式 RTL、定点口径和接口时，先核对 Note On/Off 到步进更新的生效采样帧；不能为提高 Fmax 而使音高使用旧步进多一个未声明的音频帧。
2. 在单声部正式 RTL、四声部及混音链分别构建后，记录相同 50 MHz 约束下的最差路径起终点、slack、Fmax、Setup/Hold TNS 和资源；每个阶段均运行模块仿真、逐样本参考比对及顶层 T007 回归。
3. 若仍由音高计算与相位加法共同形成最差路径，评估在事件握手时寄存步进、查表结构或其他流水线。结构选择必须服从 M1 的音高数学定义、PCM 帧请求契约和端到端延迟指标；优化后用 Gowin PnR 报告复测，不以单次静态估算宣称收敛。
4. 当前 UART 诊断版的 Fmax 比旧 MIDI 集成版 60.854 MHz 低；两次布局网表不同，单凭差值不能断言 UART 状态逻辑导致时序变差。当前最差路径证据集中在 `simple_voice`，后续要对比同一 RTL 版本和相同约束下的实验。
