## 未通过：40MHz综合估算时序

原报告要求40.000MHz，但Actual Fmax仅34.739MHz，Slack **-3.786ns**、30逻辑级。
路径`request_session_3_s0` → `reply[25]_4_s10`。这不是40MHz时序通过，
也不是物理STA结果；综合退出0仅说明工具完成。资源映射成立与时序风险分别交付。
源码respond任务将22/30个byte的CRC在单沿组合展开，结合端点判断其为回包CRC长链风险；
这是源/报告推断，尚无分拍修版验证。没有通过降频或假路径消除违例。

交M2的最小修复提案（未实施）：仅在新RAM候选内部将回包CRC拆为有界逐byte状态，
先快照完整回复字段，CRC计算完成后才发TX；重复成功缓存须存最终精确回复，
公开一拍读、COMMIT时序、线上字节、协议/超时保持；需复核session/frame异常优先级。
批准后再做新UART正负/复位回归和获准的新综合/STA。当前不擅自改已验证源或追加综合。

保留8条EX3791位宽截断警告及源行179/220/224/247/286/290/291/325；
任务字段受协议长度/512事件/4096bytes界限限制，不能因此声称无警告。
特别需M2结合非法输入和offset边界复核COPY地址14→13、长度/序号进位的意图；本轮不顺手消警重构。
