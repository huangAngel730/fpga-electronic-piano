## 实现及独立性

新增 `code/software/audio_math_acceptance_candidate/envelope_model.py`：
逐系统时钟复现冻结 `adsr_piano_envelope.sv` 的状态、同步 gain ROM、delta/product 两级寄存、
pending tick、事件优先级、重触发起点、Attack/Decay/Release 边界和 Sustain 乘法流水。
所有寄存器达到固定点后才跳过静默时钟；与逐拍执行的等价自检通过。
模型输入是原 velocity ROM、Note On/Off/tick，**不读取观测 level/envelope/step 作为 expected**。

逐 STATE 先比较 pre-NBA 的九项：raw/public state、level/start/peak/sustain Q16、
signed33 step 的二补码、elapsed、unsigned16 envelope，再推进本沿。
ROM 峰值、13108/32768 Sustain 近似、17895697/894785 reciprocal、所有截位严格复现冻结 RTL，
没有用旧 M1 算法模型替代，也没有修改生产算法来迁就数据。

`timeline.py` 结合既有独立 DDS phase/table，计算 piano ROM 地址 `{table,phase[31:24]}`。
wave 是 signed16；D→H 固定 6 拍，H 实际总线来自 D+5 的 bank snapshot。
同步波表在 D+1 NBA 已读到新地址，包络流水在 snapshot 前稳定；窗口内出现新的 lane 事件会拒收，
不把 H.wave/H.envelope 当期望来源。H 每 lane 波表与包络精确核对后，
独立计算 signed33 `wave*envelope >>> 15`、signed16 结果左移 8 得 PCM24，
只按 Q frozen occupancy 掩码启用 lane，四路 signed32 求和后饱和到 signed24。
实际核心左右使用同一 voices，故 M 左右各与独立结果核对；JSON COMMIT 再按原序与 M 精确绑定。
真实正例无 clipping；饱和及负数 floor 由断言边界自检覆盖，不能称实测发生过削波。

依赖的生产源码、7 ROM、原 capture 全只读，数学来源是冻结 H40 源。
45 源/7 ROM 与 Git `6f3e813` 的身份核验沿用原 runner；收到包的 383 文件前后 SHA 一致，
139 载体 raw/carrier SHA 以及原 Golden 双文件固定 SHA 均通过。
