# T059 后续独立实测步骤（只准备，不执行）

前提：M2复核目标固件/APK，并由用户另行批准具体安装、flash、设备串口或接线动作。
本轮没有该许可，不运行扫描、adb、esptool、串口工具，也不提供自动选端口／首台连接脚本。
两块C3不要求新增团队板卡编号；下面“第一块／第二块”只是本次测试顺序，不是永久资产标签。

## 逐块身份与产物绑定

每次只放一块参与测试，记录其当次BLE完整地址、广播名称、板面照片／可识别信息、
供电情况、实际固件bin SHA、业务commit、SDK/toolchain版本、实际编程记录（仅后续授权时）。
M3-Score-名称末3字节只能辅助选择，不能替代完整地址与人工确认；不要默认连第一项。
若需读MAC/端口身份也属于设备访问，另批准，不在本次准备阶段执行。
另一块执行同一套流程，分别封存，不能拿第一块PASS覆盖第二块。

## 手机权限／扫描／连接

1. 记录手机型号、Android版本/API、APK SHA；后续安装行为另授权。检查蓝牙关闭、权限拒绝时
   客户端正确提示且不绕过权限；API31+验证SCAN/CONNECT，API26～30验证定位权限。
2. 蓝牙打开并授予权限后，手动扫描：10秒停止、最多16目标、显示完整地址；人工选目标。
   t=0启动、t=5停止重启，新scan不得在旧t=10被旧timeout结束，应按新t=15停止。
   若系统权限回调／蓝牙状态延迟，记录实际时点，不把宿主mock时点当真实Handler行为。
3. 连接和服务发现，TX、LOCAL的CCCD订阅成功后才ready；分别记录回调和失败原因。
   连接失败、订阅失败、销毁Activity、重建Activity、扫描失败、旧callback迟到都不得推进旧事务。
4. 断线发生在Write发送中、待ACK中、READ中分别测试。旧session/seq/offset回复不推进新上传；
   重连重新ABORT、BEGIN、全量DATA、COMMIT、STATUS、全部READ，不续接旧分片。

## 桥接收发与ACK级别

先在获批的模拟UART对端环境测试，后续FPGA实际连线必须由M2核电平/引脚并批准。
UART1候选115200 8N1、GPIO4 TX/GPIO5 RX只属于C3端，绝不等于FPGA接线已批准。

| 可观测结果 | 可以证明 | 不能证明 |
|---|---|---|
| GATT Write-with-response callback | BLE传输这一片已接受 | FPGA已接受请求／提交曲谱 |
| LOCAL通知（UUID末0004） | C3本地错误/队列/代次诊断 | FPGA ACK或上传成功 |
| 模拟对端合法ACK/NACK | App＋C3在受控协议模型下的真实收发 | 真实FPGA缓存或播放正确 |
| 实际FPGA按T057回复、全部READ一致 | 对该版真实端到端上传／读回成立 | 音频／播放／整机STA自动通过 |

模拟对端必须显著标注SIMULATED_PEER。TX(UUID末0003)只能透传UART合法回复，桥不自己造FPGA ACK。
记录20B分片、原请求bytes/CRC/session/seq、UART整帧（不得部分前缀先发）、原ACK/NACK与全部读回。
覆盖好帧、CRC坏、NACK、无ACK、重复ACK、旧身份ACK、片段超时、队列忙、UART溢出诊断和恢复。
旧无线发送／物理UART缓冲字节不一定可撤回，区分D040读取代次保护和真正对端session机制。

## UTF-8日志与恢复

在实际App中连续产生ASCII、汉字、emoji的完整日志行，包含真实时间戳／空格／换行；
通过SAF实际导出文件，按原UTF-8 bytes检查<=4,194,304，超限只丢整条、无残缺UTF-8，
incomplete必须被记录，不把超限日志当完整传输证据。超限后UI／事务不得被日志阻塞。
分别测试前台扫描/连接、断开重连、Activity销毁及导出期间的并发回调；记录系统异常和原bytes。

## 结果模板

日期与时区、逐块完整身份、软件commit/固件/APK SHA、手机API/权限、供电与当次接线（如获批）、
模拟还是真实对端、输入文件SHA／事件数、逐条expected/actual、原日志SHA、退出/异常、PASS/FAIL/未测。
没有真实证据就标未测；无线实测、FPGA实际ACK、HDMI和新整机STA分开签收。
