## 四 必须补强的验证证据

### 4.1 复音和合成通道证明

新增一个可重复的压力测试模式，至少输出：

```text
active_voice_count
oscillator_count
sample_rate
clip_count
event_fifo_level
event_fifo_overflow
audio_underrun
```

同时保存：

- 多个不同频率的自动触发序列；
- WAV与频谱图；
- 独立谱峰数量；
- Gowin资源和时序报告；
- 实际I2S采样率。

该项对应 `赛题要求对照表.md` 的G11，建议在W4前形成正式任务。

### 4.2 延迟和抖动证明

测试链路必须覆盖：

```text
真实按键或MIDI输入
-> 事件接收
-> FPGA合成
-> 数字音频输出
-> DAC模拟输出
```

建议用调试GPIO标记事件接收时刻，用示波器测量到模拟音频首次有效变化的时间差，至少记录平均值、最大值、最小值和峰峰抖动。

### 4.3 两种音色证明

对同一音符、同一Velocity、同一包络采集两种音色，保存：

- 时域波形；
- 频谱；
- 算法结构；
- 实时切换过程；
- 切换时是否爆音。

## 五 I2S与LSBJ合规风险

正式赛题和讲解截图使用“I2S接口输出至DAC”的文字。当前板载DAC PT8211使用16位LSBJ，项目接口v1.1和T005已经按LSBJ实现。

这两件事不能混写：

- LSBJ链路可以证明板载DAC能够实时发声。
- LSBJ不是标准Philips I2S数据相位。
- 在未获得赛事口径确认前，不能直接声明“板载LSBJ完全满足标准I2S要求”。

建议M2在W2至W3选择以下安全方案之一：

1. 向赛事或高云技术支持确认题目中的“I2S”是否允许LSBJ兼容格式，并保存书面回复；
2. 让发送器支持可参数化的LSBJ与标准I2S双模式；
3. 保留PT8211板载演示，同时提供标准I2S模式连接PCM5102A作为合规证明。

当前不立即推翻D017和已完成的T005，但把该事项登记为风险R12。

## 六 展示与交付落实

### 文档

M1从开发初期持续收集：架构图、接口时序、黄金模型、波形、频谱、资源、时序、延迟、接线和实物照片。讲解者建议文档尽量不少于10页，但项目以内容完整和证据清晰为准，不把页数当作官方硬指标。

### 视频

M3负责主画面中的实物、操作和仪器，M1准备字幕与指标，M2准备状态输出和测试模式。推荐主画面加画中画，避免用剪辑替代实时性证明。

### 答辩

三人都要能解释：纯FPGA证据、振荡器统计口径、4与32通道区别、定点位宽、I2S或LSBJ格式、延迟测量方法、为什么没有使用预录PCM。
