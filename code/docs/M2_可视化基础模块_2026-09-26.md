## 本次交付

- `code/rtl/common/video_scan_timing.sv`：可配置主动区、前肩、同步宽度、后肩与同步极性。输入 `pixel_clk` 必须由正式显示时钟方案提供，`rst_n` 必须已经在 pixel_clk 域同步释放。输出逐像素坐标、`data_enable`、同步和行/帧起点。不含时钟发生器、TMDS 编码器或任何图像绘制。
- `code/rtl/common/visual_event_bridge.sv`：接受音频系统域**已成功消费**的 `performance_event_t` 副本，参考接法为 `accepted_valid = event_valid && event_ready`。音频侧不等待、不读取显示侧 `ready`。源域 FIFO 深度参数默认为 32，外加一份在途寄存器；队满时只丢**显示副本**，32 位 `visual_drop_count` 饱和累加、`visual_drop_pulse` 单周期指示。同步到显示域的 `video_desync` 是粘滞位；M3 的画面状态机收到它必须清除按键高亮/命中状态，或切换为明确标注失步的界面，避免漏掉 Note Off 后留下假亮键。仅两域共同 `rst_n` 清除此状态。两域复位均异步断言、按各自时钟同步释放；显示停钟不能阻塞演奏。
- `code/tb/common/tb_visual_event_bridge.sv`、`tb_video_scan_timing.sv` 和 `code/scripts/run_visual_m2_sim.ps1`：可重跑仿真，故障覆盖队满/丢弃、显示反压、视频停钟、在途复位、帧边界、消隐与同步极性。扫描模块默认 640×480、800×525 总几何仅作仿真候选，**不代表已冻结实际屏幕视频模式或像素时钟**。

从仓库根目录执行 `.\code\scripts\run_visual_m2_sim.ps1`：三个视频时钟半周期（7、17、41 ns）的事件桥各 8 场景通过；扫描时序两完整默认几何帧、缩小参数几何、正负同步极性和中途复位通过（L2 模块自检）。未跑视频时钟下的独立 Gowin PnR；这一步需要确定真实像素时钟、视频 PHY/TMDS 方案与引脚，并为新时钟编写独立时序约束。验证等级不能从当前单声部音频工程外推。

### CDC 上板前条件

事件载荷为系统域 `payload_hold` 寄存器，持续保持到显示域完成握手并返回同步确认；请求 toggle 用两级触发器同步，显示域捕获的是稳定载荷。最终布局布线必须检查跨域路径：为 bundled-data 路径制定物理时延/偏斜限制，使 64 位载荷全部先于同步后请求到达；不把整条数据路径一概 false path 且不验最长组合/布线延迟。还应检查两个 toggle 同步器的异步路径与两个时钟域的复位释放。若无法证明延迟界限，换经 Gowin 验证的异步 FIFO。单域仿真无法模拟亚稳态，也不能代替硬件 CDC 证据。PLL 失锁必须共同拉低 `rst_n`，不能只重置视频域导致 toggle 协议状态错位。

### M3 接入约定（待用户转发，尚未送达）

M3 在显示域通过 `video_valid && video_ready` 接收一个事件，反压期间 `video_data` 保持。`video_desync` 为 1 时不要继续假定“画面键态等于真实音频键态”，应清画面高亮/按键命中状态并提示失步；恢复需共同复位或后续受控快照同步方案。画面渲染模块读 `pixel_x/pixel_y/data_enable`，不得使用显示处理反压音频事件队列。引脚、屏幕型号、时钟和现场采集结果由 M3 提供给 M2 定最终方案。
