## 实质最小返修：分开ready报告与取消/接受

v4注释称frame取消并禁止同沿接受，但实际wire abort=cancel，RTL中frame_tick只有端口/注释，完全没进入accept/DDS/FSM分支。Python仍abort=cancel||frame_tick且calc_ready在frame时低；两者明显不同源合同。正常提交链在空闲帧可通过，因为其他模块挡住旧PCM，不证明producer帧边界安全。

最小方向：

1. calc_ready报告帧沿新代能力，可按既定合同在frame时允许；不要把它与abort合并拉低到永远request0。
2. 真正接受须明确!frame_tick&&!cancel，即使IDLE有sample_req也不能同帧沿接受/推进。
3. FSM当前frame/cancel分支高于IDLE/CALC/HOLD，清旧valid/context并安排新代；已发生DDS相位推进不得回滚。
4. 模型逐沿ready/accept/frame同口径同步，新增两个本包真实失败case及CALC frame取消/恢复ID短检查。用原commit测试确认request仍可发出；不要改公共commit以绕producer问题。

只改原DUT/model/对应新TB及已有checker/runner/说明授权写集，公共模块/ROM/top/约束保持，原只读实例化授权不变。不需要为了此返修扩大公共源码范围或转M3。常ready及strict改善标已闭合，针对实际新源变化才必要复验。
