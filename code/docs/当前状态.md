  **正式工程 `electronic_piano.cst` 本次未改动，V14 仍保持「禁止采用」**；
  待上板实测确认（`by` 计数增长、`la` 跟上所发字符）后再按 `变更与决策流程.md` 启动解除禁用的变更。
  **【2026-09-18 上板实测定案（V0058，L6）：V14 = 本板 UART RX，LVCMOS33／3.3 V 成立】**
  把 `uart_rx_probe.fs` 经 SRAM 下载（`programmer exit code: 0`，`User Code 0x00007516`）后，
  在板载调试口 **FT2232 通道 B（`COM13`）**读到 250 ms 周期的报告（通道 A `COM9` 全程无数据，即 JTAG 通道）。
  空闲时 A/B 两路都是 `lv=1 ed=0000 by=0000`（两路都空闲高，**此时无法区分「真 RX 空闲」与「悬空内部上拉」**）；
  从 PC 端按 115200 8N1 发 10 个 `0x55` 后：
  **A（V14）= `ed=0064 by=000A la=55 fe=0000 mn=01B0`**、**B（Y14）仍全零**。
  即 **V14 确为本板 UART RX**（10 帧全部正确解出、末字节 0x55、无帧错），
  且**按 LVCMOS33／3.3 V 配置正确**（电平标准若配错则解不出帧，这正是原先无法确定的那一条）；
  **Y14（31002 版映射）在本板不成立，已排除**。
  `PBIT=01B2`=434 拍 = 50 MHz÷115200，**反向佐证板上 `sys_clk` 为 50 MHz**；
  实测 `mn=01B0`=432 拍比理论少 2 拍，等于输入两级同步器的采样延迟，**不是波特率误差**。
  **注意三点**：① 本次驱动源是板载调试器 FT2232 的 TX（3.3 V CMOS），
  **未验证 MIDI DIN 的 5 V 电流环**（正式接入仍必须经光耦隔离），**31.25 kbaud 帧也未测**；
  ② **`electronic_piano.cst` 中 V14 的「禁止采用」本次未解除**——
  该文件属接口组共享文件（D027），解除须先在群里说明再按 `变更与决策流程.md` 走；
  ③ 诊断工程是独立工程（`code/build/probe/uart_rx_probe.gprj`），与正式顶层无关，诊断完可删。
  **顺带补齐的 UART 侧基础**：`rtl/common/uart_tx.sv` 与 `rtl/common/uart_rx.sv` 已入库（参数化 8N1，
  各带自检 TB），**T025 状态通道因此不再需要从零写串口**；顶层的 `assign uart_tx = 1'b1;` 仍待 T025 接管。
- **【已解决】复位引脚 `AA13` vs `Y12`**（2026-09-12 查引脚事实表"冲突与待确认"页关闭）。
  **结论：不存在归属冲突，`sys_rst_n` = `AA13` 正确。**
  `AA13`/`AB13`/`Y12` **三者全是 Bank 9 的用户按键**（真名 EX_KEY.0/.1/.2，
  均 LVCMOS15 低有效、需内部上拉）；官方示例只是把其中一个取别名为
  `sys_rst_n`，另两个叫 `key0`/`key1`。事实表原文定性："**这是用户工程别名，
  不是核心板 RECONFIG 或 CPU_RESET**"。
  **原记录称"错的是引脚号归属，不是电平"不准确——实际是命名别名差异。**
  已按追加规则更正 D018（见该条末尾更正段），并解除 `AA13` 的禁用约束。
  引脚采用见 **D020**。
- **【已解决】器件 `Part Number` 写法与 `PBG484A` 封装名**（2026-09-12 提出，**2026-09-13 定案**）。

  **Sipeed 官方 Wiki 的 Tang Mega 60K 页面给出定案**（"Precautions" 表）：

  > Please select the package model **`PBG484A`** & **Device Version: B** in the IDE.

  即**料号段**写 `PG484A`、**IDE 封装名**写 `PBG484A`，同一句话中并存且不矛盾，
  **两个写法都对，不存在笔误**。**D018 第 2 项据此关闭，仓库现有记录无需改动。**

  PCM5102A 仅限台面**对比测试**与答辩**论证材料**。
