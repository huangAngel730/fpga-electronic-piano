## 下落源码检查：只列候选原因

依据直接SystemVerilog源码分析，不依据CodeGraph索引。

1. visual_score_tracker.sv的calculate_y在到达hit_frame后把距离钳位到0；visual_scene_renderer.sv将其画在JUDGE_Y=400附近，屏幕琴键从KEYBOARD_TOP=410开始。因此下落矩形在琴键上方短暂停留是现有显示规则的一部分。
2. 有duration的诊断音符在effective_frame > hit_frame + duration_frames后释放；当前诊断duration_frames=30。无duration的音符在判定窗口过后标记并释放，存在非阻塞寄存器更新的下一帧边界。不能因单帧停在判定线就认定挂住。
3. 当前25MHz、800×525总时序约59.5238帧/秒，30帧约0.504秒，6帧窗口约0.101秒；这些是源码参数换算，不是视频测量。具体可见停留还受判定/释放边界影响。
4. audio_visual_display_probe.sv的score_hit_frame为score_seq+120（绝对帧），持续握手投递，且score_seq为16位。后续投递的hit_frame是否落后实际current_frame、反复在判定线附近入队/回收，须用生成器与tracker联合TB检查；不能凭本轮文字把它认定为实际故障。

可视化窗口应区分：正常短暂判定停留、诊断发生器过期时间戳引起的重复显示、真正帧计数或槽释放异常。取得原视频后与模式自动切换时段、运动/消失过程对照。若根因在诊断发生器，不改正式曲谱含义来迁就诊断。

## 上飘长条与去琴键：独立候选语义

用户请求“持续按住不断延伸长条，松键后停止生成继续上飘”和“去掉屏幕上的琴键现实”；后一项按“琴键显示”理解。先由可视化窗口落具体语义与范围说明，再实现独立候选，主M2复核后发布实测包。

- 以成功握手Note On打开长条：上端按帧上移，下端保持现有起始基线；对应Note Off停止延伸，此后两端一同上移，完全出屏后回收。
- 长条代表物理按键时长，CC64音频延音不继续生成长条。保持音频已有四声部/包络/力度/踏板行为。
- 用source_id + channel + note_number匹配按放；同身份重触发结束旧条并开新条，避免跨来源或通道误释放。长按头部出屏后仍保留held身份，不能提前忘记按住状态。
- 复位、全局清音和video_desync清除视觉状态。槽位满时明确可视化覆盖/计数策略，不反压音频、不擅自扩容或关闭音符。音频声部抢占不等于键盘Note Off，不能依赖音频槽代替物理身份。
- 删除琴键绘制，保留横向音高位置和现有长条起始基线；本轮不要求改变正式输入协议、音高范围或增加新的菜单。
