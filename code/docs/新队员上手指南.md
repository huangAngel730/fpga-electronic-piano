# 新队员上手指南

更新时间：2026-09-12。面向第一次使用 Git 的队员，从一台空电脑做到能提交代码。阅读顺序见 `code/docs/协作入口.md`，本节只讲怎么把环境接上。

## 一 先用一句话理解这套协作

三个人共用一个 GitHub 仓库。`main` 是稳定版，`develop` 是集成版，每个人在自己的功能分支上干活，干完推上去开一个 PR（合并请求），有人复核后再合进 `develop`。

没有"把文件夹发给队友"这一步。那个做法已经作废，见第八节。

## 二 需要装的东西

| 装什么 | 干什么用 | 怎么确认装好了 |
|---|---|---|
| Git for Windows | 版本控制 | `git --version` 出版本号 |
| 一个 AI 工具 | 写代码和文档 | Codex、Claude Code、Cursor 都行 |
| Python 3 | 黄金模型与文档脚本 | `python --version` 出版本号 |

Python 依赖，用到时再装：

```powershell
python -m pip install python-docx
```

FPGA 工具链（Gowin EDA、Programmer、Icarus、Verilator、Yosys、GTKWave）的版本与安装位置记录在 `code/docs/开发环境.md`。暂时没装也能先读文档、看代码、做评审，不影响接上仓库。

## 三 先让管理员把你加进仓库

这一步必须在 clone 之前完成，否则你推不上去。

1. 让仓库管理员在 GitHub 的 `Settings → Collaborators` 里添加你的 GitHub 账号。
2. 你的账号会收到邀请邮件，也可能在网页右上角出现提示。必须点 Accept invitation，只被添加不接受是没有权限的。
3. 确认方式：网页能打开仓库并看到分支列表。

## 四 把自己的电脑接到仓库

### 4.1 设置提交身份

```powershell
git config --global user.name "你的名字或GitHub昵称"
git config --global user.email "你的GitHub邮箱"
```

这决定每个提交上写谁的名字，第一次用一定要做。

### 4.2 配置 SSH 密钥

远程仓库用的是 SSH 地址，需要先在 GitHub 登记你的公钥。

```powershell
ssh-keygen -t ed25519 -C "你的GitHub邮箱"
```

一路回车，默认保存到 `C:\Users\你的用户名\.ssh\id_ed25519`。私钥不要发给任何人，只把公钥贴到 GitHub：

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

复制输出的整行，打开 GitHub 右上角头像 → `Settings` → `SSH and GPG keys` → `New SSH key`，标题随便填（例如"实验室台式机"），内容粘贴公钥，保存。

验证：

```powershell
ssh -T git@github.com
```

看到 `Hi 你的用户名! You've successfully authenticated` 就成功了。第一次连接会问是否信任主机，输入 `yes`。

### 4.3 克隆仓库

**克隆到纯 ASCII 路径。** 路径里有中文会让 Gowin 的 Tcl 命令行无法打开工程，
详见 `code/docs/开发环境.md`。例如：

```powershell
cd D:\17\project_17
git clone git@github.com:huangAngel730/fpga-electronic-piano.git fpga_gowin
cd fpga_gowin
```

不要用网页上的 Download ZIP。ZIP 里没有 Git 历史，在里面改的代码没有分支、推不上去、也合不进来，等于白做。

如果 SSH 实在配不通，可以暂时改用 HTTPS 地址 `https://github.com/huangAngel730/fpga-electronic-piano.git`，推送时输入用户名和 Personal Access Token，注意不是账号密码。

### 4.4 认识你拿到的分支

```powershell
git branch -a
```

`main` 是稳定版，不要直接提交。你要做的是从 `develop` 拉出自己的分支。

## 六 建自己的分支

命名规则见 `code/docs/Git协作规范.md`：功能用 `feature/<名字>`，修缺陷用 `fix/<名字>`，只改文档用 `docs/<名字>`。

```powershell
git switch develop
git pull
git switch -c feature/你的任务名
```

远程已经有 `feature/model-dds`、`feature/i2s`、`feature/board`、`docs/interface` 几条起步分支，归属看 `code/docs/任务看板.md` 里对应行的主负责人列。不要往队友的分支上推，也不要删或改队友的分支。要新开就取别的名字，或先跟队友确认这条分支归谁。

## 七 每次开工的固定动作

1. 拉最新：`git switch 你的分支`，然后 `git pull`
2. 读规范：按 `code/docs/协作入口.md` 的必读四份过一遍
3. 领任务：在 `code/docs/任务看板.md` 找到自己那一行，确认任务编号、目标分支和验收条件
4. 只改授权目录。需要跨目录先停下来找队友
5. 小步提交：

```powershell
git add 具体文件路径
git commit -m "feat(dds): add 32-bit phase accumulator"
```

提交信息格式是 `类型(范围): 摘要`，类型用 `feat`、`fix`、`test`、`docs`、`build`、`refactor`、`chore`。不要写"update"、"改了一下"这类看不出内容的摘要。

6. 推送：

```powershell
git push -u origin 你的分支
```

第一次加 `-u`，之后直接 `git push`。

7. 开 PR：在 GitHub 上向 `develop` 开合并请求，用仓库里的 `.github/PULL_REQUEST_TEMPLATE.md` 模板填写。至少一名非作者复核后才能合并。

## 九 常见故障

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `Permission denied (publickey)` | SSH 公钥没登记 | 回到 4.2 重配 |
| `remote: Permission to ... denied` 或 403 | 没被加为协作者，或没点 Accept | 找管理员确认，并检查邀请邮件 |
| `Updates were rejected because the remote contains work` | 队友推过新提交，本地落后 | 先 `git pull`，处理提示后重新推送，不要用 `--force` |
| `Your local changes would be overwritten by checkout` | 有未提交的改动 | 先 `git add` 加 `git commit`，再切分支 |
| `fatal: not a git repository` | 当前目录不对 | `cd` 回仓库根目录 |
| `LF will be replaced by CRLF` | 仓库早期未统一换行符时的提示 | 仓库已加 `.gitattributes` 固定为 LF，正常不再出现；若仍出现，执行 `git add --renormalize .` 后提交 |
| 终端里中文显示成乱码 | 终端编码问题 | 文件内容本身是好的，用编辑器打开确认，不要因此重写文件 |
| `git push` 要求输入密码 | 用的是 HTTPS 地址 | 改用 SSH，或用 Personal Access Token 而不是账号密码 |

## 十 绝对不能做

- 不要 `git push --force`，会覆盖队友的提交。要回退用 `git revert` 产生新提交。
- 不要往 `main` 直接推，`main` 只接受来自 `develop` 的合并。
- 不要提交 `.tools/`、安装包、波形（`.vcd`、`.vvp`、`*.out`）、码流（`.fs`、`.bit`）和厂商缓存。
- 不要改公共接口、时钟、复位、数据位宽、采样率、顶层端口和引脚。确有必要先提交影响分析。
- 不要把仿真通过写成上板通过。
- 不要两个人同时改同一个文件，开工前在群里说一声你要改哪几个。
- 不要删队友的分支，不要改队友分支上的提交。

## 十一 个人环境记录放哪里

复制 `code/docs/个人环境模板.md`，改名为 `个人开发环境 姓名.md`。建议放在 `code/docs/local/` 目录下，该目录已被 `.gitignore` 排除，属于个人本地记录，不会进仓库，也不会和队友的配置互相干扰。

如果你确实需要让它进仓库共享，就放到 `code/docs/` 下并按任务单走复核流程。
