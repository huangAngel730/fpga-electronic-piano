## 二、RTL设计规格

### 2.1 T004 DDS设计要点

**接口**:
```systemverilog
module dds_oscillator (
    input  logic        sys_clk,        // 50 MHz
    input  logic        sys_rst_n,      // 复位
    input  logic        sample_tick,    // 48 kHz采样使能
    input  logic [31:0] fcw,            // 频率控制字
    output logic signed [15:0] wt_sample  // 波表输出
);
```

**关键参数**:
- 相位累加器: 32位，自然回绕
- 波表: 1024点，16位有符号
- 波表地址: phase[31:22]（高10位）
- 资源占用: 1个BSRAM（16Kbits）

**时序特性**:
- FCW更新: 在sample_tick时生效
- 输出延迟: 1个时钟周期（BSRAM读延迟）

---

### 2.2 T009 ADSR设计要点

**接口**:
```systemverilog
module adsr_piano_envelope (
    input  logic        sys_clk,
    input  logic        sys_rst_n,
    input  logic        sample_tick,    // 48 kHz
    input  logic        note_on,        // Note On事件
    input  logic        note_off,       // Note Off事件
    input  logic [9:0]  velocity,       // 0-1023
    output logic [15:0] envelope_level, // Q1.15
    output logic [2:0]  state_out       // 状态（调试）
);
```

**ADSR参数**（与Python模型一致）:
- Attack: 240样本（5ms）
- Decay: 4800样本（100ms）
- Sustain电平: 13107（Q1.15的0.4）
- Sustain衰减: 每100样本 × 0.997
- Release: 4800样本（100ms）

**Release重触发实现**:
```systemverilog
if (note_on) begin
    if (state == RELEASE) begin
        retrigger_level <= level;  // 保存当前电平
    end else begin
        retrigger_level <= 32'h0;
    end
    
    state <= ATTACK;
    level <= retrigger_level;
    // 计算从retrigger_level到velocity_gain的斜率
    attack_delta <= ((velocity_gain - retrigger_level[31:16]) << 16) / ATTACK_SAMPLES;
end
```

**资源占用**:
- 1个BSRAM（Velocity ROM，16Kbits）
- 约150个FF
- 约200个LUT

### 2.3 T010 声部管理设计要点

**接口**:
```systemverilog
module voice_allocator_4 (
    input  logic       sys_clk,
    input  logic       sys_rst_n,
    input  logic       note_on,
    input  logic       note_off,
    input  logic [7:0] midi_note,       // 0-127
    output logic [1:0] allocated_slot,  // 0-3
    output logic       slot_valid       // 分配成功
);
```

**分配策略**:
1. **同音重触发**: 查找已有相同音符的槽位，返回原槽
2. **空闲槽优先**: 优先分配IDLE槽
3. **LRU窃取**: 满载时窃取时间戳最旧的槽

**LRU实现**:
```systemverilog
// 每个槽维护16位时间戳
typedef struct packed {
    logic       active;
    logic [7:0] note;
    logic [15:0] timestamp;
} voice_slot_t;

// 全局时间每时钟+1
always_ff @(posedge sys_clk) begin
    global_time <= global_time + 1;
end

// 分配时更新槽位时间戳
slots[allocated_slot].timestamp <= global_time;
```

**资源占用**:
- 约80个FF（4槽×20位状态）
- 约100个LUT（比较逻辑）

## 三、集成接口说明

### 3.1 完整音频链路

```
MIDI事件 → 声部分配器(T010) → [槽位0-3]
                                    ↓
[DDS(T004) + ADSR(T009)] × 4声部 → 4路PCM24
                                    ↓
                             混音器(T023) → PCM立体声
```

### 3.2 时序关系

**采样时钟域**（48kHz）:
```
sample_tick (50MHz系统时钟产生)
    ↓
DDS相位累加 (1周期)
    ↓
波表查表 (1周期BSRAM延迟)
    ↓
ADSR包络更新 (1周期)
    ↓
包络应用 (组合逻辑)
    ↓
混音器 (组合逻辑)
    ↓
PCM输出

总延迟: 约3个系统时钟周期
```

**事件响应**:
- Note On/Off事件在下一个sample_tick生效
- 声部分配在事件触发后1个时钟周期完成

### 3.3 代次管理要求

**问题**: DDS、ADSR、混音器各有不同延迟，需确保同一帧的4个声部在同一时刻混音

**方案1**: 流水线对齐寄存器
```systemverilog
// 在顶层插入延迟匹配寄存器
logic [23:0] voice_pcm [0:3];
logic [23:0] voice_pcm_d1 [0:3];  // 延迟1周期
logic [23:0] voice_pcm_d2 [0:3];  // 延迟2周期

// 将延迟较短的声部延迟到与最长声部对齐
```

**方案2**: 帧请求标识
```systemverilog
// 每个sample_tick产生唯一frame_id
logic [7:0] frame_id;
always_ff @(posedge sys_clk) begin
    if (sample_tick) frame_id <= frame_id + 1;
end

// 每个声部输出携带frame_id
// 混音器仅接受相同frame_id的4路输入
```

**M1建议**: 采用方案1（流水线对齐），更简单可靠

## 五、已知限制与待完成

### 5.1 RTL实现限制

1. **ADSR Sustain衰减简化**
   - 当前实现: 每100样本减去 level >> 8（近似×0.997）
   - Python模型: 精确指数衰减
   - 影响: 长音符尾音衰减曲线略有偏差
   - 建议: 如音质要求高，可改用查表法

2. **DDS相位累加无抖动**
   - 当前: 纯数字累加，无相位抖动抑制
   - 影响: 理论上有量化噪声
   - 建议: 后续可加入相位抖动（Phase Dithering）

3. **声部分配无优先级**
   - 当前: 纯LRU，不考虑音符响度
   - 影响: 大音量音符可能被窃取
   - 建议: 可加入velocity加权的窃取策略

### 8.2 4声部资源

| 组件 | BSRAM | DSP | FF | LUT |
|------|-------|-----|-----|-----|
| DDS × 4 | 4块 | 0 | 128 | 200 |
| ADSR × 4 | 4块 | 0 | 600 | 800 |
| 声部管理 | 0 | 0 | 80 | 100 |
| 混音器 | 0 | 0 | 0 | 100 |
| **总计** | **8块** | **0** | **808** | **1200** |

**器件资源对比**（GW5AT-60）:
- BSRAM: 8 / 118 = 6.8%
- FF: 808 / 59136 = 1.4%
- LUT: 1200 / 59136 = 2.0%

**结论**: 资源占用极低，留有大量余量
