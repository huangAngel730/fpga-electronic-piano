# T025 M2 真实削波计数阶段（2026-09-27）

状态：**独立计数模块与实际 PCM 帧缓冲握手的 L2 自检完成；未接正式电子琴顶层，未切换 `DIAG`→`STAT`。** 本工作属于 M2 的 T025 UART FPGA 状态通道，不扩大 M1 音频算法数学定义或写入范围。

## 实现与计数口径

`code/rtl/common/pcm_clip_counter.sv` 在 50 MHz `sys_clk` 域计数。一组左右声道音频只有当 `pcm_valid && pcm_ready && clip_any` 在同一时钟上升沿同时为 1 才让 32 位 `clip_count` 增加 1；左右同时削波也只计一组。计数饱和到 `0xffffffff`，外部低有效复位异步清零、由上游同步释放。

`clip_any` 必须与将要提交的**同一请求代次、同一左右 PCM** 同时锁存和保持。模块本身没有代次输入；`pcm_ready` 来自 `pcm_frame_buffer`，只在代次匹配且缓存有空间并不处于 `frame_tick` 时才允许提交。生产者需要在帧边界取消过期结果，不能让老的 `pcm_valid` 卡住后续请求；不得在样本计算、串行 I2S 播放、超期结果丢弃或普通 sys_clk 周期加计数。只有真实混音限幅标志、PCM 代次和正式状态行整体连接正确，T025 才有资格输出 `STAT`。

## 验证

从仓库根目录运行 `./code/scripts/run_t025_clip_counter_sim.ps1`（PowerShell：`.\code\scripts\run_t025_clip_counter_sim.ps1`）。脚本用 Gowin OSS CAD Suite 中的 Icarus/VVP，针对 `pcm_mixer_4voice`、`pcm_frame_buffer` 和新计数器构成的链路运行自动判定 TB。实测 **57 项检查 PASS，退出 0（L2）**：未请求时拒收、仅左削波、仅右削波、两侧同时削波、双声道不削波、缓冲满反压、重复有效、旧代次迟到、帧边界同拍拒收、正确代次恢复提交、连续削波、三位缩小计数器达到 7 后饱和、32 位计数值和 `pcm_commit_count` 同步、异步复位及复位后重新计数。三位验证只用于快速覆盖饱和边界，正式参数为 32 位。

脚本只读取 M1 模型定义过的混音器 RTL，不修改 `code/rtl/mixer/` 或接口组四文件。`code/tb/common/tb_pcm_clip_counter.sv` 使用真实组合混音器和实际 PCM 帧缓冲 `pcm_ready` 判断“提交”，不是在 TB 中伪造 ready。该 L2 结果不包括正式 DDS/ADSR/四声部逐帧声部调度，也不包括实际 UART 串口或上板。
