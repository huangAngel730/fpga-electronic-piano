# M5Stack Unit MIDI 连接器使用方法

日期：2026-09-25  
适用设备：MIDIPLUS X4 III、M5Stack Unit MIDI（SKU：U187）、Tang Mega 60K + NEO Dock  
用途：把 X4 III 的 5 针 MIDI OUT 安全地转换成 FPGA 可以接收的 3.3 V 串行 MIDI 信号。

> **当前状态说明：**本文给出的是经过官方资料和本项目板卡资料核对后的接线方案，但还不是已经完成的实物验收记录。正式接线前仍要用万用表确认 Unit MIDI 实物的电源和 UART_TX 电平，并由 M2 提供已经把 `midi_input` 接入正式顶层的码流。

## 零、Unit MIDI 到底是什么？

**Unit MIDI 是 M5Stack 生产的一块 MIDI 接口与音频合成模块，产品型号为 U187。**它不是一根普通转接线，也不只是改变插头形状的“转接头”。模块内部带有光耦隔离电路、MIDI 信号路由电路和 SAM2695 音频合成芯片。

可以把它理解成放在 X4 III 和 FPGA 中间的“翻译与保护盒”：

```text
X4 III 发出标准5针MIDI电流环信号
                 ↓
       Unit MIDI负责隔离和整形
                 ↓
       输出3.3 V UART串行信号
                 ↓
          FPGA才能安全接收
```

它主要有三种能力：

| 能力 | 通俗解释 | 本项目是否使用 |
| --- | --- | --- |
| MIDI IN隔离接收 | 把电子琴的5针MIDI信号安全转换成UART信号 | **使用，这是购买它的主要原因** |
| MIDI路由/转发 | 根据Bypass/Separate开关决定INPUT、OUTPUT和Grove之间怎样连接 | **使用Bypass接收键盘数据** |
| SAM2695音频合成 | 模块自己可以把MIDI音符变成声音，从自己的耳机口输出 | 可以单独试音，但**不作为FPGA项目最终声音** |

### 它在你的电子琴项目里处于什么位置？

你的系统里有两个容易混淆的“电子琴”：

1. **MIDIPLUS X4 III**：负责让人演奏，发送按键、音符、力度等MIDI信息，本身是控制器；
2. **FPGA电子琴**：接收MIDI信息，在FPGA内部完成声部、DDS、包络、混音和音频输出。

Unit MIDI夹在两者中间，只负责把信号安全送进去：

```text
演奏者
  ↓
X4 III（产生MIDI信息）
  ↓
Unit MIDI（隔离、转换、保护）
  ↓
Tang Mega 60K FPGA（解析MIDI并生成声音）
  ↓
PT8211和底板音频口（输出项目声音）
```

### 为什么不能只用一根线直接连接？

X4 III 的 DIN MIDI OUT 是标准 MIDI 电流环，FPGA 的 R17 是3.3 V数字输入。二者电气形式不同，直接相连既不能正确接收，也可能损坏硬件。Unit MIDI里面的光耦先把键盘和FPGA电气隔离，再输出适合数字电路处理的UART信号。

### 它不是什么？

- 它不是USB转串口模块；
- 它不是只改变接口外形的无源转接头；
- 它不是FPGA，也不会运行本项目的Verilog代码；
- 它自己的SAM2695声音不等于FPGA产生的声音；
- 它不能代替M2完成FPGA顶层连接、CST和码流；
- 接上它以后仍然要由FPGA的 `uart_rx` 和 `midi_event_parser` 解析MIDI数据。

## 一、这块模块在项目中负责什么？

X4 III 后面的 5 针 MIDI OUT 不是普通 3.3 V UART，而是 MIDI 电流环，不能直接接 FPGA GPIO。Unit MIDI 内置 MIDI IN 光耦隔离和信号整形，可以把它转换成 FPGA 能接收的串行逻辑信号。

本项目使用的方向是：

```text
X4 III 琴键
    ↓
X4 III 后面板 DIN MIDI OUT
    ↓ 5 针公对公 MIDI 线
Unit MIDI 右侧 INPUT（DIN 5 针母座）
    ↓ 模块内部光耦隔离和整形
Unit MIDI Grove 白线 UART_TX（3.3 V 逻辑输出）
    ↓
Tang Mega 60K 的 R17 输入
    ↓
uart_rx：31250 bit/s、8N1
    ↓
midi_event_parser
    ↓
统一演奏事件、声部、PCM、PT8211 音频输出
```

Unit MIDI 自带 SAM2695 合成器和音频插座，但本项目最终声音应从 Tang Mega 60K 底板的 PT8211 音频链路输出。听到 Unit MIDI 自己的音频，不能证明 FPGA 音频链路已经工作。

## 二、模块上的接口分别是什么？

| 接口 | 用途 | 本项目是否使用 |
| --- | --- | --- |
| 右侧 `INPUT` DIN 5 针母座 | 接收外部 MIDI 设备发送的数据 | **使用，接 X4 III MIDI OUT** |
| 左侧 `OUTPUT` DIN 5 针母座 | 把 MIDI 数据继续送给其他设备 | 暂时不用 |
| 左右两侧 3.5 mm MIDI 插座 | DIN MIDI 的 TRS 替代接口 | 暂时不用；不能当普通音频口 |
| 3.5 mm AUDIO/耳机输出 | SAM2695 内部合成器的模拟声音 | 可作模块自身检查，但不作为 FPGA 输出 |
| HY2.0-4P Grove | 5 V 供电、GND、UART_RX、UART_TX | **使用** |
| Bypass/Separate 拨动开关 | 选择 INPUT、OUTPUT、Grove 与合成器之间的路由 | 本项目接收 X4 III 时先用 **Bypass** |

### 为什么优先使用 5 针 DIN？

X4 III 有标准 DIN MIDI OUT，Unit MIDI 也有 DIN MIDI INPUT。直接使用标准 5 针 MIDI 公对公线最清楚，不会混淆 TRS-MIDI 的 Type A/Type B 接线，也不会把 3.5 mm MIDI 口误当成音频口。

## 三、Grove 四根线的定义

M5Stack 官方页面给出的线色定义为：

| Grove 线色 | 官方名称 | 相对 Unit MIDI 的方向 | 本项目连接方法 |
| --- | --- | --- | --- |
| 黑色 | GND | 地 | 接 Tang 板确认过的 GND |
| 红色 | 5V | 模块电源输入 | 接稳定 5 V 电源，**不能接3.3 V** |
| 黄色 | UART_RX | Unit MIDI 输入 | 接收方案暂时不用，保持悬空 |
| 白色 | UART_TX | Unit MIDI 输出 | 接 FPGA 的 `midi_rx_async` 输入 |

这里最容易弄反：

```text
Unit MIDI UART_TX（白线） → FPGA UART_RX
```

因为 Unit MIDI 把收到的琴键数据“发送”给 FPGA，所以要用模块的 TX 接 FPGA 的 RX。

### UART_TX 是不是 3.3 V？

官方原理图显示：

- 模块由红线输入 5 V；
- 板上 `SE8533X2-HF` 产生 `MCU_VDD`；
- SAM2695 使用 `VD33`；
- MIDI IN 光耦 `TLP2361` 的逻辑输出侧由 `MCU_VDD` 供电。

因此官方 U187 原理图对应的 UART 逻辑侧是 3.3 V。为了防止收到其他硬件版本或兼容板，第一次连接 FPGA 前仍要实测白线电压。

## 四、与 Tang Mega 60K 的推荐接线

### 4.1 FPGA 输入脚

本项目已经上板确认可用的外部 3.3 V 输入候选是：

```text
FPGA 球位：R17
底板网络：PMOD0_IO5 / SDRAM1_D4
J9 位置：第 8 脚
J14 位置：第 5 脚
电气标准：LVCMOS33 / 3.3 V
```

推荐优先走方便插杜邦线的 J9：

| Unit MIDI | Tang Mega 60K NEO Dock | 作用 |
| --- | --- | --- |
| 黑线 GND | J9 第3脚或第4脚 | 共地 |
| 白线 UART_TX | J9 第8脚，也就是 R17 | MIDI 串行数据进入 FPGA |
| 红线 5V | 独立、稳定的 5 V 电源 | 给 Unit MIDI 供电 |
| 黄线 UART_RX | 不连接 | 当前只接收键盘数据 |

也可以用 J14：

| Unit MIDI | J14 | 作用 |
| --- | --- | --- |
| 黑线 GND | 第12脚 | 共地 |
| 白线 UART_TX | 第5脚，也就是 R17 | Unit MIDI 从白线发出数据，R17 把数据输入 FPGA |

> **危险提醒：J14 第11脚是 5V_Peripheral，第12脚才是 GND。两脚相邻，极易插错。第一次接线优先使用 J9，不要把 J14 第11脚当成地或普通 IO。**

### 4.2 为什么不接板上的调试串口，而使用 R17 接收 MIDI？

这里最容易产生歧义：**R17 并不是开发板上固定的“硬件 UART RX 接口”**。R17 原本是一只普通 FPGA GPIO；本项目通过顶层端口和约束，把它配置成 MIDI 接收输入，代码中可以把这个输入命名为 `midi_uart_rx`。

开发板原有的 BL616 调试串口则是另一条独立通道，主要用于 FPGA 与电脑之间传输调试信息：

- **V14 不能接 Unit MIDI。** V14 与板载 BL616 的推挽输出相连。Unit MIDI 白线 `UART_TX` 也是输出；两个输出接在一起可能产生电气冲突。
- **U15 也不是 MIDI 输入。** U15 是 FPGA 向 BL616／电脑发送状态信息的输出，代码中对应 `uart_tx`。
- **R17 才是本项目选定的 MIDI 输入 GPIO。** Unit MIDI 的白线 `UART_TX` 接到 R17，数据方向是“Unit MIDI 发出，FPGA 接收”。

请按下面的“发送方 → 接收方”理解，不要只看引脚名称中的 `TX` 或 `RX`：

```text
电子琴 MIDI OUT
    → Unit MIDI 的 MIDI INPUT
    → Unit MIDI 白线 UART_TX（发送端，31250 bit/s）
    → FPGA R17（普通 GPIO，在本项目代码中作为 midi_uart_rx 接收端）

FPGA U15（uart_tx 发送端，115200 bit/s）
    → 板载 BL616
    → 电脑串口调试工具
```

因此，这是两条完全不同的通信通道：

| 通道 | FPGA引脚 | FPGA方向 | 波特率 | 用途 |
| --- | --- | --- | --- | --- |
| 电子琴 MIDI 输入 | R17 | 输入 | 31250 bit/s | 接收 Unit MIDI 白线发出的按键数据 |
| 电脑状态输出 | U15 | 输出 | 115200 bit/s | 把 FPGA 状态发送给电脑 |

**本项目实际接线结论：Unit MIDI 白线 `UART_TX` 接 R17；黄色 `UART_RX` 暂不连接；V14 和 U15 都不要接到 Unit MIDI 白线。**

### 4.3 Unit MIDI 的5 V从哪里来？

最稳妥的方法是使用一个 Grove 转杜邦/接线端子板，由独立 USB 5 V 电源给红线和黑线供电，再把黑线与 Tang 板 GND 共地。

不要这样做：

- 不要把红线接 J9 的3.3 V；
- 不要把红线接 FPGA GPIO；
- 不要在不确认针号时直接使用 J14 的5 V；
- 不要同时从两个5 V电源给 Unit MIDI供电；
- 不要带电插拔杜邦线。

## 五、Bypass 和 Separate 怎么选择？

官网说明：

- `Bypass`：INPUT 与 OUTPUT 直通，同时 Grove 侧可以接收 INPUT 的 MIDI 信号；
- `Separate`：INPUT 与 OUTPUT 分离，外部控制器可以分别监听输入和向合成器/OUTPUT发送数据。

本项目目前只有一个方向：

```text
X4 III → Unit MIDI → FPGA
```

因此先把开关拨到 **Bypass**。M5Stack 官方的“接收端/SLAVE”示例同样要求接收端使用 Bypass。以后若要让 FPGA 从黄色 UART_RX 主动发送 MIDI、控制 SAM2695 或独立驱动 OUTPUT，再讨论 Separate 模式。

建议断电后再改变拨动开关，避免切换瞬间产生难以判断的数据。

## 六、第一次连接前必须做的电气检查

### 第一步：全部断电接好模块供电

1. X4 III、Unit MIDI、Tang 板全部断电；
2. Unit MIDI 开关拨到 Bypass；
3. 红线接稳定5 V；
4. 黑线接电源GND；
5. 暂时不要把白线接 FPGA。

### 第二步：只给 Unit MIDI 上电并测白线

万用表使用直流电压档：

1. 黑表笔接 Grove 黑线 GND；
2. 红表笔接 Grove 白线 UART_TX；
3. 没有 MIDI 数据时，UART 空闲通常应接近3.3 V；
4. 如果测到接近5 V、负电压、明显不稳定或无法判断，停止接线；
5. 确认不超过3.3 V逻辑范围后，再关闭电源。

万用表只能确认大致电压，不能证明31250 bit/s数据正确。条件允许时，用逻辑分析仪进一步检查。

### 第三步：断电连接 FPGA

1. 先接 Unit 黑线到 J9 GND；
2. 再接 Unit 白线到 J9 第8脚 R17；
3. 黄色 UART_RX 不接；
4. 最后分别给 Unit、X4 III 和 FPGA 上电。

## 七、完整使用步骤

### 7.1 准备物品

- MIDIPLUS X4 III；
- X4 III 的 USB 供电线和电源；
- 5 针 DIN 公对公 MIDI 线；
- M5Stack Unit MIDI U187；
- 随模块附带的 HY2.0-4P Grove 线；
- Grove 转杜邦/接线端子转接板；
- 稳定的5 V供电；
- 杜邦线；
- 万用表；
- 建议准备逻辑分析仪。

### 7.2 键盘设置

第一次测试建议把 X4 III 调整为：

- MIDI通道1；
- 八度偏移归零；
- TRANS移调归零；
- SCALE关闭；
- 力度曲线使用Normal；
- Pitch回到中间；
- Mod放到最低。

这些设置可以让收到的音符更容易与按键位置对应。

### 7.3 连接顺序

```text
1. 全部断电
2. Unit MIDI 拨到 Bypass
3. X4 III MIDI OUT → Unit MIDI 右侧 INPUT
4. Unit 黑线 GND → Tang J9 第3或第4脚
5. Unit 白线 UART_TX → Tang J9 第8脚 R17
6. Unit 红线 → 独立5 V
7. Unit 黄线不接
8. X4 III 用USB供电
9. Tang板按原有安全顺序供电开机
10. 下载M2提供的、已经集成midi_input的正式码流
```

> 仅有 `midi_input.sv` 文件并不代表正式顶层已经使用它。若顶层没有把 R17 接到 `midi_rx_async`，接线正确也不会发声。必须使用 M2 完成顶层、CST、工程文件和全流程检查后的码流。

## 八、通信参数

FPGA接收器使用：

```text
波特率：31250 bit/s
数据位：8
校验位：无
停止位：1
简称：31250、8N1
空闲电平：高
```

M5Stack 中文网页规格表写了 `31520 bps`，但这是笔误。M5Stack 官方驱动源码明确写着：

```cpp
#define MIDI_BAUD 31250
```

标准 MIDI 1.0、现有 FPGA RTL 和官方库都使用 **31250**，不能把RTL改成31520。

50 MHz系统时钟下：

```text
50000000 / 31250 = 每个MIDI位1600个系统时钟周期
```

## 九、先用逻辑分析仪检查原始 MIDI 数据

在正式接 FPGA 前，也可以先这样测：

| 逻辑分析仪 | Unit MIDI |
| --- | --- |
| GND | 黑线 GND |
| CH1 | 白线 UART_TX |

解码设置为 UART 31250、8N1。把 X4 III 设为 MIDI通道1，按下中央C时可能看到：

```text
90 3C 64
```

含义是：

- `90`：通道1的Note On；
- `3C`：音符60，中央C；
- `64`：十进制100的力度。

实际力度会随按键轻重变化。松键可能发送：

```text
80 3C xx
```

也可能发送：

```text
90 3C 00
```

两者都可以表示松键。由于 X4 III 是二手机，必须以实际抓包为准，不能把上面的示例抄成实测结果。

## 十、接入 FPGA 后应该观察什么？

### 第一阶段：只证明串口收到字节

正常情况：

- `uart_frame_error_count` 保持0；
- 按键时 `midi_rx_busy` 出现活动；
- 逻辑分析仪能解码出 `90/80` 等状态字节。

### 第二阶段：证明 MIDI 解析正确

正常情况：

- `parser_error_count` 不持续增加；
- 按一个键，事件 FIFO 产生一条Note On；
- 松开同一键，产生Note Off；
- 轻按和重按得到不同Velocity；
- 多键同时按下时产生多条独立事件。

### 第三阶段：证明完整电子琴链路

正常情况：

- Tang板3.5 mm音频口发出对应音高；
- 松键后声音停止；
- 同时按四键时能听到四个音；
- UART状态中帧错误、解析错误和FIFO溢出不增加；
- Unit MIDI自身音频口是否出声不作为FPGA验收依据。

## 十一、常见问题

| 现象 | 优先检查 |
| --- | --- |
| 完全没有数据 | X4是否从MIDI OUT接到Unit INPUT；Unit是否5 V供电；开关是否Bypass；是否共地 |
| 逻辑分析仪能看到跳变但不能解码 | 必须设31250而不是31520；检查8N1、信号极性和地线 |
| FPGA一直报帧错误 | 白线电压、R17约束、共地、UART参数和接线长度 |
| 字节正确但没有事件 | 检查MIDI通道、解析器、Running Status和顶层连接 |
| 事件正确但没有声音 | 检查声部分配、PCM、I2S/PT8211和功放使能，不要再怀疑MIDI线 |
| 音高整体高或低 | 重置X4 III的八度、TRANS和SCALE设置 |
| Unit有声音但Tang板没声音 | Unit的SAM2695和Tang音频链路是两套系统，继续检查FPGA顶层和音频链路 |
| 连接后器件发热或电压异常 | 立即断电，重新确认5 V、3.3 V、GND和J9针号 |

## 十二、严禁事项

- 严禁把 X4 III 的 DIN MIDI OUT 直接接 FPGA GPIO；
- 严禁把 Unit MIDI 红色5 V线接到3.3 V引脚；
- 严禁把可能为5 V的逻辑信号直接送入R17；
- 严禁把Unit的UART_TX和FPGA输出脚相连；
- 严禁使用V14作为本次外接MIDI输入；
- 严禁把U15状态输出和R17 MIDI输入混为同一串口；
- 严禁在通电状态下改变杜邦接线；
- 严禁仅凭“听到Unit自身声音”就宣布FPGA MIDI链路通过；
- 严禁在M2尚未发布正式顶层和码流时自行修改官方CST接线试验。
