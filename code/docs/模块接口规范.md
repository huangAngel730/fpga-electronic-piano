## 一 适用范围

本文件是 M1、M2、M3 及各自 AI 实现正式模块时必须遵循的公共接口基线。初始 v1.0 由 M2 根据项目目标直接确定，不设置额外会议或签字门槛。

后续如果需要修改字段、位宽、握手、时钟、复位或 I2S 格式，必须先更新技术决策记录并列出受影响模块，由 M2 负责发布新版本。未发布新版本前，所有实现继续遵循 v1.0。

## 二 时钟 复位与采样节拍

### 2.1 基线时钟方案

- 正式音频通路使用单一内部 `sys_clk`。
- 音频算法通过 `sample_tick` 时钟使能更新，不把 `sample_tick` 当成时钟。
- I2S 的 BCLK、LRCLK 和移位过程由 `sys_clk` 下的时钟使能驱动，第一版不把输出 BCLK 作为普通 RTL 内部工作时钟。
- 板载振荡器频率和 PLL 输出频率由 M2 在板级资料核实后确定，但不得改变本文件的接口语义。
- 外部异步输入必须经过同步器、握手或异步 FIFO，禁止直接跨时钟域使用多位总线。

正确示例：

```systemverilog
always_ff @(posedge sys_clk) begin
    if (!sys_rst_n) begin
        phase_acc <= '0;
    end else if (sample_tick) begin
        phase_acc <= phase_acc + phase_step;
    end
end
```

禁止使用：

```systemverilog
always_ff @(posedge sample_tick)
```

### 2.2 复位

- 顶层外部复位名为 `rst_n`，低有效。
- 外部复位允许异步拉低，但必须在目标时钟域同步释放。
- 同步后的系统复位建议命名为 `sys_rst_n`。
- 每个真正独立的时钟域必须使用本域复位同步器，不直接跨域共享同步后的复位。
- 复位期间 `event_ready=0`、`pcm_valid=0`，I2S 数据输出为 0，状态计数器按模块说明清零。

### 2.3 sample_tick

- `sample_tick` 由 M2 在顶层统一生成和分发。
- `sample_tick` 频率为 48 kHz，每个采样周期只拉高一个 `sys_clk` 周期。
- `sample_tick=1` 的上升沿表示开始计算下一组左右声道样本。
- 音频核心在该上升沿取用已经进入事件 FIFO 的事件，更新 DDS、ADSR、声部和效果器状态，并启动本采样流水线。
- 每个 `sample_tick` 最多产生一组左右声道 PCM，且必须在下一个 `sample_tick` 到来前完成 `pcm_valid/pcm_ready` 握手。
- 未按时交付样本时，I2S 重复上一组有效样本，同时增加 `audio_underrun`；复位后尚无有效样本时输出 0。

## 三 统一演奏事件

### 3.1 事件结构

公共事件固定为 64 位：

```systemverilog
typedef struct packed {
    logic [2:0]  event_type;
    logic [3:0]  source_id;
    logic [3:0]  channel;
    logic [6:0]  note_number;
    logic [9:0]  velocity;
    logic [9:0]  expression;
    logic [7:0]  control_id;
    logic [11:0] control_value;
    logic [5:0]  reserved;
} performance_event_t;
```

合计位宽：

```text
3 + 4 + 4 + 7 + 10 + 10 + 8 + 12 + 6 = 64 bit
```

第一版中 `reserved` 必须写 0。不得用保留位私自传递模块内部状态。

### 3.2 字段语义

| 字段 | 语义 |
|---|---|
| `event_type` | 事件类型，编码见下一节 |
| `source_id` | 输入来源编号，例如按键、UART、MIDI 或传感器适配器 |
| `channel` | 逻辑演奏通道或 MIDI 通道，范围 0 至 15 |
| `note_number` | MIDI 音符号，范围 0 至 127，60 为中央 C |
| `velocity` | 10 位线性触发强度，范围 0 至 1023 |
| `expression` | 10 位连续表情上包络量，范围 0 至 1023 |
| `control_id` | 控制项编号，编码见 3.2.1 |
| `control_value` | 与 `control_id` 配对的 12 位值，解释方式由 `control_id` 决定，见 3.2.1 |
| `reserved` | 保留，固定为 0 |

MIDI 7 位 Velocity 映射到 10 位时使用：

```systemverilog
velocity_10bit = {velocity_7bit, velocity_7bit[6:4]};
```

### 3.2.1 control_id 编码与 control_value 解释

`control_id` 固定编码如下，未列出的编码值保留，第一版不得使用：

```systemverilog
localparam logic [7:0] CTRL_PITCH_BEND     = 8'd0;
localparam logic [7:0] CTRL_MODULATION     = 8'd1;
localparam logic [7:0] CTRL_VOLUME         = 8'd2;
localparam logic [7:0] CTRL_PAN            = 8'd3;
localparam logic [7:0] CTRL_PITCH_RANGE    = 8'd4;
localparam logic [7:0] CTRL_VOICE_SELECT   = 8'd5;
localparam logic [7:0] CTRL_EFFECT_DELAY   = 8'd16;
localparam logic [7:0] CTRL_EFFECT_MIX     = 8'd17;
```

`control_value` 按 `control_id` 采用两种解释之一：

| `control_id` | `control_value` 解释 | 中心点 | 范围 |
|---|---|---|---|
| `CTRL_PITCH_BEND` | **有符号二进制补码** | **0** | -2048 至 2047 |
| `CTRL_MODULATION` | 无符号 | 最小值 0 | 0 至 4095 |
| `CTRL_VOLUME` | 无符号 | — | 0 至 4095 |
| `CTRL_PAN` | 无符号，2048 为中置 | 2048 | 0 至 4095 |
| `CTRL_PITCH_RANGE` | 无符号，单位半音 | — | 0 至 24 |
| `CTRL_VOICE_SELECT` | 无符号音色编号 | — | 见 3.3 节音色编号 |
| 其他 | 无符号 | — | 0 至 4095 |

Pitch Bend 的完整定义：

- `control_value` 为 **12 位有符号二进制补码**，**中心点为 0**，不是 2048。
- 无弯音时必须输出 **0**，不得输出 -1 或 1。
- 正值升高音高，负值降低音高。
- 默认弯音范围为 **±2 半音**（与 MIDI 默认一致）。该范围由 `CTRL_PITCH_RANGE` 以半音为单位改写，合法范围 0 至 24。
- 音高偏移量的计算方式（由 M1 在算法内实现）：

```systemverilog
// bend_semitones 为 CTRL_PITCH_RANGE 当前值，缺省 2
// 12 位有符号归一化到 [-1, 1]，再乘弯音范围
pitch_offset_semitones = $signed(control_value) * bend_semitones / 2048.0;
// 定点实现时用乘法再右移，具体小数位由 M1 给出说明
```

- 12 位分辨率在校验后确认为充分：±2 半音范围内每单位约 0.098 音分，远低于人耳可辨阈值（约 5 至 10 音分），因此不需要扩展字段位宽。

MIDI 14 位 Pitch Bend 映射到本接口：

```systemverilog
// MIDI 中心为 8192，范围 0 至 16383
// 先减去中心再右移 2 位，得到 12 位有符号值
// 校验：(16383 - 8192) >>> 2 = 2047，恰好为 12 位有符号上限，不会饱和
//       (0     - 8192) >>> 2 = -2048，恰好为 12 位有符号下限
control_value = $signed({1'b0, midi_bend_14bit} - 15'd8192) >>> 2;
```

该映射用满 12 位全量程，无需饱和逻辑。校验结果见 `验证记录.md` 的 V0006。

### 3.3 事件类型

```systemverilog
localparam logic [2:0] EVENT_NOTE_ON         = 3'd0;
localparam logic [2:0] EVENT_NOTE_OFF        = 3'd1;
localparam logic [2:0] EVENT_AFTERTOUCH      = 3'd2;
localparam logic [2:0] EVENT_PITCH_BEND      = 3'd3;
localparam logic [2:0] EVENT_CONTROL_CHANGE  = 3'd4;
localparam logic [2:0] EVENT_ALL_NOTES_OFF   = 3'd5;
```

编码 6 和 7 保留。

### 3.4 Note On 与 Note Off

Note On：

- `velocity` 合法范围为 1 至 1023。
- 分配空闲声部；没有空闲声部时按声部抢占策略处理。
- ADSR 进入 Attack。
- 相同 `source_id + channel + note_number` 再次收到 Note On 时，第一版重新触发已有声部，不重复分配新声部。

Note Off：

- 匹配 `source_id + channel + note_number` 对应的声部。
- 声部进入 Release，不立即清零。
- `velocity` 可表示松键速度，第一版允许忽略，但不得改变 Note Off 语义。

输入适配层收到 Note On 且 Velocity 为 0 时，必须在进入公共事件 FIFO 前转换成 Note Off。音频核心不接收 Velocity 为 0 的 Note On。

`EVENT_ALL_NOTES_OFF` 用于异常恢复和演示前清空挂音，使所有活跃声部进入快速 Release 或安全静音流程。

### 3.5 valid ready 握手

接口固定为：

```systemverilog
input  logic               event_valid;
output logic               event_ready;
input  performance_event_t event_data;
```

- 当 `event_valid && event_ready` 在同一个 `sys_clk` 上升沿为 1 时，事件完成一次传输。
- 发送方在握手完成前必须保持 `event_valid=1` 且 `event_data` 不变。
- 接收方 FIFO 未满且不在复位时拉高 `event_ready`。
- 复位期间 `event_ready=0`。
- 不建立 `ready -> valid -> ready` 的组合环路。

### 3.6 事件 FIFO

- FIFO 深度固定为 32，后续只有在实际报告支持下才调整。
- FIFO 满时使用输入侧反压，即 `event_ready=0`，正常流程不丢弃事件。
- 不允许通过丢弃最老事件解决满状态，因为可能丢失 Note Off 并造成挂音。
- 上游必须保留未完成握手的事件；不能反压的外部协议适配器必须自带本地缓存。
- 若上游违反握手规则，模块拒绝该次写入并增加 `event_fifo_overflow`，不得静默丢弃。
- 至少保留 FIFO 当前水位、历史最高水位和溢出计数，供 UART 状态输出使用。

深度 32 的定量依据（2026-09-12 补注）：

- 连续控制无法填满：单一控制源限速 1 kHz，折合每采样周期 0.0208 个事件，填满 32 深度需要 1536 个采样周期（约 32 ms）。
- 突发场景以和弦齐按为主：双手同时按下 16 键产生 16 个事件，占用 16 个深度；32 深度对常见 10 键和弦有约 3 倍余量。
- 排空时间可接受：事件按每个采样周期取用一次，排空满 FIFO 的上界为 32 个采样周期，即 0.667 ms，占 5 ms 延迟目标的 13%。
- 反压后果可接受：FIFO 满时输入侧暂停，演奏者感知为短暂无响应，不产生挂音。若改为丢弃最老事件则可能丢失 Note Off 造成挂音，现场演示风险更高，故维持禁止丢弃的策略。
- 详细推导与延迟预算分解见 `验证记录.md` 的 V0005，复算脚本为 `code/scripts/analyze_event_fifo_budget.py`。

该结论在算法侧流水线拍数和输入去抖时间确定后需要复核，届时按本节开头规则以实际报告为准调整。

### 3.7 连续控制参数

第一版继续使用统一的 `performance_event_t`，不新增第二套公共接口：

- Note On 和 Note Off 每个事件都进入 FIFO。
- Control Change 在值发生有效变化时进入 FIFO。
- Pitch Bend 和 Aftertouch 在输入适配层限速并合并，同一控制项尚未发送的新值只保留最新值。
- 单一连续控制源的事件更新速率不得超过 1 kHz。
- 传感器可用更高采样率采集和滤波，但不能按原始 ADC 采样率向事件 FIFO 写入。

## 四 PCM 音频样本接口

### 4.1 接口

```systemverilog
output logic signed [23:0] pcm_left;
output logic signed [23:0] pcm_right;
output logic               pcm_valid;
input  logic               pcm_ready;
```

- PCM 固定为 24 位有符号二进制补码整数。
- 最小值为 -8388608，最大值为 8388607，静音值为 0。
- M1 可以在算法内部使用带小数位的定点格式，但交付 PCM 前必须完成有说明的舍入和饱和。
- 禁止使用无说明的低位截断或回绕溢出。
- 混音累加使用至少 32 位；效果器需要更宽时由 M1 给出定点说明，M2检查资源和时序。

### 4.2 PCM 握手

- 一组 `pcm_left` 与 `pcm_right` 共用一个 `pcm_valid`。
- 当 `pcm_valid && pcm_ready` 在 `sys_clk` 上升沿为 1 时，该组样本被 I2S 侧缓存接收。
- M1 侧在握手前保持 PCM 和 `pcm_valid` 不变。
- 每个 `sample_tick` 最多完成一次样本交付。
- I2S 侧必须提供至少一组样本缓存，串行移位期间不能直接读取正在变化的算法输出。

## 五 I2S 输出格式

> **v1.1 修订（D017）**：数据相位由标准 I2S（Philips）改为 **LSBJ
> （LSB 对齐 / 日本格式）**，以匹配板载 **PT8211** DAC 的实际格式。
> v1.0 的相位描述会使每个样点被错位锁存、输出噪声。
> 依据：`code/docs/PT8211_V1.7_E_数据手册.pdf`（PTC 原版手册），
> 决策见 `技术决策记录.md` 的 D017。
> **本节的 BCLK 频率、帧结构、采样率与位宽均未改变。**

第一版固定为 FPGA 主机模式、**LSBJ** 格式：

| 项目 | 固定值 |
|---|---|
| 采样率 | 48 kHz |
| 声道数 | 2，左声道和右声道 |
| 每声道槽位 | 32 bit |
| 有效 PCM | 24 bit（内部）；**送出前转换为 16 bit** |
| 每帧 BCLK 数 | 64 |
| BCLK 频率 | 3.072 MHz |
| LRCLK 低电平 | 左声道 |
| LRCLK 高电平 | 右声道 |
| 位序 | MSB first |
| **数据相位** | **LSBJ：每声道 16 位有效数据右对齐，LSB 落在该声道槽位的最后一位，紧贴 LRCLK 跳变沿** |
| 槽位填充 | 该声道槽位的前 16 位为填充，后 16 位为有效数据 |

槽位结构（以左声道槽位 32 bit 为例）：

```text
bit31                          bit16 bit15        bit0
[         16 位填充（忽略）        ][   16 位有效 PCM  ]
                                      ^
                                      LSB 紧贴 LRCLK 跳变沿
```

> **注意与 v1.0 的差别**：v1.0 是"LRCLK 翻转后延迟 1 个 BCLK 输出 MSB"
> （数据左对齐，MSB 在前）。v1.1 是**数据右对齐，LSB 贴边**。
> 在 64 BCLK/帧下两种相位的数据位置**相差 15 个 BCLK**。

### 5.1 24 位到 16 位的转换（新增）

内部链路维持 24 位 PCM（见第四节）。板载 PT8211 是 **16 位** DAC，
因此 M2 在 I2S 发送器内负责转换：

- **舍入**：截断会引入直流偏置并恶化量化噪声，应采用舍入（加半个 LSB 后取高位）。
- **饱和**：转换前必须限幅到 16 位范围，不得回绕。
- 抖动（dither）是否引入由 M1 决定；如引入须登记决策。
- 转换后的 16 位结果按 LSBJ 右对齐输出。

### 5.2 时序余量（依据 PT8211 手册核算）

| 约束 | 手册要求 | 本项目 | 余量 |
|---|---|---|---|
| Fbck | ≤ 18.4 MHz | 3.072 MHz | 5.99× |
| Fws | ≤ 384 kHz | 48 kHz | 8.0× |
| tH | ≥ 25 ns | 162.8 ns | 6.51× |
| VIH | ≥ 1.8 V | 3.3 V (LVCMOS33) | - |

M2 负责 BCLK、LRCLK、DATA、左右声道、位序、LSBJ 右对齐、
24→16 位舍入与饱和；M1 只交付并行的 24 位 `pcm_left` 与 `pcm_right`。

是否输出 MCLK 由实际 DAC 或板载音频器件决定，不属于 v1.1 公共 PCM 接口。需要 MCLK 时由 M2 在板级实现并更新约束。**PT8211 不需要 MCLK**（手册引脚仅 BCK/WS/DIN）。

## 六 状态与错误接口

各子系统至少提供或汇总以下状态：

- `active_voice_count`
- `clip_count`
- `event_fifo_level`
- `event_fifo_high_watermark`
- `event_fifo_overflow`
- `audio_underrun`
- `max_processing_cycles`

UART 文本字段名称一经实现保持稳定，由 M2 维护。计数器应采用饱和或明确回绕策略，不能只输出难以捕获的一周期脉冲。

## 七 固定结论

| 项目 | 当前结论（v1.1） |
|---|---|
| 事件总位宽 | 64 位 |
| Velocity | 10 位线性，范围 0 至 1023 |
| Note On Velocity 0 | 输入适配层转换成 Note Off |
| FIFO | 深度 32，标准 valid ready 反压 |
| 满 FIFO | 正常不丢事件，违规发送增加溢出计数 |
| 连续控制 | 使用统一事件，入 FIFO 前限速和合并 |
| Pitch Bend | 12 位有符号补码，中心点 0，默认 ±2 半音 |
| control_id 编码 | 见 3.2.1，未列出值保留 |
| PCM | 24 位有符号二进制补码 |
| I2S | 32 位槽位，24→16 位有效，LSBJ 右对齐 |
| 复位 | 低有效，异步拉低、同步释放 |
| sample_tick | 48 kHz 单周期新样本计算请求 |
| 内部时钟 | 单 `sys_clk` 加时钟使能 |
| I2S 格式责任 | M2 |

## 八 版本修改规则

v1.0 发布后，任何成员或 AI 都不能单方面改变接口。**2026-09-16 起不再有功能分支（D025）**，因此原「在自己的功能分支中」这个限定已无意义——接口改动一律先提提案，不得先改后补。

修改流程：

1. 在 `技术决策记录.md` 新增提案，说明原因和影响范围。
2. 同步修改接口文档、公共类型和测试桩，不先改功能模块。
3. M1提供算法与定点影响，M3提供输入或实物影响，作为评估信息而不是发布前置签字。
4. M2根据集成、资源和时序影响决定是否发布 v1.1 或 v2.0。
5. 受影响模块在同一集成窗口完成适配并运行全回归。
