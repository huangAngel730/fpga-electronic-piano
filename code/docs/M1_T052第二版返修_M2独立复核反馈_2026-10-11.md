## 真实阻断问题

### 1. 原TB未进入有效仿真

原runner：脚本exit1，内部iverilog exit6。直接独立编译同一原TB也exit6，具体为第116行`8'd(10+i)`和第121行`8'd(i%256)`非法SV语法。

修法不能把8bit缩减合同永久保留：先恢复原任务32bit request ID，再用正确类型赋值或SV sized/type cast。若只定位语法，`8'(expression)`是sized cast形式，`8'd(expression)`不是；恢复完整ID后需补32bit回绕/重复/代次断言。驱动仍在posedge有竞态，应负沿驱动、NBA后检查。

### 2. COMMIT取消仍发布

第122行只检查`state==COMMIT && !cancelled`，不看当前cancel。M2短TB在采样之后、COMMIT前负沿置cancel，下一边沿`result_ready=1 id=22`，实际sim1命中`V2_COMMIT_CANCEL_PUBLISHED`。原PROCESSING非同沿通过不能代此边界。

修复需使用当前cancel/frame优先处理所有计算/提交/held阶段；取消同沿不得接受新请求或发布旧结果，不等注册cancelled下一拍再决定。不能回滚已发生的相位推进。

### 3. cancel/sample同沿的RTL与模型状态不一致

第90行DDS tick是`sample_request && state==PROCESSING && !cancelled`，没有当前cancel，因此cancel与sample同沿时RTL推进lane0 phase到25165823（本诊断FCW），结果被取消；Python先更新cancelled立即返回IDLE，相位仍0。M2实际捕获与模型独立探针明确不一致。

只改一个输出valid不能闭合。按原契约确定接受/取消/推进优先级，并让模型按相同旧状态/NBA口径表示；已经接受且发生的推进不回滚，frame边界禁止接受/消耗旧代。原任务是sample_req&&calc_ready接受一次请求，不应再要求另一独立采样脉冲才能执行同一请求。

### 4. result_ready方向错误，仍无消费者背压

第20行把`result_ready`定义为输出有效脉冲，原任务是producer result_valid/output、consumer result_ready/input。没有消费者ready口和held状态。M2短TB实际观察结果沿=1、下一沿=0，sim1命中`V2_RESULT_NOT_HELD_NO_RESULT_READY_INPUT`，不是消费者完成了握手。

结果必须在未握手时保持ID/PCM/活跃数稳定且valid持续；背压不产生重复推进/重复clip计数。禁止用输出脉冲替换原协议。

### 5. PCM24/混音合同被删减，clip变成错误阈值

本版只输出四个16bit原波表值，删除mixer实例和PCM24左右通路；8bit ID、3bit活跃数也偏离原批准32bit口径。缺enable/frame_tick，全mask只能当输入mask局部测试，不等于完整接口。

clip_any第130行改为某lane绝对值>=0x7F00，正弦8192幅度不会触发此阈值；这不是原wide mix的正负饱和结果。M2四lane同时8192真实捕获clip=0，而原PCM24定义先左移8、宽位和为8388608，应该夹到8388607并clip=1；sim1命中`V2_PCM24_POSITIVE_SATURATION_NOT_REPORTED`。这是**原授权混音合同缺失的反证**，不是本版新16bit阈值算法自身计算错。

应复用原pcm_mixer_4voice，由四lane符号扩展/左移8得到24bit，原polyphonic_pcm_commit正常提交链处理最终PCM和clip按一次成功提交统计；不要另造7F00削波口径或修改旧mixer。若需统一局部衰减，按原任务明确模型与数学，不悄改幅度。

### 6. 原TB仍无独立数学或行为变异拒收

TB只是等待输出、检查v0在signed16固有范围、写一行capture并success_count++。不比较黄金lane/phase/PCM、ID等于接受ID、mask对应活跃数；即使编译修好和计数>=4096，也不能称>=4096数学通过。无原commit 1041/1042帧/零额外欠载、held背压、正负饱和或至少两份真正可编译错误实现。

请求场景名440/880/1760/3520，但FCW04B17E4D/0962FC9A/12C5F935/258BF26A按48000Hz原定义实际约880/1760/3520/7040Hz；上一轮已提频点错位，本版仍差一倍。这只是数学控制字换算，不是板测FFT。

### 7. runner仍可能假绿且布局/证据不齐

原授权布局中run_tb.py在code/tb/audio/t052_polyphony，DUT在code/rtl/audio；第50行却在runner同目录找DUT，原样canonical layout脚本exit1/源缺失，扁平包能找源不代表声明布局能用。

第114–115行只见PASS字符串就success=True，第175行以success决定程序exit0；没有同时要求VVP退出0、完整capture、数量及独立比较。M2**软件stub探针（非RTL运行）**模拟VVP exit1/FATAL、带PASS串但没有capture，函数实际返回success=True/exit_code=1，误收复现。报告不能把此stub称真实仿真反例。

TempDirectory退出后capture/日志被删除且正文只打印尾部，没有持久全日志/命令/退出码/工具身份/原SHA收据；本包无交付清单或真实RTL证据。runner需唯一用户输出目录、拒覆盖、超时、原始日志持久化、exit0与完整模型比较/计数联合判定。编译text模式也应显式UTF-8。
