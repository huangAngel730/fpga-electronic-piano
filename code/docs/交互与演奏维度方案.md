## 一 赛题原文要求

## 二 方案选型与合规性论证

### 2.1 候选方案

| 方案 | 交互载体 | 维度来源 | 工期风险 | 演示直观性 |
|---|---|---|---|---|
| A 全自研键盘矩阵 | 自建机械结构 | 自建扫描与力度检测 | 中 | 高 |
| **B 电子钢琴式 MIDI 交互** | **已购 X4 III（49 键），卖家称附延音踏板** | **琴键力度＋Pitch/Mod 触控条＋延音** | **低** | **高** |
| C 外购键盘硬件 + 自研扫描 | 外购键盘总成 | 自研扫描与力度算法 | 低 | 高 |
| D 电容触摸 / 光电 / 手势 | 自研传感器 | 自研传感器 | 高 | 中 |

### 2.2 选定方案：B

选定 **方案 B：以电子钢琴为主演奏形态，使用已购 MIDIPLUS X4 III 与卖家所称附送的延音踏板；通过 MIDI OUT 接收演奏消息，在 FPGA 侧转换为统一事件**。官方手册确认力度琴键、Pitch/Mod 触控条、MIDI OUT、SUS 和 EXP 接口；实物及实际消息均待核实。

选择理由：

- **电子钢琴演奏逻辑自然**。钢琴主模式以琴键力度与延音为核心；键盘已有的 Pitch/Mod 触控条仅在拓展表情展示模式使用，不额外加摇杆。
- **自研交互仍需证明**。不能把外购键盘内部传感器写成自研；本项目自行实现 MIDI 接收、事件映射、踏板状态、音高/颤音控制与声部保持/释放。仅购买 MIDI 键盘是否满足赛题“自研交互”仍有评审风险。
- **工期风险最低**。两个月内，把时间投在算法与合成引擎上比投在机械结构上收益更高，而算法正是本赛题的核心评分点（实时多音色合成引擎）。
- **力度天然满足基础要求的第二维**。带力度键盘直接提供 velocity，无需自行设计力度检测机构。
- **演示直观**。键盘形态评委一眼可识别，交互意图无需解释。

### 2.3 本方案中仍属自研的部分

选择外购键盘不等于交互侧没有工作量。以下部分由本项目自行设计与实现：

| 自研内容 | 归属 | 说明 |
|---|---|---|
| MIDI 接收与解析 | M3 | UART 采样、字节流同步、运行状态解析、实时性保证 |
| MIDI 到统一事件转换 | M3 | 依据接口规范 3.2 节映射到 `performance_event_t` |
| 连续控制器限速与合并 | M3 | 满足接口规范 3.7 节的 1 kHz 限制 |
| 维度划分与映射策略 | M3 | 决定哪些 MIDI 控制器承载哪个演奏维度 |
| Pitch/Mod/SUS 采集 | M3 | Pitch Bend、Mod（预期 CC1）、SUS（预期 CC64）需实物抓包；EXP 可选 |
| 和弦识别 | M1 | 依据同时进入的 Note On 判定 |
| 拨弦判定 | M1 | 依据力度与触发包络特征 |
| 全部合成算法 | M1 | 与交互解耦 |

**技术要点**：MIDI 是 31.25 kbaud 的异步串行协议，需要处理起始位检测、字节边界同步、运行状态（running status）压缩、以及 3 字节消息的原子性。这些不是"直接可用"的现成功能，属于交互适配层的实际工作量。

### 2.4 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 键盘 MIDI 输出电平为 5 V | 可能损坏 FPGA IO | 接入前必须确认电平；5 V 时加分压或电平转换 |
| 键盘使用 USB-MIDI 而非 UART MIDI | 无法直接接入 | 采购时确认具备标准 MIDI OUT 或可引出 UART TX |
| MIDI 31.25 kbaud 的采样与同步 | 解析错误导致丢音 | UART 采样率取 16 倍过采样，加帧错误与溢出计数 |
| 力度来自键盘内部，映射曲线不可控 | 力度听感受限于键盘 | 在适配层做曲线重映射，不改变键盘原始输出 |
| 键盘延迟未实测 | 影响 R11 灵敏稳定 | T036 实测端到端延迟 |

## 三 演奏维度定义

本项目明确区分**演奏操作**与**演奏表情**。琴键位置承担选音、触发与和弦，不重复计入拓展三维表情。按 X4 III 官方面板能力，三维拓展路线改为力度、Pitch Bend、Modulation；延音作为钢琴主模式的额外表情。硬件具备控制器不等于 FPGA 已实现效果，实际消息必须抓包确认。

### 3.1 演奏操作：琴键选音、触发与和弦

| 项目 | 内容 |
|---|---|
| 物理来源 | MIDI 键盘按键位置 |
| MIDI 消息 | Note On / Note Off |
| 事件字段 | `note_number`、`velocity` |
| FPGA 行为 | 音高选择、声部触发/释放、同时多键和弦 |
| 表情计数 | 不计入拓展三维表情 |

X4 III 为 49 键；FPGA 音符号接口仍覆盖 MIDI Note Number 0～127。琴键位置不计入三维表情，和弦须由多个同时活跃声部实测证明。

### 3.2 表情维度 1：按键力度 Velocity

同一琴键可以轻弹或重弹，力度与音高可独立变化。MIDI 7 位 Velocity 扩展为 10 位，控制声部增益、ADSR 峰值，并可进一步控制音色亮度或敲击瞬态。Velocity 0 的 Note On 必须转成 Note Off。实物需测量有效级数、分布和重复性。

### 3.3 表情维度 2：Pitch Bend 滑音/弯音

面板 Pitch 触控条在拓展模式控制 DDS 频率控制字。确认实际消息为 MIDI Pitch Bend、中心点、范围和松手回中，再按现有 `CTRL_PITCH_BEND` 映射。钢琴主模式默认不使用该控制。

### 3.4 表情维度 3：Modulation 颤音

面板 Mod 触控条在拓展模式控制 FPGA LFO 颤音深度，不能仅解析控制消息而没有可听见的周期调制。预期控制消息为 CC1，但必须抓包确认设备实际设置。钢琴主模式默认关闭颤音。

### 3.5 钢琴主模式的延音踏板

卖家称附送延音踏板，官方手册确认键盘有 SUS 接口。到货后核对实物、按下/松开极性和实际 MIDI 消息（预期 CC64）。踏板按下时保持已松键声部，踏板松开时使其进入 Release；需区分 `key_down` 与 `sustain_hold`，避免挂音和声部槽耗尽。只有捕获可靠中间值并完成响应后才允许声明半踏。

### 3.6 可选 EXP/弱音

X4 III 的 EXP 是**表情踏板输入接口**，不代表卖家附送了 EXP 踏板，也不证明默认消息为 CC11 或可以映射 CC67。弱音踏板从近期必购降为可选；若将来需要更钢琴式表情，先确认接口兼容性和实际 CC，再决定是否购买与开发。

### 3.7 维度与要求的对照

| 赛题要求 | 覆盖情况 | 承载方式 |
|---|---|---|
| R1 ≥2 个独立可控维度 | 方案覆盖，待实测 | 琴键选音/触发 + Velocity 力度 |
| R2 选音 | 方案覆盖 | MIDI Note Number |
| R3 触发 | 方案覆盖 | Note On / Note Off |
| R4 和弦 | 方案覆盖，待多键实测 | 多个同时活跃声部 |

## 四 需实测的指标

以下指标必须在 T036 实测，不得凭估计写入对外材料：

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 按键到事件延迟 | ≤2 ms（FPGA 侧） | 逻辑分析仪测 MIDI 字节到达到 `event_valid` |
| 键盘到发声总延迟 | ≤10 ms，目标 ≤5 ms | 见下方说明 |
| MIDI 解析正确率 | 100%，无丢字节 | 长时间连续演奏，检查帧错误与溢出计数 |
| 力度分辨级数 | ≥16 级 | 逐级按压记录 velocity |
| 力度重复性 | 同力度偏差 ≤10% | 同一力度重复 30 次 |
| 连续控制更新率 | ≤1 kHz | 受接口规范 3.7 限制 |
| 和弦识别同时性窗口 | 待定 | 依据人手生理极限，建议 30 至 50 ms |

**关于总延迟**：使用外购 MIDI 键盘后，延迟链路增加两段本项目不可控的环节。

- MIDI 串行传输：一条 3 字节消息在 31.25 kbaud 下约需 0.96 ms。
- 键盘内部扫描与力度检测：**待实测**，不同型号差异明显，是总延迟的主要不确定项。

因此本方案的总延迟**部分取决于所选键盘**，不能仅由 FPGA 侧决定。T036 必须实测"按键到发声"的完整链路，不能只测 FPGA 侧。若实测总延迟超出 10 ms 基础要求，应对措施包括：在适配层缩短缓冲、优先选用延迟较低的键盘型号。

**与接口规范的衔接**：Velocity 已有事件字段，Sustain/Soft 的 `control_id` 尚未冻结；需先按公共接口流程提出变更，再同步包定义、接口文档、MIDI 解析 TB 与声部状态机 TB。本文件只冻结交互方向，不直接改公共接口。连续踏板值若存在，仍须遵守单一控制源不超过 1 kHz 的限速与合并规则。

### 5.1 公共事件接口影响

现有 `performance_event_t` 可承载 Note On/Off 与 Velocity，公共包已定义 Pitch Bend 和 Modulation 的控制编码，但 MIDI 解析器目前只输出 Note On/Off。Sustain 控制编号与取值语义须由 M2 先走受控接口变更流程；Soft 本轮不新增。M3 负责 MIDI/踏板输入，M1 定义力度、滑音、LFO 颤音和踏板声部保持算法。`expression` 字段本轮不重新定义。

### 5.2 滑音和颤音定位

滑音与颤音由 X4 III 的 Pitch/Mod 触控条驱动，在拓展展示模式中**计入三维表情**；钢琴主模式默认关闭。解析出控制消息不等于效果完成，必须有可听结果和上板证据。这里的“滑音”先指按 Pitch Bend 连续弯音；若要实现音符间自动滑移（Portamento），须另行定义，不能把两者当作同一功能。

#### 5.2.1 利用现有键盘控制器的实施顺序

| 阶段 | 主责与可执行工作 | 通过条件 |
|---|---|---|
| 输入实证（可先做） | M3 分别操作 Pitch 与 Mod 触控条，保存带操作说明的原始 MIDI 消息；核对 Pitch Bend 的中心、两端和松手回中，核对 Mod 是否为 CC1、值域及归零行为。USB MIDI 抓包只能证明键盘输出，DIN→隔离模块→R17 的数据仍需另验。 | 原始消息能逐次对应操作；未抓到的消息类型、范围或回中行为一律标为待核实。 |
| FPGA 事件适配（保底档不受阻） | M3 按已核实的消息在 `midi_event_parser` 输出 Pitch Bend／Mod 统一事件，考虑 running status、实时字节插入和连续控制限速；M2 复核事件编码、公共 FIFO、系统时序与资源。现有公共包已有事件类型及控制编码，本阶段不预改受控接口。 | 模块 TB 对真实或等价字节流逐事件比较；连续输入无错位、无静默丢弃，50 MHz 时序复测。 |
| 合成效果（S5 保底档通过后） | M1 定义弯音范围、中心与音高映射，及 FPGA LFO 的速率、深度和重置行为；M2 集成并优化时序。音频效果由 FPGA RTL 产生，电脑监视器只保存输入证据。 | 固定音高时 Pitch 回中音高恢复；Mod 从零到非零时频谱或音高曲线出现可测的周期调制，归零后消失；提供逐样本/容差测试与上板听测。 |
| 拓展验收 | M3 在正式码流上分别录制 Pitch/Mod 控制前后音频与原始消息，M2 复核版本、时序和资源。 | 同一版本的输入消息、RTL 输出与可听/可测效果对应；不得只凭触控条存在或 GUI 数值变化宣称滑音、颤音已实现。 |

**排期门槛**：本项沿用《八周排期与里程碑》的 D019 加分档与固定降级顺序。W5 的 S5 保底档验收前，M3 可以先抓现有键盘消息，M1/M2 可做不挤占保底关键路径的接口与模型准备；正式 FPGA 效果实现与加分验收仅在保底档通过后启动。若 W5 结束仍未通最小闭环，按 D019 取消加分项；不占用 W7/W8 的报告与提交时间。

## 六 硬件与接线待确认项

以下必须在接线前核实，不得直接连接：

- 官方手册列有 MIDI OUT，但仍需核对到货实物和插座形式，并确认仅 USB 供电时 MIDI OUT 是否工作。
- MIDI 输出电平，**待核实**。标准 MIDI 为电流环，需光耦隔离并转换为 3.3 V UART 电平；若为 5 V UART 输出，接入 FPGA 前必须分压或电平转换。
- 与开发板 IO Bank 电压的匹配关系，**待核实**，见 `板级硬件事实.md`。接入前核对 I/O Bank 电压与引脚容限。
- 最终占用的 FPGA 引脚编号与约束文件，**待核实**，需与 M2 的约束同步更新。
- 官方手册说明 USB 可供电；实际供电方式、功耗和 MIDI OUT 同时工作状态仍需实测。
