起草日期：2026-09-12。方案冻结日期：2026-09-20。起草人：M2。

本文件回答一个问题：在两个月工期内，做什么样的演奏交互，既能满足赛题基础要求（≥2 个独立可控维度）和拓展要求（≥3 维表情调控），又不至于做不完。

## 一 赛题原文要求

基础要求原文：

> 系统依托电容触摸、光电感应、压力检测、无接触手势等**任意自研交互方案**，实现至少 2 个独立可控演奏维度的动作采集，精准识别选音、和弦、触发、拨弦等演奏指令。

基础要求细项原文：

> 自主设计演奏交互形态，基于各类传感器实现演奏动作精准采集，支持选音、触发、拨弦、**力度感应**等操作，具备**至少 2 个独立可控维度**，交互逻辑灵敏稳定，适配乐器演奏场景。

## 二 方案选型与合规性论证

### 2.1 候选方案

| 方案 | 交互载体 | 维度来源 | 工期风险 | 演示直观性 |
|---|---|---|---|---|
| A 全自研键盘矩阵 | 自建机械结构 | 自建扫描与力度检测 | 中 | 高 |
| **B 电子钢琴式 MIDI 交互** | **已购 MIDI 键盘与延音踏板；弱音踏板待购** | **MIDI 解析和踏板控制** | **低** | **高** |
| C 外购键盘硬件 + 自研扫描 | 外购键盘总成 | 自研扫描与力度算法 | 低 | 高 |
| D 电容触摸 / 光电 / 手势 | 自研传感器 | 自研传感器 | 高 | 中 |

### 2.2 选定方案：B

选定 **方案 B：以电子钢琴为主演奏形态，使用已购 MIDI 键盘与延音踏板，后续补购弱音踏板；FPGA 侧解析 MIDI 并转换为统一演奏事件**。键盘力度是否正常输出仍待抓包。

选择理由：

- **电子钢琴演奏逻辑自然**。琴键用于选音、触发与和弦，力度、延音和弱音分别承担三种钢琴式表情；不以普通摇杆凑维度。
- **自研交互仍需证明**。不能把外购键盘内部传感器写成自研；本项目自行实现 MIDI 接收、事件映射、踏板状态与声部保持/释放，若弱音踏板由 FPGA 直采，需给出采集与去抖证据。仅购买 MIDI 键盘是否满足赛题“自研交互”，仍有评审风险。
- **工期风险最低**。两个月内，把时间投在算法与合成引擎上比投在机械结构上收益更高，而算法正是本赛题的核心评分点（实时多音色合成引擎）。
- **力度天然满足基础要求的第二维**。带力度键盘直接提供 velocity，无需自行设计力度检测机构。
- **演示直观**。键盘形态评委一眼可识别，交互意图无需解释。

### 2.3 本方案中仍属自研的部分

选择外购键盘不等于交互侧没有工作量。以下部分由本项目自行设计与实现：

| 自研内容 | 归属 | 说明 |
|---|---|---|
| MIDI 接收与解析 | M3 | UART 采样、字节流同步、运行状态解析、实时性保证 |
| MIDI 到统一事件转换 | M3 | 依据接口规范 3.2 节映射到 `performance_event_t` |
| 连续控制器限速与合并 | M3 | 满足接口规范 3.7 节的 1 kHz 限制 |
| 维度划分与映射策略 | M3 | 决定哪些 MIDI 控制器承载哪个演奏维度 |
| 延音/弱音踏板采集 | M3 | 延音解析 CC64；弱音踏板待购，优先 CC67，不支持第二踏板时考虑 FPGA 直采 |
| 和弦识别 | M1 | 依据同时进入的 Note On 判定 |
| 拨弦判定 | M1 | 依据力度与触发包络特征 |
| 全部合成算法 | M1 | 与交互解耦 |

**技术要点**：MIDI 是 31.25 kbaud 的异步串行协议，需要处理起始位检测、字节边界同步、运行状态（running status）压缩、以及 3 字节消息的原子性。这些不是"直接可用"的现成功能，属于交互适配层的实际工作量。

### 2.4 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 键盘 MIDI 输出电平为 5 V | 可能损坏 FPGA IO | 接入前必须确认电平；5 V 时加分压或电平转换 |
| 键盘使用 USB-MIDI 而非 UART MIDI | 无法直接接入 | 采购时确认具备标准 MIDI OUT 或可引出 UART TX |
| MIDI 31.25 kbaud 的采样与同步 | 解析错误导致丢音 | UART 采样率取 16 倍过采样，加帧错误与溢出计数 |
| 力度来自键盘内部，映射曲线不可控 | 力度听感受限于键盘 | 在适配层做曲线重映射，不改变键盘原始输出 |
| 键盘延迟未实测 | 影响 R11 灵敏稳定 | T036 实测端到端延迟 |

### 2.5 待核实

- MIDI 键盘与延音踏板已经购买；准确型号、键数、供电方式和输出接口由 M3 实物登记。

- 弱音踏板尚未购买；采购前确认第二踏板接口是否支持 CC67，不兼容时再评估 FPGA 直采。

## 三 演奏维度定义

本项目明确区分**演奏操作**与**演奏表情**。琴键选音/触发不重复计入拓展要求的三维表情。拓展三维按钢琴演奏逻辑定义为力度、延音和弱音。

### 3.1 演奏操作：琴键选音、触发与和弦

| 项目 | 内容 |
|---|---|
| 物理来源 | MIDI 键盘按键位置 |
| MIDI 消息 | Note On / Note Off |
| 事件字段 | `note_number`、`velocity` |
| FPGA 行为 | 音高选择、声部触发/释放、同时多键和弦 |
| 表情计数 | 不计入拓展三维表情 |

键数与音域以已购实物为准，登记和实测前不再写死为 25 键或 C3～C5。FPGA 侧覆盖 MIDI Note Number 0～127。

### 3.2 表情维度 1：按键力度 Velocity

同一琴键可以轻弹或重弹，力度与音高可独立变化。MIDI 7 位 Velocity 扩展为 10 位，控制声部增益、ADSR 峰值，并可进一步控制音色亮度或敲击瞬态。Velocity 0 的 Note On 必须转成 Note Off。实物需测量有效级数、分布和重复性。

### 3.3 表情维度 2：延音踏板 Sustain

| 项目 | 内容 |
|---|---|
| 硬件状态 | 延音踏板已购买 |
| MIDI 消息 | CC64（待抓包确认） |
| FPGA 行为 | 踏板按下时保持已松键声部；踏板松开时进入 Release |
| 半踏声明 | 只有实测 CC64 存在稳定中间值时才启用；否则按 0/127 开关处理 |

每个声部需区分 `key_down` 与 `sustain_hold`。延音会占用复音槽，偷声策略必须避免 Note Off 丢失和挂音。

### 3.4 表情维度 3：弱音踏板 Soft

| 项目 | 内容 |
|---|---|
| 硬件状态 | **尚未购买** |
| 首选 MIDI 消息 | CC67 |
| 备选输入 | 若键盘无第二踏板接口，可由 FPGA 直接采集 3.3 V 脚踏开关或连续传感器 |
| FPGA 行为 | 降低声部增益、减少高频分量并软化 Attack，不能只做静音开关 |

弱音踏板购买和实测完成前，拓展“≥3 维表情”只能写为**方案已覆盖、实物未完成**，不得写成已验收。

### 3.5 附加合成模式：滑音与颤音

钢琴主演奏界面不增加普通摇杆。为覆盖拓展要求明确列举的演奏效果，保留低成本附加功能：

- Portamento：音符切换时 FCW 从旧音平滑过渡到新音；
- Vibrato：5～7 Hz LFO 调制 FCW，深度由预设档位或后续控制器设置；
- 两项默认在钢琴模式关闭，不计入三维钢琴表情的数量。

### 3.6 维度与要求的对照

| 赛题要求 | 覆盖情况 | 承载方式 |
|---|---|---|
| R1 ≥2 个独立可控维度 | 方案覆盖，待实测 | 琴键选音/触发 + Velocity 力度 |
| R2 选音 | 方案覆盖 | MIDI Note Number |
| R3 触发 | 方案覆盖 | Note On / Note Off |
| R4 和弦 | 方案覆盖，待多键实测 | 多个同时活跃声部 |
| R5 拨弦 | 非钢琴主交互，待答辩口径 | 不单列传感器 |
| R6 力度感应 | 硬件已购，待抓包实测 | Velocity |
| R7 ≥3 维表情调控 | **未完成** | Velocity + CC64 延音 + CC67/直采弱音；弱音踏板待购 |
| R8 滑音 | 附加模式待实现 | Portamento |
| R9 颤音 | 附加模式待实现 | LFO Vibrato |
| R10 ≥2 种音色 | 待算法实现与切换实测 | 钢琴/电钢琴等至少两种音色 |
| R11 灵敏稳定 | 待实测 | 见第四节指标 |

## 四 需实测的指标

以下指标必须在 T036 实测，不得凭估计写入对外材料：

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 按键到事件延迟 | ≤2 ms（FPGA 侧） | 逻辑分析仪测 MIDI 字节到达到 `event_valid` |
| 键盘到发声总延迟 | ≤10 ms，目标 ≤5 ms | 见下方说明 |
| MIDI 解析正确率 | 100%，无丢字节 | 长时间连续演奏，检查帧错误与溢出计数 |
| 力度分辨级数 | ≥16 级 | 逐级按压记录 velocity |
| 力度重复性 | 同力度偏差 ≤10% | 同一力度重复 30 次 |
| 连续控制更新率 | ≤1 kHz | 受接口规范 3.7 限制 |
| 和弦识别同时性窗口 | 待定 | 依据人手生理极限，建议 30 至 50 ms |

**关于总延迟**：使用外购 MIDI 键盘后，延迟链路增加两段本项目不可控的环节。

- MIDI 串行传输：一条 3 字节消息在 31.25 kbaud 下约需 0.96 ms。
- 键盘内部扫描与力度检测：**待实测**，不同型号差异明显，是总延迟的主要不确定项。

因此本方案的总延迟**部分取决于所选键盘**，不能仅由 FPGA 侧决定。T036 必须实测"按键到发声"的完整链路，不能只测 FPGA 侧。若实测总延迟超出 10 ms 基础要求，应对措施包括：在适配层缩短缓冲、优先选用延迟较低的键盘型号。

**与接口规范的衔接**：Velocity 已有事件字段，Sustain/Soft 的 `control_id` 尚未冻结；需先按公共接口流程提出变更，再同步包定义、接口文档、MIDI 解析 TB 与声部状态机 TB。本文件只冻结交互方向，不直接改公共接口。连续踏板值若存在，仍须遵守单一控制源不超过 1 kHz 的限速与合并规则。

本方案解决的差距（编号见 `赛题要求对照表.md`）：

### 5.1 公共事件接口影响

现有 `performance_event_t` 可承载 Note On/Off 与 Velocity，但 Sustain、Soft 的控制编号尚未冻结。后续由 M2 提案 `CTRL_SUSTAIN`、`CTRL_SOFT` 的编码和取值语义；M3 负责 MIDI/踏板输入，M1 定义声部释放与弱音音色算法。`expression` 字段本轮不重新定义，不把同一个输入重复计数。

### 5.2 滑音和颤音定位

滑音与颤音保留为附加合成模式，不占据电子钢琴主演奏界面的三维表情计数。两项仍需实现并验证，才能对外声称覆盖拓展要求中点名的演奏效果。

## 六 硬件与接线待确认项

以下必须在接线前核实，不得直接连接：

- 已购键盘的 MIDI 输出形式仍待核实。需确认是标准 MIDI OUT（电流环，5 针 DIN）、UART TX 电平输出，还是仅 USB-MIDI；仅 USB-MIDI 需另行确定 Host 桥接方式。
- MIDI 输出电平，**待核实**。标准 MIDI 为电流环，需光耦隔离并转换为 3.3 V UART 电平；若为 5 V UART 输出，接入 FPGA 前必须分压或电平转换。
- 与开发板 IO Bank 电压的匹配关系，**待核实**，见 `板级硬件事实.md`。接入前核对 I/O Bank 电压与引脚容限。
- 最终占用的 FPGA 引脚编号与约束文件，**待核实**，需与 M2 的约束同步更新。
- 键盘是否需要外部供电，**待核实**。
