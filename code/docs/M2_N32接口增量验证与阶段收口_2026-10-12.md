## 3. 真实接口差异与最小后继方案

| 信号/行为 | 冻结N32公开接口 | M2适配状态与边界 |
|---|---|---|
| sample_valid/ready/id | 32位ID，ready受idle/cancel/READ约束 | 真实短测接通；单pending保持、frame同沿拒绝旧代 |
| result_valid/ready/id、left/right | 已混音signed24，HOLD到publish | 直接传递、原样提交；不再经过四路mixer |
| cancel与排空 | 取消进入DRAIN，idle后才重新ready | frame_tick接cancel；短测旧事务取消、新代恢复通过 |
| clipped | backend内部be_clipped存在，b2d未公开 | **缺口。TB仅把拟议metadata绑0，不签削波计数正确** |
| late | 超过833拍的标志 | 不能充当clipped；本短例未late不等于所有事件准入 |
| frame请求计数/实际接受计数 | 两个不同事件 | adapter每frame产生credit，实际dispatch以valid&&ready计；不得混算 |
| 公开READ/事件仲裁 | 原有读口与router所有权 | 保持；本次只测读占用短阻塞，不签持续争用服务上界 |

准确clip的最小方案必须是**新的隔离b2d后继**：增加结果metadata输出，在原RUN发布result_id/left/right的同一寄存沿锁存be_clipped，复位/取消清除，HOLD背压期间与ID/PCM保持，接入adapter.candidate_clipped。冻结b2d、生产顶层和公共包不改。不能把clip绑0用于正式计数，也不能用PCM恰为满幅反推是否真正削波。

这属于受控接口变更，本轮仅提交方案，不实施。后续还要针对新metadata做正常/取消/背压/真正正负饱和与一次commit计数的新增关联验证；不得套用本次绑0结果或旧独立饱和报告。若修改wrapper/顶层debug声部数，需检查32槽所需6位计数、事件/READ路由及观察PCM时点；不能截成原四音字段。

本次未连接生产顶层、PLL、CDC、I2S发送器或显示，未执行综合/PnR/STA。实际帧输出采样率、长期事件负载、真正32bit ID回绕、全部取消阶段、32槽同时贡献、资源与新整机截止均未验证。原60K/四音回退、新RAM5e1d13c保持，旧RAM只作历史。
