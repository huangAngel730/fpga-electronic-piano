## 未通过问题

1. **直接解压运行失败**：`adsr_acceptance.py`使用`SCRIPT_DIR.parent.parent`，把`code/`
   加入`sys.path`，但`adsr_piano.py`位于`code/model/`。直接执行exit 1；外部补
   `PYTHONPATH=code/model`后才通过。应改为`SCRIPT_DIR.parent`或等价相对根定位。
2. **DELIVERY命令与CLI不一致**：文档要求`--capture`，实际CLI只有`--jsonl`和
   `--test-counterexamples`。M1验收器未读取原F capture，双文件逐条一致目前由M2外层审核
   证明，不能写成M1完整入口已实现。
3. **内置反例测试仍失败**：主验收器捕获`FileNotFoundError`并返回失败结果，
   `test_missing_capture()`却期待异常冒泡，因此输出0/1通过、整体exit 1。真实缺文件命令虽
   正确非零，但内置自测结论仍是FAIL。
4. **23个真实数据损坏反例只拒绝15个**。以下8个被M1验收器错误接受：
   - 删除首个RESET并同步修改END计数；
   - RESET epoch改错；
   - 插入未知记录；
   - STATE的pending_request_id错误；
   - dds_fcw错误；
   - phase_acc错误；
   - table错误；
   - envelope字段错误。
5. **DDS/相位/表选择未验收**：任务单要求FCW、DDS样本、请求代次和PCM1LSB错必须拒收，
   但当前代码仅使用`level_q16`做ADSR比较，并只检查PCM是否落在24位范围。文档所称
   “PCM、DDS检查”“tick单调”“四声部状态齐全”没有对应的完整实现。

运输审核器能拒绝错误RESET、未知记录和错COMMIT，但它也不负责DDS/phase/table数学；不能
用两个不完整检查器的并集替代M1交付要求。正例PASS证明现有真实数据与独立ADSR模型相符，
不证明当前验收器对所声明全部错误具备检出能力。
