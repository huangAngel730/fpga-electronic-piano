# T009 ADSR 融合阶段验收（M2，2026-09-27）

基线：`c53b3c3`（含 M1 `40d359d`）。用户已确认将 T009 融合分工通知私发 M1；主开发2已停写其未发布候选，交由本窗口在隔离工作树完成融合。**此文档只声明独立 ADSR 模块的阶段结果，T009 整机仍进行中。** 不改 `code/model/adsr_piano.py`、公共事件/PCM 接口、正式电子琴顶层、CST 或 M1 T010 文件。

## 实际融合内容

- 保留 M1 已定义的公开 `adsr_piano_envelope` 六个输入/两个输出接口，低有效异步复位，`state_out` 对外编码固定为 IDLE=0、ATTACK=1、DECAY=2、SUSTAIN=3、RELEASE=4。额外两拍 ROM 状态属于内部装载阶段，在端口上报告为 ATTACK；本轮边界 TB 加断言防止误改公开编码。
- 采用当前 M1 Python `adsr_piano.py` 的 48kHz 采样、Attack=240、Decay=4800、Release=4800、Sustain 按 Velocity 缩放并随时间缓慢衰减的数值定义，ROM 值由 M1 `velocity_to_gain` 生成。不采用旧 `code/docs/test/T009_ADSR包络设计.md` 中 480/2400、固定0.75的早期稿。
- 借用 M2 未推送候选的两级同步 ROM 装载、事件侧定点步长预计算、运行期 Q16 更新和长 Sustain 分阶段乘法；修正 M1 `40d359d` 的重复 `else` 导致不可编译、同拍 ROM 旧值、固定目标 Sustain 与热路径高成本除法。边界 TB 中的事件与采样同时到达由 `pending_tick` 记录，不静默丢首帧。
- 保留 M2 原候选的专项运行脚本与幅度轨迹比较器，并新建可重跑的独立 Gowin 全流程脚本及报告失败门禁。不修改模型以迎合 RTL。

## 本轮实际验证（模块级）

1. `./code/scripts/run_t009_adsr_sim.ps1`：33114 个音频采样步骤、27 项边界断言 PASS；73210 个样本按 M1 Python 模型对照，最大绝对幅度差 **2 个 Q15 LSB**，容差 **暂定**。缺ROM、截短ROM、篡改轨迹均退出非零。此处 L3 仅限所测幅度场景；调试 `state_out` 的完整逐帧状态边界尚未对齐模型，不能写成严格状态等价。
2. `./code/scripts/build_t009_fusion.ps1`：Gowin V1.9.11.03 Education，GW5AT-LV60PG484AC1/I0，单模块顶层，以 50 MHz `sys_clk` SDC 跑 `run all`；资源 **626 Logic（480 LUT、146 ALU）、147 Register、5 DSP、1 BSRAM**。50 MHz 约束下 Fmax **59.563 MHz**，最差 Setup +3.211ns，Hold +0.275ns；Setup/Hold TNS 0、违例端点 0。未加板级 CST；单声部模块时序不能推论四个副本与混音后的整机时序。DSP=5/声部在四声部复制时已达到20个，仍需正式综合确认共享和布局。
3. `python -m unittest discover -s code/tb/audio -p test_t009_fusion_report.py -v`：报告检查器在真实报告与缺失、负余量/错误器件等反例中自检通过。生成码流只为独立构建验证，不下载到板。

## 未决数学与实物验收

- 当前 M1 Python 模型在**高电平 Release 改低力度**时会立即钳制目标峰值，如 velocity=1 的 Q15 `13063→6553`，与“每步不超过138”的连续性门槛矛盾；M2 RTL 选择有界下降过渡，仅以本轮 73210 个普通轨迹达到暂定 ±2 LSB，不把此矛盾样本说成逐样本通过。M1 应明确这类演奏是允许硬截断还是必须有界过渡，并修模型/参考测试后再作终验；不能为了让整机爆音测试通过就只放宽 M2 测试。
- M1 Python Note On 在非 Release 状态仍从零重起，快速重触发可能产生新突变；最终统一行为需由 M1 明确并补样本/模拟输出验收。
- 首帧取样对齐、事件在同拍到达、状态转换与 DDR/BSRAM ROM 路径在集成后应以真实 `sample_req`、`pcm_valid/ready` 和请求 ID 复测；本模块没有 PCM 有效/代次接口，不宣称解决 T055/T025 或可听无爆音。
- 正式音频工程资源、PnR/时序、DAC 模拟输出、PA_EN 启停和实际键盘力度/松键/重触发都未测。当前总门禁里的 T007/T019 回归并不包含融合模块。M1 负责包络数学定义和最终验收，M2 在收齐声部/事件接口后做顶层及板级验证。
