## 具体变更

分配器以每槽唯一的两位秩维护四槽从最旧（0）到最新（3）的**相对顺序**。复位赋予槽 0…3 秩 0…3；每次 Note On 优先匹配相同 `(source_id,channel_id,midi_note)`，包括 Release 中的槽，再选最低编号空槽；满载时选择秩 0 最久未触发槽。目标移动到秩 3，原本更“新”的槽秩各减 1。重触发和偷声都更新先后关系；序号不以总事件数递增，因而没有 3 位计数回绕歧义。`release_done[i]` 仅在第 i 槽确实处于 Release 时清除该槽；它与相同身份的 Note On 同拍时，新 Attack 不会被清除。公开 `allocated_slot/slot_valid`、`release_slot/release_target_valid` 仍为同步单拍结果。

修改 `run_t010_voice_sim.ps1` 让 M1 的旧入口转到独立端口检查器，避免旧测试台不符合现行接口造成误判。M2 原有六场景 TB/脚本支持标量旧版和四位新版，另加独立 Python 相对排序模型与向量 TB。新版外部端口六场景 6/6 PASS；默认 2121 条跨复位、四槽、来源/通道身份、重触发、已占满抢占、多次排序轮转、同拍 Release 完成／Note On 事件向量全部比对；三组不同随机种子各 3127 条追加检查通过。对照 M1 ZIP 在定向 age_wrap 和向量第 37 条复现错误。旧版分配器在相同六场景中仍仅 3/6 通过。
