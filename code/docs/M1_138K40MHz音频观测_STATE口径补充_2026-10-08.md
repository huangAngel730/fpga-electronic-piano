## raw_state不是位打包，但定义已明确

字段取dut.u_bank.g_lane[lane].u_envelope.state，4bit私有枚举；public_state取
state_out，3bit公共调试状态。不是(note_on/note_off/occupied/source)组合位图，不是
未知内部寄存器blob。raw/pub关系允许多个raw对应同一pub：

| raw整数 | 原私有枚举 | public整数 |
|---|---|---|
| 0 | IDLE | 0 IDLE |
| 1 | LOAD_1 | 1 ATTACK |
| 2 | LOAD_2 | 1 ATTACK |
| 3 | ATTACK | 1 ATTACK |
| 4 | DECAY | 2 DECAY |
| 5 | SUSTAIN | 3 SUSTAIN |
| 6 | RELEASE | 4 RELEASE |
| 7 | LOAD_3 | 1 ATTACK |
| 8 | LOAD_4 | 1 ATTACK |
| 9 | RELEASE_1 | 4 RELEASE |
| 10 | RELEASE_2 | 4 RELEASE |

11..15没有合法定义、负数/未知/X/非整数都拒收；即使RTLdefault公共输出0也不能把
坏raw当IDLE验收。此映射对原9964条STATE全匹配：实际出现(0,0)1688、(3,1)2827、
(4,2)5262、(6,4)187；原轨迹未出现其它值不等于删除合法private加载/释放准备态。
映射检查是最低一致性，不单独证明ADSR内部cycle轨迹/全部DDS数学。相同公共状态有
多个raw不构成无法检查的理由。无需再等待寄存器文档才能拒错误raw0/pub2等变异。

## tick1采样与tick0事件

模板记录条件为rst_n && (lane_tick || slot_note_on[lane] || slot_note_off[lane])。

- tick=1来自共享lane_tick。因此同一次(epoch,cycle,pending_request_id)采样须有
  lane0/1/2/3四条且每lane唯一，顺序可以模板实际生成顺序解释；不能只看END总数。
- tick=0只因该lane的note_on或note_off事件，一条记录至少有一个eventpulse。不要求
  四lane凑齐；pending_request_id是此时bank的最近采样代次，可能与tick1共ID甚至
  已提交，不得将tick0当新REQUEST或重复采样拒掉。
- 每条(epoch,cycle,lane)唯一；同一request可有多个不同cycle的tick0事件及一个合法
  tick1采样组，需要按实际case关联，不用(epoch,request,lane)去重误删真实事件。
- RESET之后新epoch清关联/模型；实际取消的请求可无tick1/COMMIT，不发明采样补0。
  不要求所有REQUEST都COMMIT。若tick1已发生后RESET/取消致无COMMIT，按取消合同
  保留允许，不把本具体fixture的数量关系当一般硬规则。

本原fixture：REQUEST2488，COMMIT2487，tick1组2487/STATE9948（每组四lane），
tick0事件16，共STATE9964、RESET4；本fixture实际tick1 requestkeys恰等COMMITkeys，
另一个请求在复位取消而没有完成采样。这是本数据核对项，不提升成全部运行通用断言。

完整raw/state/bank timing核对可从提供源码和原记录确定。lane_tick之外事件没有新
sampleadvance，phase/包络应按其自己的时序规则校验，不按记录条数推进所有lane。
DDS独立FCW/phase/table/envelope数学和F严格格式仍由对应验收实现完成，不因本单
只给原capture的STATE口径就默认其它缺项已通过。

本单仅M2静态来源/原记录口径提供，不改code/docs/模块接口规范.md或公共包，
M1继续原验收候选范围实现。反馈待用户转发M1，尚未送达。

## 原F的R/M/END字段更正（以冻结TB实参为准）

原TB code/tb/board/m3_midi_pcm_acceptance/tb_midi_pcm.sv的M格式实参最后一项为
fixture_select，所以真实格式是：

```text
R cycle epoch
M cycle request_id pcm_left_hex pcm_right_hex fixture_select
END total_pcm nonzero_pcm full_pop_push control_stalls edge_events center_samples normal_pushes synthetic_pushes checks
```

此前交接把第六列称clip是字段命名误解，此处追加更正，不改旧原件/数据格式。
fixture_select仅测试夹具选择0/1，不能解释为音频clipping计数或削波flag。原2487个M中
2485为0、2为1；真实clip_count是另一个status输出，本JSONL/F-M没有直接记录它。
即使M1保留dataclass.clip历史变量名，也必须文档注明它实际是fixture_select。

END共tag+9整数，total_pcm必须等M记录数/JSONL COMMIT数2487；nonzero_pcm可独立
按M左声道非0记录重算2302，其它项是对应原TB计数，不凭字段存在就假称业务数学验证。
未知tag、错误字段数、错误R周期/epoch、END数量或END后记录都应fail-closed；
不要把END 2488...或只有END一个词验收成功，也不把dict比对替代原M列表顺序。
该补充提供原字段来源和最低一致性，不添加原数据不存在的clipping或新数学声称。
