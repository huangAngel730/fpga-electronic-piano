# M2：双音色切换列首项，复用60K按键/MIDI路径（2026-10-16）

## 最新顺序与最小代码结论

用户本轮将**双音色自由切换**列为基础四音后的拓展第一项；其后依次为上飘＋下落双滑块、冻结左声道真实波形、一份真实文件的最小传谱，N32最后且当前停工。双音色候选的静态/隔离准备可在等待四音实测期间并行，但新整机正式验收、码流与实物结果仍按准确同版证据判断，`board_release_allowed=false`。此前双滑块为“拓展第一项”的说法已被本次明确更新，仅保留为历史。

**首轮只用已存在的 MIDI 键盘控制代码，不新增物理按键 RTL，也不重写演奏键。**60K 正式 `code/rtl/input/midi_input/midi_event_parser.sv` 已将标准 MIDI `Program Change` 解析为 `CTRL_VOICE_SELECT`，`code/rtl/board/polyphonic_event_router.sv` 为每个 source/channel 保存 program 0/1，并在下一次 Note On 锁定该声部的音色；现有 `code/tb/board/tb_t027_midi_program_top.sv` 对真实速率UART→共享FIFO→四槽及PCM/串行活动有定向 PASS 记录。两枚板上 `key_n[0/1]` 是演奏键，EX_KEY.0是复位，不挪作切换键。

138K `_06` 物理候选已复制对应 MIDI 解析器（`inputs/sources/midi_event_parser.sv` SHA `336d867856a7b3956d524105137c035ec2637fea936538979182669987212071`）与 M1TD 音色路由（`inputs/sources/m1td_polyphonic_event_router.sv` SHA `f86dc783534c7e3897197d3a967c94d614642196c8d67bff9493d70d1a5fc808`）。该解析器约第180–194行仍把 Program Change 映射到 `CTRL_VOICE_SELECT`；路由约第136–156行仍接受 control_value 0/1、按 source/channel 保存，下一 Note On 锁到 `slot_timbre`，已发声声部不随新选择跳变；`m1td_piano_triangle_voice.sv` 的 `timbre_triangle` 为0选钢琴、1选三角。来源顶层 `m2_fourvoice_timbre_delay_board_top.sv` SHA `f2a8f30fef8ad2da26d1d3b80793b727f45806b6d5c78f2a071fb383322639be` 保留 MIDI 输入/共享事件，不需要新增音色切换用的外部引脚。

**实际按键口径**：优先使用已购 MIDI 键盘可发出的 Program Change 0/1（通道0示例字节 `C0 00`/`C0 01`）作为音色选择，普通音符仍沿用60K Note On/Off与Velocity路径。X4 III 的哪个实体控件、是否能直接发这两个 Program Change，现有实物抓包没有证明：M3先对拟用控件实际抓MIDI原始字节。若发不出，可以用已有安全隔离的外部MIDI发送源在同一码流上测试选择功能；不能声称“键盘实体键切换已通过”。只有用户确实要新增独立板载音色键且指定无冲突物理输入/接口与电平后，才在新隔离目录写**一枚去抖键→Program 0/1 控制事件**的最小适配器，先做切换按键这一项，不加菜单、重写MIDI键位、音色算法、音效或新的物理约束。本轮输入选点尚缺，写一个悬空的新按钮模块不会推进板级可用性，因此新增 RTL 文件数为0；现有所需按键/选择代码已入工程。
