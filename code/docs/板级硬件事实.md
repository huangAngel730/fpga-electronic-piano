证据优先级上不能凭示例仓库直接推翻本仓库结论（该示例料号头亦不可信，见下条），**必须回原理图核对**。
**用户已于 2026-09-12 明确指示暂缓核实，标为待定。在核实前 `AA13` 与 `Y12` 均不得用于正式 CST。**

**待定项二：`PBG484A` 与 `PG484A` 的写法 —— 已由官方文档定案（2026-09-13）**

**结论：两个写法都对，只是层级不同，不存在笔误。**

Sipeed 官方 Wiki 的 Tang Mega 60K 页面（`docs/hardware/en/tang/tang-mega-60k/mega-60k.md`，
"Precautions" 表）原文：

> The specific model of the FPGA chip used by Tang Mega 60K is **GW5AT-LV60PG484A**
> Please select the package model **`PBG484A`** & **Device Version: B** in the IDE.

### 3.1 对音频项目的直接约束

- **乘法器 118 个**是多音色复音数的主要瓶颈。每个声部若用 1 个 18×18 乘法器做包络或调制，理论上限约 118，但实际要与混音、效果器、控制逻辑共享，必须按 T016 实测确定保底复音档。
- **BSRAM 2124 Kbits** 决定波表容量。单周期 16 位样本、2048 点波表约需 32 Kbits，可容纳多个音色，但需与 FIFO、延迟效果器共享。
- **PLL 8 个**足够支撑 `sys_clk` 与音频输出时钟方案，T019 不必担心 PLL 数量不足。
- 本芯片**无硬核处理器**，所有控制逻辑必须用 RTL 实现，不能依赖软核方案。
- **板载晶振 50 MHz，已确认**，见 3.3 节。该频率不能被 48 kHz 整除，
  对音频时钟方案有直接影响。

#### 50 MHz 对音频时钟方案的影响

50 MHz 不能被 48 kHz 整除，这带来两个后果。

**一、`sample_tick` 存在微小抖动，但可接受**

```
PHASE_STEP = round(2^32 × 48000 / 50000000) = 4123169 (0x003EEA21)
实际平均采样率 = 48000.004608 Hz，误差 +0.096 ppm
tick 间隔在 1041 与 1042 个时钟之间交替，峰峰抖动 20 ns
```

长期平均误差 +0.096 ppm 极优。抖动之所以可接受，是因为
`sample_tick` 在本项目中是"处理节拍"而非 DAC 时钟，抖动只改变
算完的时刻，不改变数值结果。

**二、I2S 的 BCLK 不能用整数分频产生（关键）**

```
50 MHz / 3.072 MHz = 16.276042    ← 不是整数
```

| 整数分频 | 实际 BCLK | 误差 | 音高后果 |
|---|---|---|---|
| ÷16 | 3.125000 MHz | +17253 ppm | **偏高约 0.29 半音** |
| ÷17 | 2.941176 MHz | −42586 ppm | 偏低约 0.75 半音 |

±0.29 半音的走音人耳可直接察觉，**整数分频方案不可用**。
BCLK 必须用与 `sample_tick` 相同的相位累加结构产生：

```
step = round(2^32 × 3.072e6 / 50e6) = 263882791 (0x0FBA8827)
实际 BCLK = 3.072000004 MHz，误差 +0.0013 ppm
```

LRCLK 由同一累加器加 6 位计数器产生，天然保证 64:1 整数关系。

#### 为什么不用 PLL 倍频到 98.304 MHz

Gowin rPLL 的 IDIV/FBDIV 为整数。在 IDIV ≤ 64、FBDIV ≤ 128 范围内，
最接近 98.304 MHz 的参数是 `IDIV=59, FBDIV=116` → 98.305085 MHz，
误差 **+11.03 ppm**，反而比 50 MHz 直接分频的 +0.096 ppm 差两个数量级，
且多消耗一个 PLL 和 BUFG。因此**选择不倍频**。

若后续实测发现 BCLK 抖动导致 I2S DAC 的 THD+N 不达标，
可改用 PLL 产生 98.304 MHz 后整数 32 分频，获得无抖动 BCLK，
代价是 BCLK 频率误差从 0.0013 ppm 变为 11.03 ppm（音高偏差仍远不可闻）。

#### 三处必须纠正的认知

1. **`sys_rst_n` 不是专用复位引脚。** AA13 的真名是 **EX_KEY.0**（用户按键 0），
   位于 **Bank 9 / LVCMOS15 / 1.5 V**。官方例程 `.cst` 把用户按键 0
   取别名为 `sys_rst_n`，那只是**示例工程的自定义端口名**，
   与芯片的 RECONFIG（N12）或 CPU_RESET（F4）无关。
   本项目若沿用它做复位，必须清楚它是**用户按键**，
   且**不能按 3.3 V 驱动**（Bank 9 原理图明确要求 1.5 V）。

2. **DAC 是 PT8211-S，不是 PCM5102A。** 板载音频通路为
   `FPGA → PT8211-S → NS4263 功放 → 扬声器`。此前文档中把 PCM5102A
   当作对比对象是基于错误的假设，应改为与 PT8211-S 对比。
   **PT8211-S 的数据格式与标准 I2S 不同**，详见 §3.7。

3. **`PA_EN` 是低有效，且上电阶段必须处理。** 事实表明确
   `0=功放开启，1=功放关闭`。复位期间若 `PA_EN` 悬空或被置 0，
   扬声器会在上电瞬间被误开启并可能放出爆音。
   对策：复位期间输出 1 关闭功放，配置完成后才使能。

#### UART RX 的 `V14` 为什么"禁止采用"

官方 `.cst` 中 `rxp V14` 这一整行**被注释掉了**，且注释内容自相矛盾：

```
//IO_PORT "rxp"  IO_TYPE=LVCMOS15 PULL_MODE=NONE DRIVE=OFF BANK_VCCIO=3.3;
```

同一行既写 `LVCMOS15` 又写 `BANK_VCCIO=3.3`，两者不可能同时成立。
因此只保留 `V14` 的物理连接事实，**IOSTANDARD 留空**，
等待官方修订或对照器件手册后再定。

### 3.5.1 BTB 回查规则（31005 表头明文写入，与 D020 一致）

31005 表在表头原文写入：

> 60K球位必须由BTN针号回查30354核心板；底板原图的138K球位标签仅用于审计，
> **禁止写入60K CST**。"未给出"不得自行假设。

规则的完整形式（31005"电气与复用规则"页"BTB映射"条）：

> 底板31005连接器旁的 `BANKx_球位` 是 **138K 原图标注**。
> 60K 必须按：**底板网络 → J0/J1/J2 针号 → 30354 核心板 → 60K 球位**，

这与 **D020** 及用户指示"不需要把 31005 原理图上的 138K Bank 归属

#### 为什么这是本项目最容易踩的坑

**PT8211 用的是 LSBJ（LSB 对齐 / 日本格式），不是标准 I2S（Philips 格式）。**

手册原文对移位规则的描述：

> The DIN data must be the two's complementary format and the MSB
> (Most Significant Bit) must be the first. **When the Word Select (WS)
> clock in the Low level, the DIN data will be shifted to the right input
> register.** Likewise, the DIN data will be shifted to the left input
> register when WS clock in the **High** level.

即：**LSB 紧贴 WS 跳变沿结束**，数据在帧内向右对齐。

| 格式 | 左声道数据位置 | 右声道数据位置 |
|---|---|---|
| 标准 I2S（Philips） | MSB 在 LRCLK 翻转后第 1 个 BCLK，占 BCLK #1–#16 | MSB 在 BCLK #33 |
| **PT8211（LSBJ）** | 数据占 BCLK #1–#16，**LSB 在 #16** | **LSB 在 BCLK #48** |

在 64 BCLK/帧下，两种格式的数据位置**相差 15 个 BCLK**。

> **后果**：如果按标准 I2S 写发送器去驱动 PT8211，
> **每一个样点都会被错位采样，输出不是音乐而是噪声/嗡声**。
> 这类故障很容易被误判为"时序约束没做好"或"DAC 坏了"，
> 实际是数据相位不对。

#### 时序余量核算（已执行）

以本项目 `Fs = 48 kHz`、`BCLK = 3.072 MHz`、64 BCLK/帧 对照手册：

| 约束 | 手册要求 | 本项目实际 | 余量 | 结论 |
|---|---|---|---|---|
| Fbck | ≤ 18.4 MHz | 3.072 MHz | 5.99× | 通过 |
| Fws | ≤ 384 kHz | 48 kHz | 8.0× | 通过 |
| tH | ≥ 25 ns | 162.8 ns（半周期） | 6.51× | 通过 |
| VIH | ≥ 1.8 V | 3.3 V (LVCMOS33) | - | 通过 |

**三条约束全部满足且余量充足**，§3.3 的 BCLK 3.072 MHz 与相位累加器方案
**得到手册证实**。

#### 对本项目接口的三条约束

1. **发送器必须实现 LSBJ，不能用标准 I2S 相位。**
   冻结接口 v1.0（D013）中"MSB 在 LRCLK 翻转后 1 个 BCLK"的描述
   适用于标准 I2S，**不适用于板载 PT8211**，需要修订或增加一个
   格式转换级。已在 `code/docs/模块接口规范.md` 第五节加醒目警告并
   登记为待决策项。

2. **24 bit → 16 bit 必须由 FPGA 处理。**
   本项目 PCM 位宽为 24 bit，而 PT8211 只有 16 bit。
   必须在发送前做**舍入与饱和**（不能用简单截断，否则量化噪声和
   直流偏置会变差）。手册未提及抖动要求，TPDF 抖动是否引入由 M1 决定。

3. **BCLK/LRCK 比例成立，且余量充足。**
   `3.072 MHz / 48 kHz = 64` BCLK/帧，见上表核算。

### 三补 开机流程与指示灯判读（2026-09-14 用户实机确认）

> 来源：用户上板实测口述，2026-09-14。**这是本仓库首次记录开机流程**，
> 此前 §4 只写了"电源开关长按 2s"，未说明如何**确认已经开机**，
> 导致排障时把"未开机"误判为"下载失败/无输出"。

**正确的开机步骤（2026-09-14 修订，见下方"供电余量"）**：

1. **只插电源线**，**先不要插调试线**。
2. **长按电源键 2 秒**。
3. 确认**多色闪烁的电源指示灯亮起** —— **这才是开机成功的判据**。
4. **开机确认之后，再插调试线**。
5. 然后才执行下载/扫描。

**⚠️ 供电余量不足（2026-09-14 实机踩到，本条推翻此前的相反建议）**：

- **故障现象**：电源线与调试线**同时插着**时，长按电源键 2 秒**无法开机**——
  只有 4 个橙色电量灯亮，**多色闪烁的电源指示灯不亮**，且此时
  `programmer_cli --scan` 报 `No Gowin devices found!`（exit 49），
  Windows PnP 中 FT2232（VID_0403）**完全未枚举**。
- **验证方法**：**拔掉调试线后，仅用电源线即可正常开机**。
- **根因判定**：**供电能力不足**，不是板子损坏。调试线（FT2232）与
  FPGA/功放同时取电时，瞬态电流把电压拉垮，电源管理芯片的软启动流程
  起不来，于是只点亮由电池直接驱动的电量指示灯。
- **⚠️ 由此推翻本节原先的建议**：本条此前写的是"接线时**建议电源线与
  调试线同时连接**"（来源为用户口述经验）。该经验**仅在电池电量充足时
  成立**；实测证明在电量偏低或带载（如接了耳机/扬声器）时会**直接导致
  无法开机**。**故以"先电源、后调试线"为准**，原建议作废。
- **排障顺序**：遇到"开不了机"或"`--scan` 找不到器件"时，
  **第一步就是拔掉调试线，只用电源线试开机**，再往下查。
  这两者是**同一根因的两种表现**（FPGA 没上电 → JTAG 链路自然无应答），
  不要误判为下载器故障或 FPGA 损坏。
- **尚未确认**：电池当前电量、电源适配器规格、两路同时供电时的实际
  电流/电压。若后续频繁出现此现象，应先给电池充电 15~30 分钟再试。

**⚠️ 关键判读陷阱（本次排障踩到的坑）**：

- **调试线插上之后就会有 4 个橙色灯亮起，那不是开机指示灯。**
  只看到 4 个橙灯亮，**不代表板子已开机**。
- 必须等**多色闪烁的电源指示灯**亮起，才算真正开机。
- `§4 底板外设清单` 中"LED 4 + 8"的 **4 个电量指示灯**即指这一组，
  它们反映的是**电池电量/充电状态**，与 FPGA 是否运行无关。

**调试线要求**：
- **调试线必须具备数据传输功能**（不能是纯充电线）。
- **后续持续使用这根固定的调试线**，避免换线引入新变量。

**板上开关**：
- **开发板现有开关不要拨动**。V0032 记录的 SW4（`FPGA`/`DBG`）反常现象
  （`DBG` 档报 Code 43）在**保持开关不动**的前提下未再复现，
  当前 JTAG 链路稳定可用（`--scan` 0.18 秒返回）。
  在未查明 SW4 真实功能前，**维持出厂位置**是已验证可用的状态。

**耳机实测注意（V0035 教训）**：
- 底板 3.5mm 耳机座**必须插到底**。插不到底时触点不接触，表现为
  **完全无声**，且该故障**在软件侧完全不可观测**。
- 3.5mm **三节（TRS）与四节（TRRS）插头均可使用**：四节多出的
  MIC 段在本板（无 Mic）悬空，L/R/GND 三个触点位置与三节一致。
- 测试音幅度为满量程 1/4（±8192），**耳机上属"能听清但不响"**；
  换 8Ω 无源扬声器后音量会明显增大，不必据耳机听感调大幅度。

### 4.1 对音频项目的直接价值

- **底板自带 Speaker 接口（2×3W）和 3.5mm 立体声耳机座**，音频通路为 `FPGA → PT8211-S → NS4263 功放 → 扬声器`（见 §3.4、§3.7）。T015 应基于**这条既有通路**做实测（延迟、噪声、直流偏置），而不是假设外接 PCM5102A。
- **`PA_EN` 低有效**，上电复位阶段必须先输出 1 关闭功放，避免扬声器爆音。
- **PT8211-S 是 16 bit / LSBJ 格式**，与标准 I2S 相位不同，且需要 FPGA 侧做 24→16 bit 舍入，见 §3.7。
- **MIC ARRAY 接口支持 Sipeed 6+1 麦克风阵列**，是 T036 交互方案实测的候选之一，比自建传感器阵列省硬件工作量。
- **DVI RX 与 DVI TX 互相占用**，若后续要做显示，只能二选一。
- **PMOD、40P 排针、DVP 三者复用**，M3 做引脚规划时必须避免功能冲突，并在引脚表中记录复用关系。

## 五 供电与电气安全

### 5.1 三种供电方式

| 方式 | 要求 |
|---|---|
| 双 USB 5V | 同时连接 **USB-3.0** 和 **USB-DEBUG** 两个接口 |
| 12V DC | DC5521 规格；若用 USB-C 转 12V DC 配件，需连接**有 12V 输出能力的 PD 电源** |
| 3.7V 锂电池 | 电压必须 **≥ 3.6V**，连续放电能力 **≥ 600mA** |

### 5.2 官方明确的故障现象与处理

| 现象 | 原因与处理 |
|---|---|
| 上电后底板只亮 4 个指示灯，SOM 指示灯不亮 | 未开机。**PWR 按键（HDMI 接口旁）长按 2 秒**开启电源 |
| 底板 Battery-Indicator 指示灯闪烁 | 正常现象，通常是靠近 12V DC 连接器的那颗 LED；接 3.7V 锂电池时这些 LED 作为电量指示 |
| 长按 PWR 2 秒后底板指示灯全部熄灭又依次亮起 | **供电能力不足**。改用双 USB 5V、12V DC 或 ≥3.6V 锂电池供电 |
| 电源指示灯亮，但 Programmer 提示 No USB Cable Connection | 检查 USB 线是否接入标记为 **DEBUG-USB2** 的 USB-C 接口；避免使用机箱前面板 USB 和未独立供电的 USB HUB；确认已安装 FT2232 驱动（设备管理器出现 USB Serial Converter A/B） |
| IDE 找不到型号 GW5AT-LV60PG484A | IDE 版本过老，需升级到商业版 ≥1.9.10.03 或教育版 ≥1.9.11.03 |

**对本项目的意义**：T007 首次上板时，若出现"指示灯全灭又依次亮起"，应先怀疑供电，而不是先怀疑 RTL 或约束。这一条应写入 T007 的记录模板。

### 5.3 电气安全硬约束

- **GPIO 排针外部通信必须确保 IO 电压为 3.3V，过高电压会永久损坏 PCBA。**
- 接触 PCBA 前先释放手上静电，避免静电击中板卡。
- 完全断电后才能插拔。
- 上电过程中避免液体和金属触碰元件焊盘，防止短路烧毁。
- 连接 FPC 软排线时确保排线无偏移地完整插入，**通电前仔细核对两端连接器 1 号 PIN 方向**。
- 测试 PCIe 金手指时，主机端与板卡都必须关机或断电。

这些约束与根目录 `AGENTS.md` 的电气安全条款一致，M3 在 `rtl/input/` 和实物接线中必须遵守。

### 6.1.1 上板实测记录：JTAG 链路无应答（2026-09-13，未解决）

T007 上板时实测到以下事实，**均为一手观测，但结论未定**，登记于此供后续排查与售后沟通使用。

**观测到的现象**

| 项目 | 实测结果 |
|---|---|
| FT2232 枚举 | ✅ 正常：`USB\VID_0403&PID_6010\2025030317`，`USB Serial Converter A/B` 与 `COM9`/`COM13` 全部 `Status=OK` |
| 下载器固件版本 | ✅ 与官方 Mega NEO 最新固件序列号 `2025030317` **一致**（`update_debugger.md` 给出） |
| `programmer_cli.exe --scan-cables` | ✅ `exit 0`，0.09 秒返回，列出两条 `USB Debugger A/0`、`A/1` |
| `programmer_cli.exe --scan` | ❌ **无限挂起**，无输出、不超时退出 |

| 更换 USB 口、更换数据线、双 USB 口供电 | ❌ 无改善 |

**定位**：`--scan` 挂起而非报错，说明**指令已发出但 JTAG 链路上无任何器件应答**。
下载器本身正常（`scan-cables` 秒回），故断点在 **FT2232 的 JTAG 引脚到 FPGA 之间**。

**SW4 反常现象（关键，尚未解释）**

`DEBUG-USB2` 一带有一个 `USB A switch`（单刀双掷，丝印 `FPGA` / `DBG`）。实测：

| SW4 档位 | FT2232 枚举 |
|---|---|
| `FPGA` | ✅ 完全正常 |
| `DBG` | ❌ `Code 43`（`CM_PROB_FAILED_POST_START`）掉线，退化为 `VID_0000&PID_0002` 无描述符设备 |

**这与标称功能相反**——按常理 `DBG` 档才应接通调试器。两个档位下 JTAG 均扫不到 FPGA。

> **⚠️ 待核实**：本仓库既有资料（`板级硬件事实.md`、`code/docs/reference/` 外部整理稿、
> 引脚事实表）**均未覆盖 SW4**，其与 `DEBUG-USB2`、FT2232、FPGA 的实际连接关系无记载。
> 上述"标称功能"来自用户口述资料，**不得当作已确认的板级事实**，须按实物或原理图确认后再写入。
> `DEBUG-USB2` 口正下方另有一个 `UPDATE` 按键（官方 `update_debugger.md` 记载，
> 用于把 BL616 调试器置入 DFU 模式，须在**上电前**按住）；本次已检查未见被压住。

**已排除的原因**：不是 USB 线缆问题（换线无效）、不是 USB 口问题（换口无效）、

**待尝试**：换另一台电脑复测（可一刀切分清本机 USB 控制器问题与板卡问题）、
将 SW4 反复拨动后停回 `FPGA` 档重扫（排除触点接触不良）、联系 Sipeed 售后或论坛。
