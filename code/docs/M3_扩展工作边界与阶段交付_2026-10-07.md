## 4. BLE必须遵守的最低行为合同

实际目标安卓GATT↔C3↔UART↔FPGA。候选只传完整T057协议字节，帧≤142bytes、记录
最多512/4096bytes，不能改变版本、cmd/session/seq/offset/CRC/END计数或旧发布原子语义。
App从归一化JSON得到相同8字节事件，必须与原PC工具/独立JSON truth一致。无线模块
不生成PCM、不按手机到包时间演奏、不把Notify/Write回调当FPGA应用ACK。

最小MTU23下按20bytes载荷分片（实际协商更大可优化但不得硬依赖），C3收齐**完整合法
T057 UART帧**后连续发送给对端，避免把BLE分片间隔直接带到UART导致20ms帧间超时。
接收缓存、连接数/并发、队列明确有上限；候选默认单用户/单上传/停等，忙或断线可拒绝
或重置本地转运，禁止无界增长、内存异常或静默丢部分字节后仍回成功。

模块只透传真实对端ACK/NACK/READ，不能为模拟对端/队列塞满/无线回调伪造FPGA成功
ACK。模块本地“busy/timeout/disconnect”必须与FPGA协议回复区分，UI能识别来源。
一条回复跨多Notify也须按完整帧重组/CRC验证，保留session/seq匹配与有限重试。
同一重试不得换body/seq（除非原协议要求），断线停止事务，重连按ABORT/新session完整
重传等候选流程，不能把断线前后碎片拼到一次提交。保持旧已提交曲谱的错误保护。

软件阶段至少：0..255二进制、20byte分片、各种拆包/合包、完整512逐条读取/4096bytes、
同tick事件序、少/重/乱包、CRC/错session/seq、丢ACK有限重试、对端NACK不误收、取消、
连接变化、权限拒绝/蓝牙关闭、长帧/缓存满、双模块目标身份、真实T057记录回放。
分别标注“协议核心真实执行”“模拟GATT/UART对端”“手机/模块实物未测”，不能合并冒称
实体端到端通过；至少两种成功编译/运行后被特定错误拒收的行为反例及坏capture拒收。

设备编程。其余内部实现和独立测试可自行完成，不每个小步骤都等M2。不涉及阻塞的工作
继续做，不能用一个未提供硬件/审批挡住整套独立交付。
