## 新发现：M3 checker 的假通过

在其自带 `ReceiptCheckTests` 合成有效夹具（`vlog`/`vsim` exit=0、原 SHA 快照一致、精确整行 PASS）中，只向 `vlog` **或** `vsim` 原日志另加一行 `# Error: synthetic diagnostic`，调用未改动的 `_check()` 均返回 `PASS`。原 11 项测试没有覆盖这例。原因是 `_COMPILE_ERROR_RE` 仅识别 `** Error` 或 `Errors: [1-9]`，而 `_FATAL_OR_TIMEOUT_RE` 未拒普通 `Error:`；完整 PASS 允许与另行错误并存。该反例是软件合成，不能声称实际 ModelSim 已打印此错误，也不等于 RTL 错误；但这版 checker 的“错误即拒收”判据**不予签收**。M1 原 `execute_r04_once.py` 的错误识别/普通子串 PASS 漏洞另见 `M1_R04执行器补件与40MHz音频端点_M2限定复核_2026-10-15.md`，两端须分别修，不能用此 checker 给旧 M1 执行器放行。

M3 在其获准写集最小修复 checker：识别工具常见 `Error:`/`Errors: 1`、`** Error` 和失败词，保留独立整行 PASS；补 `vlog` 与 `vsim` 中错误在 PASS 前/后、退出 0 的负例以及真实缺件/身份/超时等旧反例，附新源码 SHA、原始双流/命令/退出码。其当前 `code/software/r04_receipt_check/`、`code/software/frame_budget_offline/` 目录与最新 M3 活任务单所列 `code/software/m3_r04_receipt_audit_20261015/` 的**精确写集不一致**，帧预算工具也不在该第二软件包的既定范围内；M2 先登记事实，不把已推送目录倒写成事先获准。后续修复的写入路径须先按协作流程确认，不让 M2 代改 M3 源。现行 checker 的输入也未逐项包含原任务单要求的 `vlib` 原始双流/命令、cwd、工具 SHA 与 M2 确认引用；接入真实回执前需补合同或明确当前只能签窄范围，绝不凭软件 PASS 签真实整机。
