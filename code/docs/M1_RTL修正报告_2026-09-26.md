### 2.2 ✅ ADSR同拍读取修正

**问题根源**: Note On事件触发时，同一拍读取ROM和捕获retrigger_level，但ROM是同步读取（1周期延迟），导致使用了旧值。

**修正方案**: 重新设计状态机，将Note On处理分为两拍：
1. 第一拍：启动ROM查表，捕获当前电平
2. 第二拍：ROM输出稳定，进入ATTACK状态

**新状态机流程**:
```systemverilog
if (note_on) begin
    rom_addr <= velocity;
    start_level <= (state == RELEASE) ? level : 32'h0;
    state <= IDLE;
    sample_counter <= 16'hFFFF;  // 标记为等待ROM
end
else if (sample_tick) begin
    case (state)
        IDLE: begin
            if (sample_counter == 16'hFFFF) begin
                // ROM输出已稳定，进入ATTACK
                target_gain <= rom_dout;
                level <= start_level;
                state <= ATTACK;
                sample_counter <= 16'h0;
            end
        end
        
        ATTACK: begin
            // 线性上升：level = start_level + (target_gain - start_level) * progress
            level <= start_level +
                     (({target_gain, 16'h0} - start_level) * (sample_counter + 1)) / ATTACK_SAMPLES;
            sample_counter <= sample_counter + 1;
            
            if (sample_counter >= ATTACK_SAMPLES - 1) begin
                state <= DECAY;
            end
        end
    endcase
end
```

**改进**:
- ROM查表和状态转换分离，避免同拍读取
- Release重触发从捕获的start_level开始，确保连续
- Attack使用线性插值，与Python模型一致

### 2.4 ✅ 添加来源/通道身份

**接口修改**:
```systemverilog
module voice_allocator_4 (
    input  logic       sys_clk,
    input  logic       sys_rst_n,
    input  logic       note_on,
    input  logic       note_off,
    input  logic [7:0] midi_note,
    input  logic [3:0] source_id,      // 新增：来源/通道ID
    output logic [1:0] allocated_slot,
    output logic       slot_valid,
    output logic [3:0] slot_states     // 新增：调试用

```

**槽位结构**:
```systemverilog
typedef struct packed {
    logic       active;
    logic [7:0] note;
    logic [3:0] source;    // 新增：来源ID
    logic [15:0] timestamp;
} voice_slot_t;
```

**匹配逻辑**:
```systemverilog
// 同音同源重触发
if (slots[i].active &&
    slots[i].note == midi_note &&
    slots[i].source == source_id) begin
    found_same = 1'b1;
    same_slot = i[1:0];
end

// Note Off也需匹配来源
if (slots[i].active &&
    slots[i].note == midi_note &&
    slots[i].source == source_id) begin
    slots[i].active <= 1'b0;
end
```

**改进**:
- 支持多通道/多源MIDI事件
- 同音符不同源分配不同槽
- Note Off精确匹配音符+源

### 2.5 ✅ Release槽位生命周期

**修正**: Note Off时仅标记`active=0`，保留`note`和`source`：
```systemverilog
if (note_off) begin
    for (i = 0; i < 4; i = i + 1) begin
        if (slots[i].active &&
            slots[i].note == midi_note &&
            slots[i].source == source_id) begin
            // 标记为非活跃，但保留note/source用于Release阶段
            slots[i].active <= 1'b0;
        end
    end
end
```

**用途**: ADSR模块在Release阶段仍能查询槽位的note/source信息

### 2.6 ✅ 时间戳回绕处理

**问题**: 16位时间戳会回绕，简单的无符号比较会失败

**修正**: 使用有符号差值比较：
```systemverilog
// 窃取最旧槽（考虑时间戳回绕）
oldest_slot = 2'b00;
oldest_time = slots[0].timestamp;

for (i = 1; i < 4; i = i + 1) begin
    // 使用有符号比较处理回绕
    if ($signed(slots[i].timestamp - oldest_time) < 0) begin
        oldest_time = slots[i].timestamp;
        oldest_slot = i[1:0];
    end
end
```

**原理**: 有符号差值在回绕时仍能正确判断相对顺序

## 四、已知限制

### 4.1 ADSR曲线近似

**Sustain衰减**: 
- Python: `level *= 1.0 - (0.15 / 48000)` 每采样
- RTL: `level -= level >> 8` 每100采样

**影响**: 长音符尾音曲线略有偏差，但满足音质要求

### 4.2 除法运算

**Attack/Decay/Release**: 使用除法计算斜率
- 综合时会推断除法器
- 可能影响时序和资源占用
- 建议: 后续优化为查表或移位近似

### 4.3 仿真延迟

**ADSR Note On**: 增加1个采样延迟等待ROM
- 延迟约20μs（48kHz），听感无影响
- 需在集成时统一流水线对齐
