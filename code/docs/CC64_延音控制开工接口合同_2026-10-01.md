# CC64延音控制开工接口合同（M2准备，2026-10-01）

源基线develop4902882。本次用户明确要求M2准备M3开工接口；CC64公共编码尚未写入audio_defs_pkg/模块接口规范，具体群通知发送确认后由M2正式发布。现有控制ID0..5/16..17已占用，**拟新增CTRL_SUSTAIN=6**；保持64位事件及所有外部端口/电压/时钟。包内合同可用于独立模块与仿真，但不能据此声称当前正式键盘路径已处理CC64。

## A. MIDI到统一事件（M3输入适配、M2公共发布）

CC消息为Bn 40 vv，n通道0..15；vv7bit0..127。running status/realtime穿插/本地FIFO背压沿用既有规则，禁止把未识别消息变成音符。

统一事件：event_type=EVENT_CONTROL_CHANGE(4)、source_id=解析器现有SOURCE_ID、channel=n、control_id=CTRL_SUSTAIN(拟6)、control_value={vv,vv[6:2]}；note_number/velocity/expression/reserved置0。不改其他现有消息映射。value12>=2048表示踩下，<2048松开；raw63→2031为松开、raw64→2064为踩下、0→0、127→4095，严格等价MIDI7bit>=64。只支持二值踏板，不宣称半踏。

独立合同包函数sustain_value_from_midi生成该映射；SUSTAIN_CTRL_ID_PROPOSED只是合同候选常量，不要为绕过正式发布在解析器复制私人control_id。M3可以先用合同版输入TB准备CC64分支，公共包未发布前不要推送引用尚不存在CTRL_SUSTAIN的正式解析器。

## B. 模块文件与端口

M3新实现：code/rtl/input/sustain_control/sustain_controller.sv。
M2提供：code/rtl/board/sustain_control_contract_pkg.sv、sustain_controller_ports.svh。
声明示例：

```systemverilog
`include "sustain_controller_ports.svh"
module sustain_controller (`SUSTAIN_CONTROLLER_PORTS);
    import sustain_control_contract_pkg::*;
    // M3 implementation
endmodule
```

所有信号在同一50MHz clk域，rst_n异步断言，由上游同步释放。控制模块不接sample_tick、不计算PCM、不改变原ADSR自然衰减；Note Off的Release请求延后，不等于包络冻结。固定4个槽，最多16来源×16通道的独立踏板位。端口无packed struct依赖，便于Icarus/Gowin。

| 端口 | 位宽/方向 | 语义 |
| --- | --- | --- |
| cmd_valid / cmd_ready | 1 in/out | 输入命令成功握手时消费一次；上游在背压期间保持全部字段 |
| cmd_type | 3 in | NOTE_ON0 / NOTE_OFF1 / PEDAL2 / RETIRE3 / PANIC4；5..7无操作 |
| cmd_slot | 2 in | NOTE_ON/OFF/RETIRE的物理槽0..3，PEDAL/PANIC忽略 |
| cmd_source_id / cmd_channel | 各4 in | 槽身份或PEDAL所属来源/通道 |
| cmd_note_number | 7 in | 槽身份，PEDAL/PANIC忽略 |
| cmd_control_value | 12 in | PEDAL值，按上述阈值解释；其他命令忽略 |
| cmd_generation | 32 in | NOTE_ON/OFF/RETIRE的槽生命周期代次；M2每次接受NOTE_ON包括重触发赋新号 |
| release_valid / release_ready | 1 out/in | 一组Release位掩码握手；不是一拍容易丢的脉冲 |
| release_mask | 4 out | 哪些槽首次开始Release；对应payload随valid保持至ready |
| release_generations | 128 out | 每槽32bit小端slice[32*i+:32]代次，非mask槽置0 |
| occupied/key_down/deferred/releasing_mask | 各4 out | 验证与系统连接状态；不可反压音频帧请求 |

输入命令在握手上升沿应用，状态/Release输出在该沿后可观察。cmd_ready=rst_n&&!release_valid；即使release_ready=1也不在同一拍接受新命令，避免同一组旧Release与抢占混用。该约束不影响PCM正常采样：M2仅背压演奏事件派发，不把ready接成音频时钟使能。

## C. 命令状态转换（本合同唯一确定语义）

**NOTE_ON**：M2声部分配完成后传实际slot、source/channel/note和新generation。槽立即occupied=1/key_down=1/deferred=0/releasing=0，保存新身份/代次，取消该槽旧踏板保持。允许抢占其他身份、同身份Release中重触发，不为旧被抢音再发Release（ADSR新Note On由M2正常触发）。踏板位是source/channel独立状态，抢占不清其他来源踏板。

**NOTE_OFF**：M2先按source+channel+note找到槽，附当前generation；controller再验证slot身份及generation全部一致。不存在/旧generation/已Release/重复OFF为无操作。匹配则key_down=0：踏板下且该槽尚未Release时deferred=1，不发Release；踏板上则deferred=0、releasing=1并排队该槽Release。

**PEDAL**：更新该source/channel踏板位。踩下不使已有Release倒流或复活。松开时，仅将该source/channel的occupied && !key_down && deferred && !releasing槽置deferred=0/releasing=1，并排队对应mask/generation。仍按住键不释放；多槽一组mask。重复松踏板不重复Release。

**RETIRE**：M2收到真正Release完成后传slot和当时身份/generation。仅occupied && releasing且全部匹配时清occupied/key/deferred/releasing；旧完成、保持键或踏板保持中的RETIRE不清槽。释放完成不能只传全局bool；不能把自然衰减到0的held/deferred音符立即当成“新空槽”。

**PANIC**：全局清音而非单通道CC123，清全部256踏板位、清key_down/deferred；所有occupied && !releasing槽置releasing并排队mask，不为已在Release的槽再发。等实际RETIRE回收，不强制改变ADSR曲线；复位则立即清所有状态和pending Release，不泄漏复位前请求。

仅一个命令通道，每拍至多一个握手，因此不同命令先后顺序由M2已有事件顺序决定，无隐含“同拍先踩后松键”。例如OFF先于PEDAL-down则正常Release，PEDAL-down先于OFF则保持。release有效时上游命令背压；消费后valid清零，状态不回退。

## D. M2正式连接责任（M3不修改这些文件）

M2改polyphonic_event_router：Note On仍通过现有allocator；分配结果锁存后发controller NOTE_ON并触发ADSR。Note Off先匹配shadow身份、交controller，而不是先调用allocator.note_off，否则已先置in_release会破坏踏板保持。

M2收到release mask时在事件派发域依槽逐个向allocator发原身份NOTE_OFF，得到release_slot后触发ADSR；直到整组完成才release_ready=1，期间冻结槽再分配并保存代次，不能先ack后丢脉冲。四槽最多四个Release，PCM采样继续，控制握手不得使音频停顿。

M2每次新NOTE_ON给槽增加32bit代次，包括同身份重触发，并把该号随待回收通知携带；只比较相等，不做有符号年龄排序。32bit可回绕，但不得保留跨2^32分配仍未处理的完成/Release通知。保持命令队列有界并在slot重用时取消旧回收即可。这里generation是新控制连接的内部防旧消息字段，不改变已有LRU算法。

ADSR state=IDLE且controller releasing为1时M2发RETIRE；自然静音但key/deferred仍保持则不释放身份；若Note Off时包络已IDLE，开始Release请求后即可RETIRE，不等待不存在的状态转换。M2保证RETIRE带正确生命周期快照，不能在抢占后用新号替换旧通知。

source/channel隔离和global panic由controller控制，不由M3改原allocator/ADSR。M2负责编译列表、正式top连接、采样事件背压、模型集成回归及Gowin/PnR；CC64规范发布后M3改parser。M1算法包T027/Pitch/Mod/T028不包含本任务。

## E. 自检与交付

M2提供生成向量与TB，基于上述状态合同、用户明确行为，无波形数学。覆盖未踩松键/踩后松键/松踏板/按住键松踏板/同音重触发/跨source与channel/抢占/旧generation回收/重复事件/全局清音/输出背压/复位取消。M3可以追加自检；不能仅把输入脚本print PASS当真实RTL结果。

先运行 `python -X utf8 code/scripts/prepare_sustain_contract.py`：准备合同向量，检查128个CC阈值映射、编译端口/TB占位以确认工具接口兼容（不运行占位、不声称延音实现通过）。

M3提供模块后运行 `python -X utf8 code/scripts/prepare_sustain_contract.py --controller code/rtl/input/sustain_control/sustain_controller.sv`：真实自检TB对命令向量及握手执行，有明确PASS/FAIL。只读M3模块，临时输出code/output/sustain_contract，不修改原始源码。

允许M3写parser/独立sustain_controller及其授权测试/说明；正式M2接口文件、共享包和规范不要私自修改。参数编号新增须群通知确认。实现若需改变本合同，先交具体影响，不自己与其他模块对接旧版。

本合同不是M3模块完成记录；M3还未收到本离线包的私发确认。M2准备包可直接发送，公共发布待群通知。当前主线仍T024实物音频，T025/T026暂停后续补验不变。
