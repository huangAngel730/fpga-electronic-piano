# M2 Pro四声基础：观察出口与完整链准入差额（2026-10-17）

本说明服务当前唯一Pro四声基础主线，依据M2活单R03及用户本轮“先完成基础”。它是具体输入/受控改动影响与准入缺口，不是已实施RTL补丁或新的完整链许可。

## 已存在的真实接口

现有M2 Pro候选top只公开50MHz参考时钟、板级复位/按键/MIDI、PT8211三引脚、PA、UART和TMDS。旧R05同版 `m2_fourvoice_timbre_delay_frame_core` 模块公开的音频接口还包括event valid/ready/data、frame_tick、request_accept/request_id、commit_pulse/committed_id/PCM/clip、play PCM、pending及状态计数。模块内部命名存在不等于Pro包装top已公开该观察出口。

新来源包逐字段分类B1的61项观察需求。M2可以给候选源/ROM/约束/模拟PLL身份和已存在模块端口的静态定位；真实event应用slot、voice生命周期/generation、四路advance mask等更深字段不能由PCM倒推，不能把内部层级读数包装成公开采集。上午monitor的scalar lane自检也不是实际四路公共tick推进的生产定义。

## 完整链新的精确执行条件

旧P7 TB本身也不能作为不改即跑的验收输入：`tb_pro_full_chain.sv` 直接读取 `dut.u_legacy` 内部core时钟、状态及深层 `slot_note_off`，尚不是B1所需的公开观察合同；其deadline断言为 `status_max_processing_cycles < 834`，会接受833，而本轮严格服务预算为清理年龄 `<833`。原TB未取得完整执行结果，这些只是本轮静态发现，不能写成已跑出的反例。后继TB需绑定公开观察出口并按实际采样相位固定截止定义，不能把旧TB当已签真实四声/逐放/串行证据；原件保留不覆盖。

1. 历史挂起PID只做当前状态核验；旧原件缺创建时间/完整路径，禁止按旧PID盲杀。本轮安全后继仅以自己创建并持有句柄/Job的Python夹具验证清理。
2. 后继执行器须有源码/helper/工具前后SHA、suspended→Job→resume、实时文件双流、总期限、超时与父退子留清理原件。软件夹具PASS不代表P7真实工具树已运行；旧runner及环境开关不恢复。
3. 如要恢复完整链，需绑定新运行入口/源码闭包和ROM包SHA、确定的TB及观察映射、工具EXE/依赖/许可、独占输出、正负例目标及一次明确时间/轮数额度。当前活单写明“当前不新增完整链仿真”，本轮尚未获得该精确许可，不先执行后补批。
4. 数字链之后，商业Gowin实际许可、Pro完整料号/device version和PCB/Bank/MIDI/PA电气原件齐备，才可形成真实Pro工程/PLL、完整综合/PnR/STA与新.fs；单次SRAM下载还须绑定精确SHA另准入。旧PG484报告/码流/额度均不迁移。
