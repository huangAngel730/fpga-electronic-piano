## 接口与事件时序

源 `result_valid/result_ready` 携带一个完整的 `result_req_id + result_left + result_right + result_clip_any`；结果保持寄存器只能在请求窗打开、ID 与 `current_req_id` 匹配且不是 `frame_tick` 的时钟沿接收。请求窗只在 `frame_tick && calc_ready` 后开放，一次成功捕获立即关闭；同代次重复结果拒收。`result_valid` 被反压时由上游保持、超期后必须撤销，不能让旧结果阻塞新一帧。模块自身只有一槽，不缓存第二组结果。

内部寄存器保持 `pcm_valid/pcm_req_id/pcm_left/pcm_right/pcm_clip_any`；不因源组合波形后续变化而改变。`pcm_valid && pcm_ready` 同拍向现有 `pcm_frame_buffer` 提交，随后清除有效位和削波标志；每次完整帧边界比交付优先，丢弃仍未提交的旧结果，禁止在边界同拍把迟到结果续写到新一帧。外部低有效复位异步断言、由上游各时钟域同步释放，清除有效位、样本和标志。

这里 `calc_ready` **须与** `pcm_frame_buffer.calc_ready` 同源。`pcm_ready` 必须是帧缓冲的真实 ready；任何中间门控必须同时门控缓冲的 valid 和计数器看到的 ready，使“实际 PCM 入缓冲”与 `clip_count` 严格同一时钟沿。完整顶层的源流水线必须把 `clip_any` 与相同请求 ID、左右 PCM 在同一点锁存，否则不能接真实 `STAT`。
