# 早期八键电子琴原型代码评审

评审日期：2026-09-12。评审对象：`legacy-prototype/`。本评审不修改冻结原型，只判断其用途和迁移价值。

## 结论

该代码作为早期八键方波原型是合格的：模块数量少、数据流直观、基本可综合，并已通过 Icarus 自检仿真。它适合继续作为仓库和工具链的 L2 冒烟测试。

它不适合直接作为正式竞赛音频核心。正式工程需要重新实现输入事件、采样节拍、波表 DDS、ADSR、复音、混音和 I2S，并补齐定点与时序验证。

## 做得较好的部分

- 顶层将按键处理和音调生成拆成两个模块，依赖关系清楚。
- 外部低有效按键先经过两级寄存器同步，考虑了亚稳态风险。
- 去抖时间和系统时钟参数化，便于在仿真中缩短等待时间。
- 32 位相位累加器比简单整数分频更容易扩展到 DDS。
- 多键采用明确的高音优先级，没有组合锁存器。
- testbench 至少检查了 C4、A4 和高音优先级，CI 能发现基本功能回退。

## 主要问题

### 中等风险 去抖共用一个计数器

`key_debounce.v` 对八个按键共用 `candidate` 和一个计数器。任意一个按键变化都会重新启动整组去抖，某个按键持续抖动时会延迟其他按键更新。早期演示可以接受，正式多键演奏应采用逐键计数器、采样积分或矩阵扫描状态机。

### 中等风险 参数边界不完整

当 `DEBOUNCE_MS` 为 0，或低时钟导致 `COUNT_MAX` 为 0 时，`COUNT_MAX - 1` 会产生不合理比较。正式模块应限制参数范围，并在仿真时对非法参数报错。

### 中等风险 位宽转换有 lint 警告

Verilator 对 `tone_generator.v` 中 32 位整数到 64 位运算、64 位除法结果截到 `PHASE_W`，以及去抖计数器与整数常量比较给出位宽扩展或截断警告。当前常量范围下通常不会破坏结果，但正式代码必须显式定义无符号位宽和截断策略。

### 中等风险 切换音符产生波形不连续

无按键时相位清零，但从一个按键直接切换到另一个按键时，相位累加器不会重新对齐。对一位方波而言可能在切换瞬间产生额外边沿；正式音频链路会表现为爆音风险，应通过包络、相位策略或短斜坡处理。

### 高风险 仅有一位方波输出

`audio_out` 是相位最高位形成的一位方波，不包含 48 kHz PCM、波表、ADSR、多声部混音、舍入饱和和 I2S，因此不能作为赛题要求的实时多音色引擎。

### 测试覆盖不足

现有 testbench 没有验证：

- 按键抖动和去抖边界；
- 复位期间与复位释放后的状态；
- `audio_out` 是否翻转以及实际输出频率；
- 松键静音；
- 多按键快速切换；
- 参数极值和异常场景；
- 明确的最终 `PASS` 标志。

此外，Icarus 的 `$error` 不一定使 `vvp` 返回非零退出码，因此 CI 必须同时解析输出。当前工作流已经这样处理。

## 正式工程迁移建议

| 原型内容 | 处理建议 |
|---|---|
| 顶层模块拆分思路 | 可以参考，但正式顶层由 M2 在 `代码/rtl/` 重建 |
| 两级输入同步 | 保留原则，增加同步属性和复位释放说明 |
| 整组按键去抖 | 不直接复用，改为逐键或扫描式去抖 |
| 相位累加器 | 保留数学思路，使用 Python 生成 FCW 并逐样本对比 |
| 整数音符频率表 | 改为 MIDI 音符到高精度 FCW 表或生成 ROM |
| 一位方波输出 | 仅作调试，不进入正式音频链路 |
| 现有 testbench | 保留为历史 CI，正式模块另建完整自检 TB |
