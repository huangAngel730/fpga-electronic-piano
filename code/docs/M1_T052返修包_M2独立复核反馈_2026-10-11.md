## 阻断问题及位置

1. **另造采样周期且位宽溢出。** `t052_polyphony_test_source.sv:47` 的 `10'd1042` 被截成 18，10 位 counter 本来也装不下 1041。Python 模型使用整数 1042，与 RTL 周期不同。原授权要求由外部 frame/sample 请求驱动，不能新造一套近似 48 kHz 调度。应回到原任务单外部 frame_tick/sample_req 合同，不能仅把计数器加宽就宣称原反馈闭合。
2. **接口合同缺失。** 当前只有 req_valid/req_ready、FCW 和单拍 pcm_valid，缺 request ID/回绕、frame_tick、enable/mask、result_ready、四路 PCM 和 active_voice_count。PROCESSING 内 req_ready=0 只是输入忙碌，不等于结果背压；没有 result_ready 就无法验证 held 结果稳定。局部原合同已授权，正式公共接口不改。
3. **取消只拒绝未接受请求。** IDLE 看 cancel，PROCESSING/COMMIT 不看；已接受旧请求仍产生结果，真实诊断已复现。需 frame 优先、旧结果无效、禁止同沿重新接受/消耗旧代，已接受相位推进不回滚；按原任务分别测试计算中和 held 阶段取消。
4. **TB 未实现独立数学验收。** 仅 wait pcm_valid、检查 signed24 范围并 success_count++；signed24 数值本身就在该范围内，不能检测共享/丢失声部、错相位、错拍或全零错误实现。没有请求/结果一一绑定、16 mask、结果背压、commit/1041–1042 帧周期与 clip 单次计数。`cancel` 场景和范围检查不是“两个可编译错误版本”。
5. **TB 当前无法在指定 Icarus 运行。** 行 133–136、175 的局部 automatic 变量报不支持。可用 task automatic 加声明/显式初始化，或在合适作用域声明变量后逐循环赋值；不能简单删 automatic 却把随机初始化变成只执行一次。同时修正 posedge 驱动竞态，在负沿驱动、NBA 后检查，并增加有界 watchdog。
6. **runner 路径及验收条件错误。** 行 58/155 三次 parent 得到 code/tb，再拼 code/；行173又把同目录 TB 多套一层。DUT 在临时 work_dir.parent 查找但没有复制。需绑定声明的仓库 root/只读依赖，将 TB/DUT/必要文件和 ROM 放入唯一 ASCII 工作目录，保留完整日志、capture、真实退出码和 SHA。原运行分支只看 PASS 字符串，不同时要求退出码 0、真实数量、完整 capture 和独立比较，仍可能误收；不允许覆盖旧结果或复用旧 vvp/ROM。
7. **软件缺文件误报及交付记录。** 五个单测缺 ROM 后 return，main 仍打印全部通过并返回 0，原单测 log 的 5 条“跳过”不是本机问题推测，而是附件已有事实；M2 再次复现了相同行为。所有必需依赖缺失必须非零，测试统计如实区分 PASS/SKIP。原 log 为非 UTF-8 字节，保留原 SHA，不强行转换后替换；新证据显式 UTF-8。包内没有 changes.json/命令退出码收据，成员也没有保留 code/... 交付路径。
8. **频点说明与硬编码不一致。** 原 TB 写“220/440/880/1760Hz”，硬编码 FCW `0258bf26/04b17e4d/0962fc9a/12c5f935` 按原 48kHz/32 位合同分别约为 **440/880/1760/3520Hz**。这只是独立控制字换算，不是实际坏采样节拍下的频率或现场 FFT 通过；返修需要统一频点、FCW 和期望样本。
