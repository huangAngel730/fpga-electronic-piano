## 合同与源码审查

合同是本独立候选的v1，不发布或覆盖公共performance_event/PCM/STAT接口。

- 归一化JSON严格schema1/sample_hz48000，1..512条记录，每条8bytes：tick:u32 +
  type/channel/note/velocity各u8，小端；同tick文件顺序保持，NoteOn0归一化为NoteOff。
- 115200 8N1、40MHz、bit divisor347，停等。帧有同步字/version/cmd/session/seq/offset/
  length和CRC-16/CCITT-FALSE，payload≤128；CRC黄金向量0x29b1。
- BEGIN/DATA/COMMIT/ABORT/STATUS/READ、ACK/NACK及14错误码定义明确。分包与整曲CRC分别
  验证；只在全长/CRC/事件合法后原子发布，新上传失败和ABORT保留旧曲谱。
- 最后一次成功请求仅在完整body/length相同才重放原ACK，不以CRC碰撞或重复seq代替身份。
  数据包、BEGIN、COMMIT的丢ACK重试不二次写入/发布。查询替换缓存的限制已写入合同。
- 20ms帧间与5s会话超时、超长帧丢弃/恢复、有限重试及PC总deadline均明确。超时不是成功。
- 公开同步rd_req/rd_index→rd_valid/rd_event，仅已提交银行可读。COMMIT同拍请求旧银行，
  后续请求新银行；rd_event文件记录不能直接当公共演奏64位事件。

双银行8192bytes行为隔离成立。生产消费者仍需冻结“发布身份/银行生命周期”的读取与播放
合同；仅锁存score_id并不能允许旧银行在后来上传中被覆盖。后续可选择复制、读锁或停止
播放再更新，由M2另行定案，不能在当前候选PASS后直接接进音频。

RTL结论依据原源码分析，不是CodeGraph HDL索引。公开读口一次拼8个byte、READ响应另有
