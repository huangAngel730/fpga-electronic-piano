# M2 T024 独立 1/4 路 DDS＋ADSR＋混音资源/时序探针（2026-09-28）

**阶段结论**：用同一 Gowin V1.9.11.03 Education、GW5AT-LV60PG484AC1/I0、同一组 M1 DDS/ADSR ROM 和50 MHz `sys_clk` SDC，在独立探针比较一条、四条数据通路；四条的Fmax **52.528MHz**，最差Setup余量 **+0.963ns**、Hold余量 **+0.062ns**。单独工具侧L5；**不是四复音正式电子琴/音频样本准确性/板级证据**。当前T010红门禁还未修复，本阶段未修改M1模型/RTL或正式顶层/约束。

## 实测范围和数据

探针 `code/rtl/board/voice_datapath_probe.sv` 给每路DDS独立FCW、每路ADSR独立Note On/Off/Velocity，将四路输出展平连接现有32位宽位混音器；公开左右PCM及各声部包络非零标记，减少综合工具裁剪风险。单路变体与四路变体使用**同一套**测试RTL、存储器文件与工具选项。独立TB用不同频率/力度验证四路状态真实活动，1路与4路输出有别，复位后清零：546项自动断言PASS，270个非零混音采样，270个混合差异采样。

|---|---:|---:|---:|
| Logic | 683 | 2959 | 2276 |
| Register | 179 | 716 | 537 |
| DSP | 6 | 24 | 18 |

四条最坏Setup路径：`g_lane[1].u_adsr/start_q16_0_s0/Q → u_probe/mult_78_s1/B[13]`。Hold最差：某 DDS 相位寄存器到波表地址。两档报告Setup/Hold违例端点均0、50MHz约束有效；同版器件和工具一致。独立报告检查器拒绝错误器件、丢失BRAM用量、负Setup及缺时钟，5项故障注入自检PASS。17项源码、脚本、ROM、报告和码流SHA-256保存在 `code/docs/evidence/t024_voice_datapath_20260928.json`；原始完整报告和码流在Git忽略的 `code/output/t024_voice_datapath/`。

## 数值口径与保留风险

此探针使用M1旧独立 DDS `sine_1024_32767.mem`，在探针内以右移17位、再左移8位作**临时资源代理缩放**，右声道使用左声道的负值仅为观测布线；**不是**D028正式波表峰值±8192口径，也未对任何正式左右PCM做黄金向量逐样本比对。探针四路正峰值即使同相也可能低于24位削波门槛，不能拿本次 TB 判断削波效果、音质或正式音量。波表存储、混音器与乘法资源的真实用量只对本拓扑成立。

探针没有T010声部身份与Release生命周期、MIDI/事件FIFO、T055帧请求与PCM代次缓冲、T025串口 `STAT`、效果器或HDMI，也没有正式顶层的CST引脚约束与板级DAC测量；仅以输入系统时钟约束分析内部寄存器。50MHz余量仅+0.963ns（Hold+0.062ns）意味着复制后接入控制链可能不收敛，但还不能根据这个独立报告判正式工程失败。四路DSP24、BSRAM8是**测得**的阶段风险数，不是T016最终资源申报值。没有下载此探针码流，不占用用户硬件。

## 复现

在仓库根目录：

```powershell
.\code\scripts\run_t024_voice_datapath_sim.ps1
python -m unittest discover -s code/tb/board -p test_t024_voice_datapath.py -v
.\code\scripts\run_t024_voice_datapath.ps1
```

第三条从源码重新生成一条/四条项目并验证实际Setup/Hold、Fmax、资源、四路ROM存活后自动刷新证据JSON。若重建码流/报告哈希变化，旧JSON不得直接沿用。M1修复T010且M1/用户确认ADSR轻力度重触发与D028波表/PCM口径后，M2才安排真正四声部顶层接线、完整黄金向量/逐帧提交和整机PnR；碰受控 `electronic_piano_top.sv` 前先按规则群里说明。T016/T024仍进行中。
