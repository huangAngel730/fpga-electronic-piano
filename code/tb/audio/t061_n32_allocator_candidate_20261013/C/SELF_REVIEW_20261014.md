# N32-C 本轮自审边界

用户要求中间不反复外送审核，由主对话2与子智能体解决。本轮已进行输入计划、独立数学、
TB 时点和 runner 防卡的分工核查；不是 M2 最终验收，也不是独立审核窗口签收。

- 基线：从 B 已通过封存逐字节复制 wrapper、RTL、ROM 和数学依赖。资产生成时工作树
  数学依赖先与 B 冻结 SHA 核同并检查前后身份；最终实际 checker 从冻结 snapshot 导入。
- 输入黄金：ca08 在 R07 RTL 之前生成，独立 FrameOracle 与逐沿 Oracle 双重比较；
  不从观察输出反填 PCM／身份／控制。
- 时间与归宿：真实 J 接受、F 首次 valid、K 连续 HOLD、P 握手分列；旧 ID／取消后／
  复位后／未来 ID 等合法 payload 不能绕过当前 live 资格。
- R05 前缀：只截原始完整沿，不制造 END；C05 已 BEGIN 未接受状态显式记录，尾部
  live 与读返回清空，四个 RT 及四次模型退休共同闭合。
- R07 后缀：从真实 reset 和公开 NoteOn 建立初态，独立期望，不强装原 C04 状态；
  关闭 ready 及 C09 数学场景复位前各有排空等待，C07 取消中复位场景不被删除。
- 防卡：TB 的每 OP 5000 拍上限独立于 CPU／日志，runner 的 300 秒进度只看 OP 转换；
  两项软件回归在 ca08 的资产收据内。原 R05 失败及 R06 拒收不回填 PASS。
- 反例：23 个短段完整 capture 软件变异和 1 个原 capture 抢占槽软件变异均有指定诊断；
  集合运行退出 0 表示成功拒收，单项 `exit_code=1` 是 checker 拒收标志，不冒称独立
  OS 进程或行为 RTL 变异。
- 身份：执行计划／snapshot／B 封存／输入黄金／源工具前后 SHA 及失败日志齐套；
  封存 manifest 区分整轮失败、局部前缀通过和独立短段通过。
- 前缀留痕：早期工具实录仅作历史；最终 n32cpe02 新纯软件完整重放 212.141 秒、
  反例 17.015 秒均退出 0，完整命令与输入／Python 前后 SHA 保持。最终组合引用这份
  新收据，旧 REUSED 和原失败不被覆盖；长 RTL 仿真没有重跑。

当前证据足以报告本轮分段场景功能 L2／数学 L3；M2 可依据包内精确证据独立复核。
没有验证物理资源、整机 deadline／STA、通用长程或设备实物；完整 T061 保持 PARTIAL。
